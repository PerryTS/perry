# Rules of the byte-cell births check (crates/perry-gc-effects/src/births.rs;
# DESIGN-family-reach section 11, condition 3). Same line format as seeds.txt:
#
#   <kind> <exact|prefix|contains|regex> <pattern> -- <reason>
#
# birth    the one allocation of every byte cell that is a JavaScript value.
# in-hand  a function the backward walk does not enter: it runs only when a
#          byte cell already exists (its receiver or an argument is one), or
#          it dispatches on a value the program holds, so a member of the
#          typed-array family is reached only with the family live and a
#          member of core is a row of the check itself.
# origin   a function that can reach the birth and that the runtime reaches
#          only through a pointer (no caller in the graph, or its address is
#          taken in code): a completion the event loop runs, a callback handed
#          to the host, a scheduled task. The reason says which observation of
#          the program schedules it, hence why the family is live whenever it
#          runs. Such a function without an origin rule fails the check.
# before-claim  a function that runs before an image's family claim is set
#          (the claim is the first call of the generated installer, which
#          js_gc_init runs last). It must not reach the birth: the claim
#          would not see that byte cell.
#
# fills    a function that takes addresses only to store them in slots (an
#          install). The walk does not go from a stored function to it; a
#          stored function the GC rules delegate to no wrapper needs an
#          origin rule.
#
# A rule that matches no function fails the check.

birth exact perry_runtime::buffer::store::store_alloc -- the one allocation of every byte cell that is a JavaScript value (typed arrays, Buffer, ArrayBuffer, SharedArrayBuffer); the two private index cells of a comparator sort come from store_alloc_scratch and are no values

before-claim regex ^js_gc_init(_with_layouts)?$ -- the runtime's initialization, the first runtime call of a compiled main: everything it does (collector setup, stack maps, the installs themselves) runs before or while the generated installer sets the image's claim; module initialization and user code come after it
in-hand exact perry_runtime::buffer::store::store_alloc_scratch -- the comparator sort's two private index cells: zeroed Uint32 cells that never take the pool or shared placement (which allocate an owner through store_alloc) and are never handed to JavaScript
in-hand exact js_native_call_value -- calls a function value: program code, or a built-in function value the solve holds as an observed entry
in-hand prefix js_closure_call -- calls a closure's body: program code, or a built-in function value the solve holds as an observed entry
in-hand exact js_promise_run_microtasks -- drains the microtask queue: a reaction is program code or a built-in function value
in-hand exact perry_runtime::array::buffer_receiver::buffer_receiver_dispatch -- an Array method called on a Buffer receiver: the Buffer exists
in-hand exact perry_runtime::array::header::buffer_receiver_as_uint8_typed_array -- views a Buffer receiver as a Uint8Array: the Buffer exists
in-hand exact perry_runtime::object::typed_array_proto_thunks::dispatch_uint8_buffer_method -- a method called on a Uint8Array or Buffer receiver: it exists
in-hand exact perry_runtime::object::class_registry::construct::builtin::construct -- `new` of a built-in constructor value: a typed-array or Buffer arm runs only when the callee is that constructor, an observed entry of the family
fills regex ^js_(runtime|nm)_install_ -- an install: it stores its group's operations in the hook slots and its module's dispatch function in the registry and runs none of them
