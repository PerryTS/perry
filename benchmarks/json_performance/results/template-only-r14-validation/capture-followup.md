# Read-only next investigation; not implemented in R14

R14 changes only template hit construction, not template capture. The frozen main capture disassembly and indirect-symbol table prove a 576-byte memcpy from the local values array into a local ParseObjectTemplate, followed by a 600-byte memcpy into the thread-local cache. The capture frame totals 1376 bytes (96-byte saved-register area plus 1280 bytes). Array plans are also copied into local scratch for root-barrier iteration through match-by-value. These are static redundant-work findings, not a measured attribution of the changing-input slowdown.

Lower-risk follow-up: construct one local ParseObjectTemplate directly, fill entry.values in place, then load keys/shape at the original point after value admission succeeds. Initially use null/zero metadata placeholders so shape lookup order and failed-admission behavior stay unchanged. Iterate borrowed planned-array values during root barriers instead of copying arrays. Keep the existing root barriers and final cache publication order, and retain all admission/GC policies. Confirm the 576-byte intermediate copy and array copies disappear, then compare changing and repeated inputs.

A separate, larger design to investigate only if useful: avoid building a complete template for every one-off source. Admit a full plan only after observing the same source again. It would require a properly traced pending-source state in the existing bounded cache, preserving mutation freshness, invalidation, scanner updates and failed-admission behavior. This has not been implemented; it is an alternative cache design that must preserve GC policy and requires its own proof and full measurement. Do not expand the cache to fit the eight-member benchmark corpus.
