# Follow-up if key-list regression persists

R8 source extends only the first admission predicate, but LLVM changes the whole public entry's block layout and stack frame (272 to 288 bytes). The key-list worker passes undefined for spacer: in the saved candidate assembly it takes the tagged-spacer branch, rejects its non-null replacer, and skips the floating zero comparison. Therefore a key-list slowdown is NOT evidence that every call now executes fcmp. Do not attribute it to that instruction or the frame size without an isolated experiment.

A bounded next experiment can retain the original compact admission block and attempt newly eligible spacers only after the old block has failed. Put the new attempts in a separate helper if necessary to avoid copying all inlined writers into the public body. Retain the original spacer/replacer values for fallback. Check generated assembly before paying for a measurement: expected ordinary entry and key-list route should be as close to main as possible; do not assume Rust source ordering forces LLVM layout.

Literal zero -> undefined normalization is NOT an equivalent fallback in this runtime. It would enable the existing lazy raw-source shortcut, changing the recorded zero/true lazy crashes into noncanonical raw output for whitespace/duplicate-key cases. Any compiler-selected bounded helper must fall back with the original spacer, or first fix lazy canonicalization/materialization correctly. A helper selected for arbitrary computed spacers also needs dynamic pretty/boxed-coercion controls, not only dynamic zero.

All proposals here are unimplemented and unmeasured. R7 outlining and R5/R6 production changes remain excluded. Required proof stays exact three-package builds, byte-pinned workers, Node behavior including callback-only copying GC, unsuppressed native/shadow comparison, quiet-host CPU/RSS controls, and eventual full original/consumption/rotating/retained/short-call scope before overall qualification.
