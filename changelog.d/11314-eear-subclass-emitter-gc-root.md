`sub.asyncResource.eventEmitter === sub` now holds for an `EventEmitterAsyncResource` subclass after a moving collection (#11258). The native `AsyncResource` backing stores the subclass's `this` in its `event_emitter` word as a raw heap address, and no root scanner visited that word. A copying minor that moved the emitter therefore left the word pointing at the stale from-space copy. `set_async_resource_event_emitter` now records each backing whose linked emitter is a heap object in a per-thread `EVENT_EMITTER_LINKED_BACKINGS` set. Stdlib and ext emitters are numeric handles in the handle band, so they are not recorded. `scan_async_hooks_roots_mut` visits each recorded word, which marks the emitter and rewrites the word after a move.

The link is a strong root, which mirrors Node's `asyncResource.eventEmitter` edge. Backings are never freed, so a linked subclass emitter now stays alive for the life of the process. A weak, rewrite-only link would dangle if user code kept `sub.asyncResource` after the emitter died. Adds `gc::tests::runtime_roots::hook_dispatch_handles::test_async_resource_event_emitter_link_follows_a_moved_subclass_emitter`, which fails when the scanner visit is removed, and `test-files/test_gap_11258_eventemitter_async_resource_subclass_gc.ts`.
