Compiled output no longer depends on the machine that builds it. A build without `--march` used to tune host builds to the build machine (`-march=native` / `-mcpu=native`), so a program built on an AVX-512 box contained AVX-512 instructions and crashed with `SIGILL` on any CPU without them, and the same source built on two machines gave two programs. Every build now targets a fixed CPU per target triple, the same for host and cross builds: `x86-64-v3` (AVX2, BMI1/2, FMA; Haswell, Zen 1 and later) on x86-64 Linux, macOS and Windows, `apple-m1` on Apple silicon macOS as before, and the architecture's LLVM baseline elsewhere (armv8-a on aarch64 Linux and Android). The compiler, runtime, stdlib and extension archives are built at the same level (`.cargo/config.toml`). The build machine's full instruction set is still available as an explicit opt-in: `--march native`, `PERRY_TARGET_CPU=native` or perry.toml `[build] march = "native"`. `--march generic` gives the architecture's LLVM baseline (x86-64 v1) for app code. Runtime CPU dispatch inside the runtime (the AVX2/AVX-512 string scanners) is unchanged. `perry publish linux` no longer defaults to `x86-64-v2`: without `--march` it sends nothing and the worker builds at the same fixed baseline.
