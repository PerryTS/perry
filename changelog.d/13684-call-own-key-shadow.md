Prove method calls on an own key an object holds from birth when unknown code may have written the builtin prototypes: the callee lookup stops at the own data property, as reads already do (DECISIONS 234), so a factory literal no longer escapes as the receiver of an unknown callee. A later delete or redefinition of the key gives the call the builtin members again. A literal's per-unit contract now also carries its own accessor keys (getters and setters): the reader holds them on its stand-in instance, so a call through a getter's result runs with the receiver as this (the receiver escapes in the reader) instead of being dropped, and an accessor key shadows the chain like a data key. No runtime caches or side tables are added.
