Performance: an element read or store whose key is not proven non-negative no longer tests the key's sign in front of its bound. The element tiers already bound every element arm with one unsigned compare (`idx <u length`, `idx <u capacity`, `idx <u floor`), which declines a negative key because it is at least 2^31 unsigned, so the sign test moves to the miss arm: there a negative key leaves for the exact property-key read before the tier's cold element read, and a non-negative miss keeps the cold read. Every key takes the arm it took before (`-1` and `-2^31` are named properties, `-0` is element 0, NaN and `1.5` are named properties, holes and keys past the length read through the prototype). A native integer key (`k | 0`, an int32 local) is no longer mapped to `-1` by a select before the bound, on reads and on stores. A read whose key is proven in range has no bound and keeps its test. `PERRY_UNSIGNED_BOUND=0` turns it off; `PERRY_FACTS_SABOTAGE=unsignedbound` (the miss arm drops the exit for negative keys) is the negative control, which check mode (`PERRY_VERIFY_FACTS=1`) reports as "unsigned bound".
