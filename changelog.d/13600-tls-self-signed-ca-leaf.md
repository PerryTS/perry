fetch: a server whose certificate is self-signed with `basicConstraints CA:TRUE` is now accepted when that exact certificate is trusted through `NODE_EXTRA_CA_CERTS`, as `node:https` and `node:tls` already do, instead of failing with a transport error. The certificate must still match the requested host and be within its validity period; `NODE_TLS_REJECT_UNAUTHORIZED=0` still disables verification.
