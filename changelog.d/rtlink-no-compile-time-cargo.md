`perry compile` no longer runs cargo. WebAssembly (`--enable-wasm-runtime`), approved Node-API addons and the routed `http` / `https` / `net` / `tls` / `ws` / `zlib` adapters are compiled into the prebuilt runtime and stdlib archives and installed per program, so these programs link the same archives as every other program instead of rebuilding the runtime (a fastify compile no longer pays a cargo rebuild). The runtime calls the WebAssembly host archive through an entry-point table it registers, so no archive references a symbol it might not link. `cargo build --release` now builds the compiler together with every archive it links (runtime, stdlib, `perry-wasm-host` and the routed `perry-ext-*` wrappers); `cargo build-perry` is the same set for a build that adds packages. A missing wrapper archive is now an error that says what to build. The unused `PERRY_LLVM_BITCODE_LINK` bitcode-link mode is removed.
