Whole-program facts keep an Array's birth length as a floor (`PERRY_FACTS_ARRAY_FLOOR`, on by default; `=0` restores the previous rules). An index store past the length now raises only the length interval's upper bound (to the largest key plus one), a store whose keys are all negative changes nothing (a negative key is a named property in the array's separate bag), and an append (`push`) raises the upper bound to `u32::MAX`; `reverse`/`copyWithin` make a grown length unknown. So `killers`-style arrays written at keys in `[-16, 16]` keep their constant length and proven element reads. A `new Array(k)` birth length is recorded only for `k <= MAX_FRESH_DENSE_ARRAY_LENGTH`, so the birth guarantees the capacity a proven read addresses, and the element read's own capacity test is gone. New sabotage arms `arrfloor`, `arrappend`, `arrcap` (alias `densebirth`) and `arrfwd` with their S0 fixtures; a runtime test classifies every `capacity` write against the floor, and the inline literal header goes through `perry_abi::array_birth_header`, which asserts `capacity >= length`.
