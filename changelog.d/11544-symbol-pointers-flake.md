### Fixed

- Fixed a flaky perry-stdlib test, `thread_exit_releases_the_threads_fresh_symbol_pointers` (#11539). It failed about once in 40 full runs on Linux with "a dead thread's Symbol() stayed in SYMBOL_POINTERS". The test checked only whether the dead thread's `Symbol()` address was still registered. At thread exit `MallocState` returns the header to the system allocator, and a concurrently running test's `Symbol()` can get the same block and register the same address. A diagnostic build confirmed this: every failure had a live symbol with the next id at the dead one's address. The release hook itself was fine. The test now identifies the symbol by `(address, id)` through the new `perry_runtime::symbol::registered_symbol_id_for_test` probe; symbol ids are monotonic and never reused. `symbol_verdict_is_by_identity_not_by_address` is a deterministic regression test that fails with the old address-only verdict. With the `SYMBOL_POINTERS` release removed, the fixed test still fails every run.
