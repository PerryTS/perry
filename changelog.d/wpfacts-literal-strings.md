Performance: a store or an alias of a value whose every String is a program string literal's value no longer tests for a heap string and calls `js_string_addref_if_heap_string`. wpfacts reads the fact off the string value lattice it already keeps (`Node::strs`: a literal is a source of its one constant, copies and nullish filters hand a set on, every other String birth is any string) and exports it per local (`BindingFacts::literal_strings`: a parameter every caller passes literals, a `let` of them) and per class field (`FieldFacts::literal_strings`: every writer of any unit stores literals, e.g. a `"white" | "black"` field flipped by a function that returns literals). A literal's value is born shared and nothing appends to it in place, so the demote that protects an append accumulator from being rewritten under a second holder has nothing to do: codegen drops it at a proven class-field store whose field carries the fact, at a store whose value reads such a local, and at `let y = x` / `y = x` when `x` or `y` is such a local. With the demote gone, a class-field store whose value is never a GC-heap object (a literal, a selection of literals, a call of a function that returns only those: its write barrier was already emitted as nothing) no longer tests the value for a pointer and the receiver's generation for that empty arm, so `this.side = opposite(this.side)` is the store alone. A field or local that also receives a concatenation, a method result, a JSON or input string, or anything through an unknown writer has no fact and keeps the demote. Check mode (`PERRY_VERIFY_FACTS=1`) tests each consuming site: a `STRING_TAG` value whose header is not shared is reported as "literal string" (exit 86); `PERRY_FACTS_SABOTAGE=litstr` is its negative control. `PERRY_FACTS_LITERAL_STRINGS=0` turns the fact, its consumers and the empty-arm cleanup off; the dump (`PERRY_FACTS_DUMP`) prints one `# lit_strings` line per local and per field that carries the fact, with its constants.
