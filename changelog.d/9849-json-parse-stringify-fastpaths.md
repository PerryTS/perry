Speed up JSON parsing and stringify with bounded NEON/SSE2/word string scanning, direct Unicode escape emission, and a temporary duplicate-key index for very wide objects. Preserve strict syntax validation, duplicate-key order and existing GC boundaries; prove depth one cheaply for large flat scalar arrays.

Use stack-buffer ECMAScript number formatting, eligible inline short-string results, and a guarded compact-decimal path. Serialize dense primitive arrays directly after checking their layout and callback constraints, avoiding recursive traversal and temporary managed roots. The numeric emitter matches Node and Bun on 1,730,283 exact doubles with zero temporary allocations in its leaf harness.

Bound retained parse-shape metadata to 4,096 total key slots. Sustained 50,000-key parsing improves from 44.35 to 21.04 ms and peak RSS drops from 227 to 177 MiB against the preceding fast-path implementation. Vectorized UTF-8 validation and UTF-16 counting improve Unicode JSON parse/stringify by a further 3.8× while preserving malformed-byte semantics.

The latest quiet Apple M1 comparison measures numeric-array stringify at 1.61 ms versus Node's 1.98 ms and Bun's 2.95 ms, 4.13× faster than the Unicode checkpoint. Small scalar stringify improves 7.7–10× over that checkpoint, resolving the earlier tiny-call regression. Record stringify at 16 KB–8 MB improves 12–15% but still trails the better engine. GC policy and parse-boundary sources remain unchanged from v0.5.1520.

Validation passes 54 JSON runtime tests, 26 compiled fixtures matching Node, all 152 benchmark output checks, and five moving-GC stress subjects with two seeds each. The full quiet run includes 456 timing and 432 memory trials. CPU/RSS parity and no-regression acceptance remain open: 9/38 CPU, 58/74 peak RSS and 28/36 retained RSS medians meet the better engine. Seven-process repeats still show a 2.8% wide-parse and 1.1% long-ASCII stringify median slowdown with partly overlapping ranges, plus numeric-parse peak RSS increasing from 64.53 to 66.78 MiB.
