codegen: the inline heap-address guards now treat the LLVM triples `*-apple-macosx*` (the macOS host default, `arm64-apple-macosx15.0.0`) and `*-apple-xros*` (visionOS) as low-address targets. `heap_addr_lower_bound_inclusive` matched only the rustc spellings (`darwin`, `visionos`), so both targets fell to the 2 TiB fallback floor. Every inline method, learned-word, property-IC and typed-array guard then missed for GC objects below 2 TiB and took the runtime slow path. mimalloc's macOS arenas sit above 2 TiB, which hid this. With GC memory near 4 GiB (OS-backed regions), Commander retired 14% more instructions and Zod 7%. New test `heap_address_floor_covers_emitted_triples` checks the triples codegen really emits (host default plus every `--target` name).
