Whole-program facts: a built-in method read as a value keeps the identity of the native it was read from. `[].slice` held in an array, or taken from one and called with `.call(arr)`, is still `Array.prototype.slice`: called on an array (`targets[i]()` binds the array as `this`, `fs[0].call(arr)` passes it) it runs what `arr.slice()` runs, so the array and the objects it holds no longer count as handed to unknown code. A built-in read under a computed key, a static of a namespace, an inherited `Object.prototype` method, a native without a model, `eval` and `Function`, or a call on a receiver of another kind stays an unknown function, as before; `new` of a built-in prototype method throws, so nothing flows through it. No proven site is gained or lost in tssrc, tscwork, fastify_inject, chess, chesst or d_zod4; the padded hello binary is unchanged.
