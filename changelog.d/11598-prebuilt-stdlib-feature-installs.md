- **perf(size): an installed perry no longer links every stdlib subsystem into every program.** Without a workspace to rebuild from, perry links the prebuilt full-feature `libperry_stdlib.a`, and its always-live hubs (`js_stdlib_init_dispatch`, `js_handle_method_dispatch` and its property/set/own-names/prototype siblings, the async pump and has-active gate) named every optional subsystem directly, so the linker kept sqlite, all of RustCrypto, nodemailer, zlib's Brotli/zstd codecs, … in programs that used none of them. The hubs now reach optional features only through fixed-order hook slots that each feature fills from its own `js_stdlib_install_<feature>` entry point (`perry-stdlib/src/common/feature_hooks.rs`); an empty slot is skipped exactly as the old `#[cfg]` skipped the arm, so dispatch order and behavior are unchanged. Whenever the stdlib is linked, the link step generates a small object (`perry_codegen::stubs::generate_stdlib_installer_object`) whose static constructor registers an installer that `js_stdlib_init_dispatch` runs: on a prebuilt link it installs only the program's features (the same set an auto-optimized rebuild compiles, expanded through perry-stdlib's `[features]` table — `crates/perry/src/commands/stdlib_installs.rs`, whose test fails if the table drifts from `Cargo.toml`), and it installs everything when the program has deferred dynamic code. Auto-optimized and `--no-auto-optimize` links install everything compiled, i.e. behave exactly as before. Measured on Linux x86_64 against the release-built prebuilt archives: a `node:net` + `fetch` + TLS backend 23.87 → 19.29 MB, a sockets-only program 22.84 → 16.05 MB, `node:sqlite` 22.26 → 15.84 MB, fetch-only 22.28 → 17.25 MB; auto-optimized sizes unchanged. Validation: the Node builtin compatibility matrix and 259 stdlib-feature programs from `test-files/` produce identical results with the base and patched installed-mode packages (the only differences are tests that print random bytes / per-build class-name hashes); perry-stdlib's tests 184/184 on both; no new warnings in any feature subset (36 pre-existing ones removed). The runtime-side hubs (`js_get_global_this`'s `eval`/Intl thunks, native-module-by-name, Temporal in the generic operators) still pin the JS parser, ICU and Temporal on a prebuilt link and are the follow-up.
