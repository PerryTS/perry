Runtime realm: a behavioural check keeps the built-in effect declarations true. `scripts/realm_effects/behave.py` reads every declaration with effects from the realm manifest (`realm-v1.json`), generates one TypeScript program per native, receiver kind (plain array, array with a logging `constructor`/`@@species`, Proxy), call form (reflective `F.apply`, `recv.m(args[0])`, `recv.m(a0)`) and argument count, compiles it with perry and runs it on probes that log every Proxy trap, ToPrimitive, callback call (with `this` and arguments), species construction, receiver change, result and what a forced `gc()` leaves alive. Every observed event must be covered by the declaration; a red names the event and the effect it needs (`python3 scripts/realm_effects/behave.py --perry target/release/perry --realm <OUT_DIR>/realm-v1.json --out <dir>`; `--weaken Name=verb` is the sabotage mode; unit tests in `scripts/realm_effects/test_behave.py`). It found three wrong declarations, now corrected: `Array.prototype.map` and `filter` return `species(this, ..)` (the array path runs ArraySpeciesCreate, array/iter_methods.rs), not a fresh plain array; `Array.prototype.sort` coerces its comparator's result (ToNumber). The effect grammar accepts `coerce(returned(N), ..)` for that. Runtime behavior is unchanged; the facts solver interprets sort's effects, including coercion of the comparator result. The checker covers argument counts from zero, ordinary element toString/valueOf conversion, caught abrupt completion, and negative controls that preserve the original probes.
