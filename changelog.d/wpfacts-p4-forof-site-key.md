Performance: a `for (const x of arr)` walk's element read now has its own element-fact site (the loop binding's position), so the facts that already applied to `arr[i]` reads apply to it: a read of a constant-length array takes the proven-array load, and a Number element skips its number test. Whole-program facts also add an element read's past-the-end `undefined` only when the read may be at or past the end: for a program array literal whose length never moves, a key the facts bound inside `[0, length)` reads an element (or a hole, which still reads `undefined`). The rule watches both the key's interval and the array's length, and adds the `undefined` as soon as either may leave that range. `PERRY_FACTS_ELEM_UNDEF=0` restores the previous facts and the walk's site-less read; `PERRY_VERIFY_FACTS=1` re-tests each such read's key against the floor, and `PERRY_FACTS_SABOTAGE=arrundef` is its negative control.
