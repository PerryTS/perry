perry-stdlib: the promise bridge no longer needs tokio (turnloop P8, tokio lane L).

`common::async_bridge` was the whole of perry-stdlib's `async-runtime` feature: the settle queue and main-thread pump every native binding resolves its promises through, *and* the tokio current-thread runtime. The auto-optimize driver force-enabled `async-runtime` for every stdlib-linking program, so every such binary carried tokio, including programs whose native work never touches it (crypto, bcrypt, argon2, zlib, readline, worker_threads, timers, UI apps).

The bridge is now split:

- `common/async_bridge.rs` (new feature `async-bridge`, no tokio): pinning, the in-flight guard, both settle queues, the GC root scanner, `ensure_pump_registered`, `js_stdlib_process_pending`, `js_stdlib_has_active_handles`, `pool_for_promise_deferred`, and a new `reject_promise_later` for argument errors found before any work starts.
- `common/tokio_bridge.rs` (`async-runtime` = `async-bridge` + tokio): `RUNTIME`, the wait-driver tick, `spawn` / `spawn_for_promise*`, `block_on`, `run_one_tick`, `drive_pending`. Its public names are re-exported through `async_bridge`, so no caller changed its path, and `ws.rs` / `tls.rs` / `net` / `fetch` (sibling lanes G and H) are untouched.
- `perry_ffi_async.rs`: `perry_ffi_spawn_async` and `perry_ffi_spawn_blocking_with_reactor` compile only with `async-runtime` (their payload is a tokio future). `perry_ffi_spawn_blocking` keeps its tokio-pool arm under `async-runtime` and, without it, runs on turnloop's `Occupancy::Long` worker set (PerryTS/turnloop#42, in turnloop since 0.1.0-alpha.5, so the alpha.6 pin already has it) through a new `perry_runtime::turnloop_pool::submit_long`, falling back to one plain thread on a thread with no loop. `perry_ffi_run_pending` turns the loop for the whole budget when there is no tokio half to drive.

Features: `crypto`, `bundled-bcrypt`, `bundled-argon2`, `compression-gzip`, `bundled-nodemailer` and `external-zlib-pump` now imply `async-bridge` instead of `async-runtime`. The driver force-enables `async-bridge` (and for UI builds, and for `readline`), and selects `async-runtime` for every shared-tokio wrapper through the same `binding_needs_shared_tokio` predicate the #507 rebuild and the #7629 coherence check use, plus the existing pg / mysql2 / ws / net / http-client rules. `full` still implies `async-runtime`, so prebuilt and `PERRY_NO_AUTO_OPTIMIZE` builds are unchanged.

Measured on perrymaster (auto-optimize, Node 26.5.1 oracle): a crypto program's stdlib archive went from 16 tokio codegen units to 0, the binary from 12,022,336 to 11,874,696 bytes, and its output still matches Node byte for byte; the same for a `node:zlib` program routed to perry-ext-zlib (12,046,816 to 11,886,880 bytes). The perry-stdlib -> tokio manifest edge stays (inventory unchanged at 17 edges); what moved is which programs reach it.
