- **fix(hir): a class captured inside `for (let i …)` no longer sees the loop's post-increment value (#11250).** The class-capture refresh passes in `perry-hir/src/lower/expr_function.rs` (after assignments, inside assignment expressions, before returns) re-read *every* capture of a class, wherever the refresh lands. For a class that closed over a per-iteration head binding `i`, a refresh placed in the loop's condition/update, after the loop (triggered by `i++` or by a write to any other capture, e.g. `i++, x++` or a later `x = 5`), or before a `return` after the loop, read the single HIR slot for `i` — by then holding the next iteration's value — so the last class observed `3` (`0,1,3`; `1,2,3` for `i = i + 1`). New `lower/class_capture_scope.rs::prune_out_of_scope_capture_refreshes` runs after those passes and drops any `RegisterClassCaptures` / `RefreshClassExprCaptures` that captures a `for`-head lexical binding outside that loop's body. In-body refreshes are kept, and `var` heads (hoisted out of `For::init`) keep their single shared binding. Test: `test-files/test_gap_11250_for_let_class_capture_update.ts`.
