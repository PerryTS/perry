Fix UI-only Android apps failing to load with an unresolved `perry_ffi_native_async_new` symbol. Native Android UI archives depend on the async shims provided by perry-stdlib, so the compile pipeline now requires stdlib before optimized-library selection, undefined-symbol scanning, and linking. This covers Android arm64, Android x86-64, and Wear OS without adding a dummy `Headers` use to the application.

Validated the production dependency decision and Android stdlib link branch in an isolated Rust probe across 28 combinations. NDK archive fixtures retain the unresolved shim before the change and resolve it afterward on all three Android targets, including strict `--no-undefined` links. This is targeted archive/link validation; the full Android dependency build remains blocked by existing turnloop libc errors.
