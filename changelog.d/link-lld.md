Native Linux executables now link with lld when `ld.lld` (version 13 or newer) is on PATH, and with GNU ld as before when it is not. lld lays out the same inputs in a smaller file with the same code: chess shrinks by about 1%, and no instruction counts change. The fixed base 0x400000 and the separate code segment are kept as GNU ld had them. The default hot-text order works under lld too: its run gets its own output section, `.text.perry_hot`, in front of `.text`. Identical code folding (`--icf`) is not used. `--icf=all` merges JS functions whose code is identical, which changes the function names in `error.stack`. `--icf=safe` has nothing to fold, because neither rustc nor perry emits address-significance tables. `PERRY_LINK_LLD=off` keeps GNU ld; `PERRY_LINK_LLD=icf-all` adds `--icf=all` for measurement only. Cross links, musl, Android, HarmonyOS, macOS and Windows are unchanged, and so are builds with `--function-order`.
