Native Linux executables can now be linked with lld: set `PERRY_LINK_LLD=1` and have `ld.lld` 13 or newer on PATH. Without lld on PATH, GNU ld is used as before, and GNU ld stays the default. lld builds a smaller file from the same code: chess drops from 9 386 120 to 9 291 376 bytes (−1.0%), hello2 by 1.5%, the three.js skin bench by 0.35% and the tsc build by 0.22%. Start-up also runs 2.4% fewer instructions in ld.so for hello2. It is not the default yet, because each run costs about 6 000 instructions in ld.so's lazy binding. GNU ld binds the libc functions that mimalloc calls through the PLT early through `.plt.got`; lld gives each its own lazily bound slot. The fixed base 0x400000 and the separate code segment stay as under GNU ld. The default hot-text order works under lld: its run gets its own output section, `.text.perry_hot`. Identical code folding is not used. `--icf=all` merges JS functions whose code is identical, which changes the function names in `error.stack`. `--icf=safe` has nothing to fold, because neither rustc nor perry emits address-significance tables. `PERRY_LINK_LLD=icf-all` adds `--icf=all` for measurement only.
