Runtime groundwork for linking the typed-array / Buffer group by the whole-program fact `family_reach` (nothing acts on the fact yet: every install is still the detector's decision). The name dispatch of the typed-array methods (`at`, `fill`, `set`, `indexOf`, the iteration methods and the rest) moved behind the typed-array install hook, so a program that installs no typed arrays no longer carries it. Its empty hook and the empty hooks of the typed-array constructors abort with a message instead of answering `null` / `undefined` (a program holding a typed array without the group installed got wrong values before). New `family_never` module: a compiled image can claim that it never creates a byte cell (`js_runtime_families_never`, called by the generated installer when its claim is not empty; no image makes one yet), and the one allocation of every byte cell (`buffer::store::store_alloc`) aborts if one is born under a claim; a comparator sort's two private index cells are exempt (`store_alloc_scratch`). New census `perry-gc-effects births` (rules `scripts/gc_call_effects/byte_cell_births.txt`): which realm natives and which pointer-reached functions can reach the byte-cell allocation in the runtime's call graph without the realm declaring the birth; `--strict` makes it a gate.
