Native async completions settle only on the agent that created them. `js_native_async_process_pending` drained every pending token in the process, so a Worker's pump (`js_run_agent_pumps`) could settle the main program's promise and run its continuation on the Worker's thread, against module globals that thread never initialized: an Android app's Play Billing promise (`@perryts/play-billing`, `perry_ffi_promise_new` + `perry_ffi_promise_resolve_bits`) was settled by its `worker_threads` chess-engine Worker and crashed with a SIGSEGV in the next property read. The pump now takes only tokens whose `owner_agent` is the calling agent (as the stdlib resolution queues do since #11433) and leaves the rest queued, and completing a token wakes its owner (`notify_agent_work`) rather than broadcasting to the main thread.
