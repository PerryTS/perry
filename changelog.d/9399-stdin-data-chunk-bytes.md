- Fixed `process.stdin` `'data'` chunks arriving as EMPTY Buffers (#9399). The chunk was allocated with `buffer_alloc(len)`, which reserves capacity but leaves `length` at 0, and the caller never set it — so every un-encoded chunk reported `.length === 0`, `toString()` returned `""` and `Buffer.concat` appended nothing. Only the `setEncoding(...)` string path was unaffected.
- Fixed `stream.on("data", cb)` on `process.stdin` reached through an alias (`const s = process.stdin`, a parameter, or a field such as `this._stdin`) registering into a runtime-local listener list that the event loop's has-active check cannot see (#9399). `addListener`/`once` already delegated to perry-stdlib's readline registry; `on` now does too, so an aliased listener both receives its bytes and keeps the process alive while stdin is open. Together these are why `claude mcp serve` answered nothing and exited 0 with the request still unread.
