A module that only dynamic `import()` / `require(expr)` sites load, each in a function that provably never runs, is no longer compiled. Right after collection, the whole program's activation pass (DECISIONS 225) finds the bodies that can run; a dynamic edge whose sites are all in other bodies is dead, and every module only dead edges reach leaves the graph before the facts and codegen. In the Supabase CLI this drops the whole oxfmt formatter (28 modules and its platform bindings): `@supabase/postgrest-typegen` imports it only from its default formatter, and the CLI always passes its own. The activation pass got the precision this needs: a conditional, a logical operator, a destructuring or parameter default and an assignment in an `if` branch reach their result only when their test can select them; an object literal's keys are present at birth; a read of an own key the object surely holds reads no `undefined` from the end of the prototype chain; a spread literal holds a key every source surely holds; and a module only `import()` loads runs only once an active body loads it. A builtin prototype method read as a value (`Function.prototype.call`, `String.prototype.replace`) is now a builtin function, so a callback given through `.call`, `.bind` or a call-bound helper counts as running.
