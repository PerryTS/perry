Performance: a store whose value is a binary-image String literal takes no write barrier. That covers a literal (`this.side = "white"`), a selection of literals under a test with no store in it, and a call of a module function that returns only such selections (`this.side = opposite(this.side)`). Such a String lives in the binary's data, not the GC heap. It is never young and never greyed, so neither the generational nor the incremental barrier has anything to record. Every other value keeps its barrier. Chess on macOS arm64, instructions retired, barriers kept → this change: search 45.63 → 41.34 G (−9.4%), perft 1.138 → 1.055 G (−7.2%), legal 1.564 → 1.466 G (−6.3%), evaluate unchanged. `PERRY_STATIC_STORE_BARRIERS=1` keeps every barrier.
