`--target web`: every bridge call stores its arguments into the frame it opened. `join` on an `any` receiver, the `class_call_method` fallback (a value-position `o.list.push(v)` and static method calls), `toReversed`/`toSorted`/`toSpliced`/`with`/`copyWithin`/`entries`/`keys`/`values` and `path.sep`/`path.delimiter` wrote above the open frame or closed one they never opened, so nested calls overwrote each other's arguments (`a.join("-")` printed `3Authorization4`) and the slot arithmetic underflowed (`attempt to subtract with overflow` in a debug build). Debug builds now assert that a slot lies inside the open frame and that a bridge call has a frame to close (#14734).
