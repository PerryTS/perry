- **runtime: a thread exit now forgets its typed arrays in the process-global kind cache (#11463).** `PERRY_TA_KIND_CACHE` and `INLINE_OWNING_U32_CACHE` are process-global, but the `TYPED_ARRAY_REGISTRY` behind them is per-thread. An exiting thread dropped its registry and freed its arena blocks without unregistering anything, so the cache kept its "this address is a typed array" entries after the memory was gone. When another thread's arena reused such a block, whatever it allocated at a dead typed array's address was misclassified. For a Promise, `js_value_is_promise` returned 0, because `is_offheap_sidetable_alloc` answers before the GC-header probe.

  That was the intermittent `streams::pipe::tests::pipe_keeps_locks_until_async_abort_settles` failure in full perry-stdlib runs. The test's pending abort action landed on a stale address and was read as a non-promise. The pipe then treated the abort as synchronous and rejected before the action settled. Under load, the pre-fix binary failed it 2–3 times per ~20–60 runs; the fixed binary failed it 0 times in 60.

  `Arena::drop` (`crates/perry-runtime/src/arena/block.rs`) now calls `typedarray::invalidate_kind_caches_in_ranges` with the ranges it frees, next to the #11319 closure side-table release. The helper only touches atomics, and it clears each slot with a compare-exchange so it cannot erase an entry a live thread writes at the same time. The regression test `runtime_thread_exit_tests::thread_exit_forgets_the_threads_typed_array_kind_cache_entries` (perry-stdlib) fails when that call is removed.
