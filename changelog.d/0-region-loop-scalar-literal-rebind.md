Fix: a non-escaping object or array literal inside a loop region's body read back `undefined`. A loop region lowers its body twice, a shape-guarded F-body and the generic G-body. The F-body scalar-replaced `const u = { c: o.x, d: o.y }` and left a dummy `ctx.locals` slot, so the G-body took the `var`-redeclaration path and heap-allocated `u` while `u.c` still loaded the F-body's field slots. `f(new B(), 10)` summing `u.c` printed `NaN` instead of `150`, at every optimization level and with facts off. A second lowering of a scalar-replaced binding (object literal, array literal, `split`, `new`) now stores into the same slots.
