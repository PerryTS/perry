Linux binaries keep less of themselves in memory: the link now places the runtime functions that ordinary programs execute together at the front of `.text` (a default hot-text order), instead of leaving them spread over the whole runtime text where every first call maps another 64 KiB of the file. The order is a checked-in list (`crates/perry/src/commands/compile/link/hot_text_order.txt`) of the runtime functions a corpus of programs executes, most widely used first, keyed without crate hashes so a version bump or a rebuilt runtime resolves the same lines; the compiler resolves it against the runtime archives of the link and passes it in the linker script it already writes for the JS text section. No instruction and no object changes, only where the runtime's functions sit: the binary holds the same function bytes, and `.text` differs by alignment padding alone (a few dozen bytes, smaller in most programs). Measured on qb10: peak RSS of a typical small program −2.8 MiB (median of 52 held-out parity programs, 10.1 → 7.2 MiB), chess −3.3 to −3.8 MiB (−12% to −20%), a hello-sized program 6.1 → 3.8 MiB, with instructions and start-up instructions unchanged. `PERRY_HOT_TEXT_ORDER=off` keeps the previous layout, and `--function-order` (a per-program recording) replaces the default. `scripts/hot_text_order.py` records and builds the list, and its `check` command is the gate: it fails when a listed core function no longer exists (a rename) or when a smoke program executes more than 5% of its runtime bytes outside the ordered run. ELF links with GNU ld or lld only; macOS, Windows, WebAssembly, Android and HarmonyOS builds are unchanged.
