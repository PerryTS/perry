Fix (whole-program facts, activation reach): a member a program puts on a built-in prototype is reached by every read that can find it (class H of the activation false proofs, `temporal/test_gap_temporal_keyed_read_chain`). Two rules. (1) A constructor a host object holds (`Temporal.Duration`, `Intl.NumberFormat`, `WebAssembly.Module`) is a native function value in the solve, and the realm table listed the own keys of such a function for node modules only (`scripts/wpfacts_realm_declared_keys.py` dropped every dotted name): `F.prototype` and the statics read as absent, so `F.prototype.m = f` and `Object.defineProperty(F.prototype, k, { get })` had no receiver and `f` went nowhere, while a read on an instance ran it. The table now has `held` rows (57: `prototype` and the statics of the Intl, Temporal and WebAssembly constructors); such a key reads the opaque member, as a node module class's does, and a store under it is no program field (rule R1). (2) An accessor installed on a built-in prototype (`Object.defineProperty(String.prototype, k, { get })`, an index key included) ran only for receivers whose lookup the solve walks; a primitive's read, a string index read past the end and an unknown value's read reached none. It now escapes (any receiver may call it); the program-wide E23 kill it already caused is unchanged. Check mode (`PERRY_VERIFY_FACTS=1`) reported `Activation / inactive body: body entered` for both and `PERRY_FACTS_DCE=1` trapped in the removed body. Switches `PERRY_FACTS_REACH_HELD_KEYS=0` and `PERRY_FACTS_REACH_PROTO_ACCESSORS=0` restore the previous solve; both key the compile caches. S0 arms `reach-held-keys-negative` and `reach-proto-accessor-negative`.
