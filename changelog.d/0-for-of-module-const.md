Performance: a `for (const x of xs)` walk over a source typed as a Number array (a `number[]` parameter or local, a module `const` or `let` initialized with numbers) asks the runtime once per loop for both the IteratorRecord's array-mode proof and the packed-f64 loop admission (`js_array_record_enter_counted`), and the counted loop uses that answer instead of calling its own guard. Arrays of any other element type skip the admission. In the packed loop, a leading `const x = a[k]` binding of the counter's element is a Number, so a reduce like `s += x` keeps `s` unboxed instead of tag-testing both operands and keeping the dynamic `+` fallback. This also applies to hand-written counted loops of that shape and to the IteratorRecord loop's own packed clone. For-of over an 8-element module constant inside an outer loop: 321 to 200 instructions per outer iteration (300 before the source walk; Node 148). The same loop over a `number[]` parameter or a module `let`: 325 to 204. `PERRY_LITERAL_FOR_OF=0` still selects the IteratorRecord loop alone.
