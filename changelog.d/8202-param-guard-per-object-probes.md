`perf(runtime)`: `js_param_type_guard` resolves its per-object facts ONCE per object instead of once per descriptor field, and reuses a validated object across the arms of a union (#8202). Measured on the 19-program corpus (instructions retired, best-of-5, stdout/stderr byte-exact, peak RSS unchanged on every row): `interp` −1.51%, `iso_miss` −1.24%, every other row within ±0.2%.

Three costs, none of which decided anything:

- **The accessor probe ran per field.** Reading an accessor would run user code, so a field shadowed by one must take the generic fallback — but the check was `get_accessor_descriptor(address, name)` per field per guarded call, and even its own #6759 per-key prefilter costs a UTF-8 validation plus a key hash first. `owner_may_have_descriptor_entries(address, true)` answers "does this object own ANY accessor" from one meta word, and it is `false` for every ordinary object, so the per-field work disappears for the whole common case. Exactly equivalent: when the summary is `false` the per-key bit test could only have been `false` too (`bits & anything == 0`), and a non-meta-capable owner still reports `true` and keeps the per-field probe.
- **The `keys_array` header was re-validated per field.** `try_read_gc_header`, the obj_type/forwarded test, and the length/capacity/size arithmetic all ran again for every field looked up; a two-field object paid for it twice. `object_keys` resolves it once per object.
- **A union re-validated the same object once per arm.** Arms are tried against the SAME value, so every arm past the first re-ran `plain_object` — including the ShapeId probe, the object model's hottest lookup (#8125). A one-entry cache keyed on the NaN-box bits serves the retries. Nothing between two arms can invalidate it: validation runs no JavaScript and allocates nothing, so no collection can move or mutate the object.

Also hoists `table_end` into `Descriptor`, which `node` recomputed from `node_count` on every node visit.

**What this does NOT recover, and why the issue stays open.** A SKIPVAL arm (validation replaced by `true`, routing unchanged, outputs byte-exact) prices the whole validator at −13.36% / −11.04% on `interp` / `iso_miss` at `07c8040bf`, so #8202's residual reproduces. But its two headline mechanisms are not real: the "768-byte `GuardState` init" is **never paid** — `js_param_type_guard` compiles to `sub sp, sp, #0x470` plus a single `str xzr, [sp]`, LLVM having already elided the `[(0, 0); 64]` zero-init — and `Descriptor::parse` ablates to −0.26% / −0.19%. Ablation of the individual probes measures the shape probe at −0.88% / −0.69% and the accessor probe at −0.74% / −0.65%. The remaining ~11pp is the interpretive walk itself, spread thin across union-arm iteration, key-string comparison and per-field dispatch, with no dominant term — so no fixed-per-call fix reaches it. That share needs the issue's third candidate (caller-side static proofs so a proven `evalNode -> asNum(l)` bypasses the wrapper) or #8169's wrapper round-trip, not a cheaper validator.
