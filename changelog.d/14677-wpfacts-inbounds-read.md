Performance: a computed read whose key the program text bounds by a length test is not past the end in the whole-program facts. Every `a[k]` of an Array whose length the program decides at run time (a `[]` grown by `push`, a `slice` copy) used to yield its element or `undefined`, because the key's interval cannot rule out a read past the end. Now a read is in bounds when a test `i < a.length` guards it (a `for` or `while` test, an `if`, `&&`, `?:`, an early exit), `i` is not written since, the key is `i`, `i - c`, or `j`, `j ± c` for a local declared in the guarded code as `let j = i - c0` that is only ever decremented, the key is a non-negative integer by its interval, and the Array is one of this program's whose length never shrinks (no `pop`, `shift`, `splice`, `length` store, delete or escape, through any name). Such a read yields an element (or what a hole reads when the Array may hold one), so `const x = a[i]` in a counted loop over a pushed Array is a Number without `??`, and the compiled read drops its bound test and, for an Array without holes, its hole test. `PERRY_FACTS_INBOUNDS_READ=0` restores the previous facts and reads; `PERRY_FACTS_DUMP` lists each text-proven read (`# inbounds_read module= site= kept= present=`); check mode tests the key against the length at the read (negative control `PERRY_FACTS_SABOTAGE=inread`).
