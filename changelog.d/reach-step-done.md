Fix (whole-program facts, activation reach): a getter under `done` on an iterator's step result is no longer called inactive. Every consumer of the iteration protocol (a for-of step, array destructuring, array and argument spread, `yield*`, `Array.from`, `new Set` / `new Map` and the other built-in consumers) reads `done` of what `next()` returned before it reads the value (IteratorComplete). The solve read the value only, so `{ get done() { ... }, value }` returned by a `next()` had a getter body that was "inactive" while it ran: check mode (`PERRY_VERIFY_FACTS=1`) reported `Activation / inactive body: body entered` (parity fixtures `array/test_gap_array_binding_iterator_close`, `iterator/test_gap_iterator_close_completion_order`, `iterator/test_gap_iterret_close_destruct`, `operators/test_gap_region_numeric_expression_order`), and `PERRY_FACTS_DCE=1` trapped in the removed body. The solve now makes that read at every place it steps an iterator (`Model::step_done`: `Gen::iterate`, the destructuring step, the `yield*` pull and its `throw` / `return`, `builtins::iterate`). `PERRY_FACTS_REACH_STEP_DONE=0` restores the previous model.
