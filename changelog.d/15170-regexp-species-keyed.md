`str.matchAll(regexp)` and `str.split(regexp)` no longer hand the realm to unknown code in the facts solve. Their SpeciesConstructor step now reads the regexp's `constructor`, then that constructor's `@@species`, and constructs from `(regexp, flags)`, each with a known key. Before, the model touched the constructor with every protocol: with the realm's own `RegExp` that read every `Function.prototype` member as an unknown callee, so one `matchAll` call proved 565 of 4574 reads instead of all of them.
