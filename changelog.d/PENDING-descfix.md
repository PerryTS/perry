`Object.defineProperty`, `Object.defineProperties`, `Object.create(proto, props)` and `Reflect.defineProperty` validate a definition in one place again: each receiver family's `[[DefineOwnProperty]]` checks the descriptor against its own current facts and returns the verdict, which `Object.*` throws as a `TypeError` and `Reflect.defineProperty` returns as `false`. The second, record-based gate added in #12275 is removed, so a definition no longer allocates a `getOwnPropertyDescriptor` record to validate itself, and `defineProperties` reads each source key's enumerability without building one.

Fixes defining properties on fetch `Headers`/`Request`/`Response` (string and symbol keys, the Next.js `PATCHED_SET_HEADER` pattern), which threw "object is not extensible" and made `Reflect.defineProperty` return `false`. `Object.isExtensible` now reports native handle objects as extensible (and `isSealed`/`isFrozen` as false), matching Node, and a non-configurable expando on a native handle, typed array or class static keeps its redefinition invariants.
