Memory safety behind a lying annotation (`function f(a: number[]) { return a.push(7); } f(null as any)`): a TypeScript annotation proves nothing about the value, and five places read or wrote a header, or handed the runtime an address, that the annotation alone selected. (1) The inline `push` tier (`Expr::ArrayPush`) read the receiver's header with no pointer test: `null`, `undefined`, a Number, a boolean or a short string behind `number[]` died with SIGSEGV; its slow arms handed the runtime the low 48 bits as an address (a `null` came back as the head address 2 and was written into the local). The tier now tests that the receiver is a heap pointer (one subtract and one unsigned compare, fused before the header word it already loads) unless the whole-program verdict of the site proves every receiver an Array (`SITE_ARRAY_MEMBER`) or the receiver is an owned literal local; a miss is the ordinary `Get(recv, "push")` + `Call`, which throws node's TypeError for a primitive. (2) The annotated `arr.length = v` arm (strict code) passed any value's payload to `js_array_set_length_strict`: it now admits a heap pointer whose header is an Array's, every other receiver takes the complete strict `[[Set]]`. (3) An element store into a field, module binding or captured receiver annotated an Array passed a String's payload (a short string's BYTES) to `js_typed_feedback_array_set_f64_extend` as an address: a receiver that is no heap pointer takes `js_put_value_set_dynamic`. (4) By-name Array sites (runtime `js_array_method_needs_get`, the checked entries' admission): a String, BigInt or boolean behind the annotation now takes the real `Get` (a String runs `String.prototype.at` / `indexOf` / `slice` / ..., as node does) instead of the built-in reading the payload as an Array. (5) Runtime `map::clean_map_ptr` / `set::clean_set_ptr` passed any cell of another kind (an Array, a Date, a closure, the other collection) through as a `MapHeader` / `SetHeader`, so `m.set(k, v)` behind a `Map` annotation WROTE into that cell's memory: such a receiver now resolves to null (the answer a plain object already got). Switch: `PERRY_ANNOTATION_RECEIVER_TESTS=0` restores the codegen half's UNSAFE lowering (a compile-cache input; it exists to measure the tests' cost on one build); the runtime halves have no switch.
