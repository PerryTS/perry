A `Uint8Array` / `Buffer` element store of a Number-returning string method on a proven string (`u8[i] = s.charCodeAt(i)`) takes the native byte store again with whole-program facts off, instead of a runtime ToNumber store per element (#14970: about 3.3x on the issue's loop with `PERRY_PROGRAM_FACTS=0`). `atob(x)` / `btoa(x)` now prove their result a string, so `const s = atob(b64)` keeps the inline `charCodeAt` lowering. Such a store also evaluates to the Number itself rather than its ToInt32: `(u8[i] = s.charCodeAt(99))` is `NaN`, as in Node, not `0`.
