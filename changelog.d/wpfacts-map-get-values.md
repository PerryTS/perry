Performance: `Map.prototype.get` returns a Map's values, not its keys, in the whole-program facts. A collection's contents were one set of values, so `m.get(k)` of a string-keyed Map could be a String, and a field read of the result (`entry.move` behind `entry !== undefined`) could be the `undefined` a String's missing property reads: the value was Number-or-undefined and stayed boxed through every typed call it reached. A Map the program's own `new Map()` bears (no iterable) now has a value node that holds what `set` stored as its second argument, and `get` reads it, for as long as every write of the Map's contents is a `set` the facts see; an escape, a HARD marker, spread `set` arguments, a store under a computed key or a copy into the Map open it for good (`get` reads the whole contents again). Iteration, `keys`, `values`, `entries` and `forEach` are unchanged, and so are Sets, WeakMaps, subclass instances and Maps born from an iterable. `PERRY_FACTS_MAP_VALUES=0` restores the previous facts; `PERRY_FACTS_DUMP` lists each Map birth (`# map_values map= closed= values= contents=`); negative control `PERRY_FACTS_SABOTAGE=mapvals`.
