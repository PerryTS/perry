An object literal that spreads and also has computed keys, such as `{ ...s, [k]: v, a, b }`, now takes the same fresh-spread clone path as a spread literal with static keys, instead of the slow literal builder. The result is born on the spread source's layout, the computed key is converted once (ToPropertyKey, so a key object's `toString` / `valueOf` / `@@toPrimitive` still runs once and in order), and the value is then defined. A computed method or anonymous function value keeps the builder, because it needs name inference. The `spread_reduce` benchmark of #14976 drops from about 1000 ms to about 110 ms (node: about 108 ms).
