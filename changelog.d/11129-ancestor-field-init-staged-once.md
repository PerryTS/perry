- **fix(codegen): class field initializers of ancestors run exactly once per construction (#11120).** A construction stages ancestor field initializers before a constructor body runs, then hands the parent part to a parent constructor. On three paths that parent constructor installed the same ancestors again. Public initializers ran twice (side effects doubled), and a `#private` field threw `Cannot initialize a private field twice on the same object`. This blocked redis@6.1.0 `createClient({ socket })`: `@redis/client`'s `linked-list.js` classes live in a CommonJS module body, so they capture and get a synthesized `super(...args)` constructor.
  - `super(...spread)` lowers to `js_super_construct_apply`, which runs the parent's whole standalone constructor, yet the root was staged up front too. The new `ctor_super_reruns_parent_ctor` (`lower_call/field_init.rs`) mirrors the `SuperCallSpread` arm selection and follows a plain `super()` into an inlined ancestor's body. When it answers yes, nothing above the leaf is staged.
  - `UpToInclusive(stop_at)`, used for an inherited constructor body inlined into a no-own-ctor class, staged the whole prefix including `stop_at`. That body's own `super()` applies those classes again, so a plain `class F extends E {}` over a constructor-owning derived `E` with a `#field` threw on `new F()`. It now stages what `stop_at`'s own constructor stages.
  - The standalone constructor of a no-own-ctor class (`codegen/method.rs`, the dynamic `new <classValue>()` path) staged the root, then called a local ancestor's constructor symbol, which staged it again. Afterwards it applied only `SelfOnly`, so constructor-free intermediates were dropped. It now stages nothing up front and applies `BetweenExclusiveTo(ancestor)` afterwards.
  - Gap test: `test-files/test_gap_11120_ancestor_field_init_staged_once.ts`.
