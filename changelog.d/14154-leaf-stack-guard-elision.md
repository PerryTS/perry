Performance: a compiled body none of whose calls can run JS drops its entry stack check. Every callee must be an LLVM intrinsic or a runtime symbol the GC-effects table does not class as `Reenters`; user code and unknown symbols count as `Reenters`. Such a body is on no recursion cycle, so the check never decides anything, and after inlining its `asm sideeffect` TLS read sat in the caller's hot loop. A loop-free body whose re-entering calls sit in at most eight blocks moves the check from its entry to a new block in front of each of them, so a path that calls nothing skips it. A calling block's leading phis move into its check block. It declines when one of those blocks is the entry block, or the body has a `try` or an `invoke`. The calling blocks keep their names and other contents. `PERRY_STACK_GUARD_CALL_SITES=0` keeps the check at entry for bodies that call, and `PERRY_LEAF_STACK_GUARD=1` keeps every check at entry.
