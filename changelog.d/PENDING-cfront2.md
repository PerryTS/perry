The compile's second module walk (`rerun_collect_with_class_field_types`, which lowers every module again against the class field types the first walk found) no longer prepares module sources again. The first walk returns the plain module sources it prepared (read, CommonJS wrap, static-require transform and the scans over their result), keyed by canonical path together with the settings they were prepared for, and the second walk takes them as an argument and drops them when it returns. The second walk uses a source only when the walk starts with the same preparation settings and computes the same classification for that module (wrap eligibility, JSON/text, entry); otherwise it prepares the module as before. A source that names both `import.meta` and `require` (TypeScript's `typescript.js` is one) still goes through the `import.meta.require` rewrite in each walk, because the rewrite records addons in the context; the second walk reuses the preparation that follows it only when its rewrite output is byte-identical to the first walk's. Asset adapters and `--bunfs-root` builds are still prepared by each walk.

Computed-`require` warnings are now collected apart from the CommonJS wrap's other diagnostics, so a prepared source no longer depends on `cjs_require_diagnostics`: the walk prints them only while that setting is on, which keeps them to the first walk as before. The `PERRY_DEBUG_CJS_WRAP` dump is taken by source preparation and printed after them, in the same order as before. A test checks that the second walk collects identical modules with the first walk's sources and without them.

Front end (start to codegen), base = the previous build: tsc 43.9 s -> 35.9 s (its second walk 21 s -> 12 s: `typescript.js` is no longer wrapped twice), fastify 4.2 s -> 3.9 s, Next.js standalone 36.5 s -> 35.8 s (its second walk was already bound by lowering). Peak memory at the end of the front end is unchanged within noise. Module objects are byte-identical to the previous build.
