The npm host packages never shipped the native-extension archives (libperry_ext_*.a), so a program importing node:http, ws, net, zlib, sharp and the other well-known modules could not link from an npm install. They now ship in a new @perryts/perry-ext-<platform> package (macOS and Linux glibc), which perry finds next to its host package and uses only when the versions match; the missing-archive error names the package to install.
