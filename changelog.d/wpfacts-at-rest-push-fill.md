I32 at rest, push-filled births: an int Array born empty by an instance field initializer (`k = []`, `k = new Array()`) and filled by `this.k.push(v)` in its class's constructor before anything else can see it is now stored at rest (I32 words) with its final length. A new flow-sensitive walk (wpfacts `push_fills`, beside `ctor_phase`) finds the fill phase: the class has no parent; from the initializer on `this` is used only as reads and stores of fields already defined (anything else closes the phase); the appends are top-level statements of the constructor body or of a top-level counted loop `for (let i = A; i < B; i++)` with constant bounds, a counter nothing else writes and no `break` / `continue` / `return`; the first other mention of the field, a `return` or the phase closing seals it. The solver takes the fill as one birth in `N` steps: the template's birth length is `N` (so the length is fixed, the Array dense, and a read below `N` holds no `undefined`), a fill push is no append and no generic use for the Arrays of its own fill, and the template is an at-rest candidate beside the fused fills (new refusal `mixed push`). Codegen lowers a fill push (`rest_pushes`, keyed by the receiver's member offset) as one `js_array_rest_push`: the first append gives the Array its `N` slots and the I32 layout (the returned head is written back to the field), every append stores the encoded word at `length`, and the storage never moves afterwards. Check mode: a pushed value that is no int32, an append at or past `N`, and a slot below the floor that holds no I32 word (a read before the fill ends, a short fill) exit 86.
