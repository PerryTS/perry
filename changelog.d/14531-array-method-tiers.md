Array methods: every tier that runs an `Array.prototype` method by name now knows that the name resolves to that builtin on its receiver (`a.m(..)` is `Call(Get(a, "m"), a, [..])`); `push` was #14522, this is every other method. Five holes, all wrong answers before: (1) `pop` on a local, parameter or module-binding receiver (`Expr::ArrayPop`) ignored an own data or accessor `pop` (`a.pop = fn; a.pop()` popped): it now calls the checked entry `js_array_m_pop0`, as does the slow arm of the inline `pop`. (2) A folded Array method on a module binding read inside a function (`let G: number[]; function g() { return G.unshift(7); }`) was guarded by the global install flag, which no Array arms, so an own `unshift`, `splice`, `some`, `sort`, `copyWithin` or `toSpliced` was ignored: its guard now reads the Array header behind a heap-pointer test. (3) `findLast`, `findLastIndex`, `with`, `entries`, `keys` and `values` on a field receiver reached their direct call with no guard (an own property, an own prototype and a subclass override were ignored). (4) An object that is no Array behind an Array annotation (`const a: number[] = obj as any`, a class instance with its own methods, an array-like) ran the builtin for every method: the guard's runtime question is now the Array-site predicate `js_array_method_needs_get`, and the checked entries (`js_array_m_*`) no longer admit an ordinary object, so the site performs the real `Get`: the object's method runs, a missing or non-callable one throws TypeError. An Array subclass instance keeps the by-name body, which resolves a class override itself. (5) The universal dispatcher ran the array-like algorithm on an object without the method (`{ length: 0 }.push(7)` returned 1; node: TypeError): it now does so only for an object that inherits `Array.prototype`'s method. The facts model `Expr::ArrayPop` as the `pop` method call as well. No hot path gains a test: the inline `pop` and `push` tiers and the checked entries' fast admission are unchanged. Switch: `PERRY_ARRAY_METHOD_TIERS=0` (main's lowering and facts; a compile-cache input; the runtime halves, which only concern receivers that are no Array, have no switch).
