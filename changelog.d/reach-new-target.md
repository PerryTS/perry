Fix (whole-program facts, activation reach): a member of the new target's `prototype` is no longer called inactive after `Reflect.construct`. The object `Reflect.construct(T, args, N)` makes has `N.prototype` as its [[Prototype]]. For a built-in `T` (`Reflect.construct(WeakMap, [], NT)`) and for a function `N` that names no class layout, the solve holds the result as unknown, and it dropped the new target there: `NT.prototype = { has: () => ... }` then had a `has` whose body was "inactive" while `nt.has(k)` ran it: check mode (`PERRY_VERIFY_FACTS=1`) reported `Activation / inactive body: body entered` (parity fixture `map/test_gap_weakz2_birth_site`), and `PERRY_FACTS_DCE=1` trapped in the removed body. Where the result is unknown, what the new target's `prototype` holds now goes to the unknown with it (`Model::new_target_unknown`): it is on the chain of a value any code may call a member of. A class new target of a program target still names its layout, and nothing changes there. `PERRY_FACTS_REACH_NEW_TARGET=0` restores the previous model.
