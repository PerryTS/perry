Performance: a `+` of two calls that return strings is a string concatenation. Codegen types a call of a program function as "any value", so `squareName(a) + squareName(b)` called `js_dynamic_string_or_number_add` (about 65 instructions) although every body the call reaches returns a string. wpfacts now exports the primitive kinds of each call's result (`ModuleBindings::call_kinds`, by the call's span, joined over the copies of the call; a result that may hold an object or an unknown value exports nothing; probe `# call_kinds module=<m> offset=<o> end=<e> kinds=<kinds>`). Codegen (`expr/facts_string.rs`) lowers `a + b` as the pairwise concatenation when the facts call both operands strings: a call that returns only strings, such a call (or one that may also return `null` or `undefined`) defaulted with `?? <string>`, a `+` with such an operand, a conditional of two. The pairwise concatenation joins two short inline strings at the site and calls `js_string_concat_box` otherwise; the empty literal of `f(x) ?? ""` under such a `+` is the empty inline string. The fact selects a lowering, never an answer: every arm is still chosen by the operands' tags at run time.
