**The FNMT fallback root certificate was truncated by one byte, so the fallback provided no FNMT trust anchor at all.** The first entry of `FALLBACK_ROOT_CERTS` — used on hosts whose system store has no `RAIZ FNMT-RCM` — decoded to a DER of 1322 bytes instead of 1323, which every TLS stack rejects. Nothing caught it because the suite asserted only the PEM's shape (armour present, no test-CA names), and a mangled base64 body satisfies that. A new test parses every embedded fallback root as X.509 DER and fails on the offending index with the parser's reason: against the truncated body it reports `expected 1323, actual 1322 at DER byte 1322`.
