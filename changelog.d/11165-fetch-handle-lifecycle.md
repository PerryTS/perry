Fix unbounded Web Fetch registry retention and handle-id exhaustion in long-running services. A full GC now traces Request, Response, Headers, Blob/File and FormData ownership, removes records nothing can reach, and recycles their ids. This is the change that stops the retention #11164 prepared for: a Headers or FormData record's bound-method cache is released with the record. The Headers cache now lives in a registry-only `HeadersRecord` wrapper (not `Clone`), because `HeadersStore` is also embedded, unscanned, in every Response and Request record. Signals, cached Headers, FormData files, detached bound methods and subclass wrappers stay live while reachable. Minor collections still retain and relocate registry heap edges. Each mutator reclaims only the handles it allocated, including on thread exit.

Blobs named by an unrevoked `URL.createObjectURL` URL are strong roots, so `resolveObjectURL` can no longer return a different object after its id is reused; it also checks that the id is still a Blob. A freshly allocated id survives the first full trace after its birth (the Fetch scanner roots "young" ids), so an id a native function holds unpublished across an allocation is never recycled under it.

A collection triggered by an allocation can no longer self-deadlock on a registry mutex: every reader that allocated or threw while holding `FETCH_RESPONSES`, `HEADERS_REGISTRY` or `BLOB_REGISTRY` (`response.url` / `.statusText` / `.type`, `blob.type` / `.name`, `response.clone()`) now copies what it needs, drops the guard, then allocates. A source scan over every Fetch file fails on a guard held across an allocation, and regression tests run a full trace inside each of those readers and inside the Headers JSON helpers #11164 fixed.

Pacing: a full trace is requested when a mutator's owned-id count doubles since the last one (never below 4,096), and while the shared id band is nearly exhausted, instead of every 4,096 allocations regardless of heap size. Tracing checks the handle band arithmetically before the provider's thread-local lookup and indirect call, so ordinary heap words pay nothing extra.
