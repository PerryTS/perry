The cross-module method inliner no longer gives a module imports, and so module-init edges, for code it never inlined (#11244). Before this fix, `import { MongoClient } from "mongodb"` (and `import * as m`, `import { BSON }`) threw `Cannot read properties of undefined (reading 'default')` at startup, with mongodb 7.5.0 compiled from source.

- Root cause: `inline_functions_inner` admits every inlinable method harvested from earlier-compiled modules as a candidate. Some of those methods read names their own module imports (`Expr::ExternFuncRef`). The inliner queued an import of each of those names into the destination module for every admitted candidate, before any call site had chosen one, and nothing removed the unused ones later. Each synthesized import was an ordinary static import, so `run_pipeline.rs` (per-module `__init` deps) and `init_order.rs` (the entry's eager order) turned it into an init edge. A module reachable only through a lazy `import()` then initialized at startup. Inside an import cycle, a module was re-entered before its exports were populated. In mongodb's case, `mongodb-connection-string-url/lib/redact.js` gained edges to `mongodb/src/error.ts` and `mongodb/src/index.ts`. Through them it initialized the whole driver, which reached `.esm-wrapper.mjs` while `lib/index.js` was still mid-init.
- Fix (`crates/perry-transform/src/inline/extern_imports.rs`): admitting a candidate now only queues its requirements. After the inlining phases (init, functions, class methods), an import is added only for names that some body in the module actually references. The imports that remain are marked `is_deferred_require`. That flag is read only by init ordering, so the import binds the name for codegen but is never an init edge. No edge is lost. An inlined body runs only where the source method would have run, on an exact `new C()` receiver, so C's module has already initialized, and that module imports the path itself.
- Inlining decisions are unchanged: the same candidates are admitted and the same call sites are inlined. Only the unused imports are dropped.
- New gap tests: `test_gap_11244_inliner_import_init_edges` (a lazily imported module ran at startup, plus a control where the method is inlined and its import is kept) and `test_gap_11244_inliner_import_cycle` (the mongodb cycle shape, `TypeError: Cannot read properties of undefined (reading 'n')` on main). The fixtures are in `test-files/fixtures/issue_11244_inliner_import_edges/`. New unit tests: `cross_module_candidate_not_inlined_adds_no_import` and `cross_module_inlined_candidate_adds_its_import`. `cross_module_synthetic_imports_are_sorted` asserted the old eager behaviour, so it now stands in for inlined bodies and also asserts that the import is not an init edge.
