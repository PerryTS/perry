Performance: an element store through a key that is no proven index (`a[j + 1] = v` with `j` a counter bounded by its loop test, a parameter key) into a local, parameter or field the whole-program facts give an Array of Numbers (`Rep::Arr` with `elem` f64 or i32, not at rest) is now the rep-keyed store: the forwarding test (none for fixed storage), `idx <u capacity`, the hole test of the old slot, the plain-double test of the value (none for a native integer) and the raw store. Such a receiver is a plain program Array for its whole life (never frozen or sealed, no element descriptor) whose present slots hold Numbers, so the store needs no band, type or integrity test, no old-value classification, no layout note and no barrier. A forwarded header, a key outside the capacity or at or past 2^31, a hole, a growing store and a boxed value take the site's exact store as before. Check mode (`PERRY_VERIFY_FACTS=1`) tests the receiver's claim and the named slot before the store ("array rep", exit 86; `PERRY_FACTS_SABOTAGE=arrelem` with `array-store-negative` is its negative control). `PERRY_FACTS_ARRAY_STORE=0` turns the tier off; `PERRY_STORE_ARM_DIAG=1` prints one line per store that takes it.
