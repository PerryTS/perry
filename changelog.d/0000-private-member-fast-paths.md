perf(runtime, codegen): private class members (`#x` / `#m()`) no longer spell and scan marker strings on every access (#10501).

Every `obj.#x` read or write and every `obj.#m()` call ran `js_private_guard`, which built `#<perry:private-field:{class}:{name}>` (or `…private-brand…`) with `format!`, resolved the storage namespace, and scanned the receiver's own keys by name — twice, once as the brand fallback and once as the "initialized" check — before the value itself was touched. That was ~4,600 instructions per access. A private method call then READ the method by name (recording a member hint and allocating a bound-method closure) and called the closure, ~12,000 instructions per call. lru-cache spent about half its CPU there.

- **Guard fast path** (`ic_miss/private_guard_fast.rs`). For an instance member accessed on an ordinary heap object, every input the storage namespace depends on is checked to be inert — no fresh ClassDefinitionEvaluation on the lexical brand stack, the receiver, or the brand owner — so the marker is the template one and both checks reduce to "the receiver owns that marker with a non-undefined value". Which own key carries the marker, and whether its slot is inline, are pure functions of the receiver's ShapeId (ordered keys and the live inline bound are part of it; ids are never reused), so a per-agent 2-way cache maps `(ShapeId, class, access site)` to the slot. All three inertness inputs can only name an evaluation by reaching a class object of the declaring template, so a process-global per-template bitset (set in `js_object_mark_class`) lets ordinary classes skip them entirely. Anything the fast path cannot prove falls through to the unchanged general path, which stays the only source of verdicts and throws.
- **Per-site guard word.** A private FIELD access site (kind 0, instance read/write) now calls `js_private_guard_site` with a zero-initialized `i64` codegen global holding `(ShapeId << 32) | slot` for the last proven receiver shape, published only when the marker reads `true`. A hit is a shape-word compare plus one slot read (inline or overflow): no TLS, no hashing, no string. The template bit is re-checked on every hit. The word holds no managed address.
- **Fused `recv.#m(args)`** (`lower_call/private_method.rs`). An instance private-method call is lowered to `js_private_method_guard` (brand check BEFORE the arguments, as PrivateGet requires) and `js_private_method_call` (after them), which calls the declaring class's vtable entry, resolved once per site into a 2-word site global, with the same lexical private brand the by-name path established. Neither half uses the member-hint stack. Static private methods keep the generic lowering; a vtable miss falls back to the old by-storage-name dispatch.
- **No per-access allocation elsewhere.** Hint records carry an interned `&'static str` instead of a fresh `String`; `private_value_request` (the PIC-miss private read/write path) rejects on bytes and borrows the name, copying it only when a fresh evaluation actually needs a qualified storage key; the general guard no longer repeats an element-present check whose inputs are identical to the brand fallback it just ran.

Measured with the issue's `bench.ts` (N = 20,000 under callgrind, x86-64-v2; instructions per iteration of the class method body, before → after): `Priv.step` 31.7k → 1.6k, `PrivField.step` 14.0k → 0.39k, `PrivMethod.step` 15.6k → 3.5k (of which ~2.7k is PUBLIC `this.n` access, below). Whole-process per-iteration: `private` 40.7k → 10.6k, `private_field_rw` 15.7k → 2.1k, `private_method_call` 17.3k → 5.2k; `public` unchanged at ~230. Wall clock for N = 1,000,000 on this host: `private` 5.3 s → 1.7 s, `private_field_rw` 1.4 s → 0.18–0.24 s, `private_method_call` 2.5 s → 0.52–0.68 s.

Not addressed here, and now the dominant remaining cost: installing private storage appends keys to the instance, so its ShapeId no longer matches the class's canonical shape. Public method calls on such an instance miss the guarded direct call (`authoritative_has_own` in the dynamic dispatch, ~4.9k per call in `private`) and public field reads miss the typed class-field fast path (`js_class_field_get_ic` fallback, ~1.1k). Private storage also spills to overflow slots when a class has fewer public fields than private ones, and overflow reads never hit a PIC. Both need private storage laid out in the class shape (the "fixed slots" design in the issue).

Validation: the 38 private-member test files in `test-files/` (including the new `test_gap_10501_private_member_fast_paths.ts`, which warms every site and then feeds it foreign receivers, cross-evaluation receivers, overflow-slot markers, throwing private methods, argument-order checks, async/generator private methods) match Node 26.5.1 byte-for-byte; new perry-runtime unit tests cover interning, cache agreement with the general check, stale-slot re-reads, evaluation-branded receivers and the site word.
