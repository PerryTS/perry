**Raw native registry ids can no longer be mistaken for heap receivers by the named-get probes — and that is now pinned by a test.** The production half of this fix is already in `main`: the `native_get` raw-word arm classifies the handle band before it reads anything (`native_get.rs`), and `js_object_get_field_by_name` reaches named dispatch for those ids. What was missing is the witness, which is why the originating PR stayed open. The new test asserts that a raw id — `1`, the fetch band start, `HANDLE_BAND_MAX - 1`, and the same ids passed through an honest `Handle` tag — cannot prove an ordinary data slot (`try_data_get_by_name` answers `None`) and that `js_object_get_field_by_name` answers `undefined` for them, while an ordinary object still reads its key through both paths. It passes against `main` unchanged, which is the evidence that nothing was left to port.
