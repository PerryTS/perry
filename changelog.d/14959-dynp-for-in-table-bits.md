for-in over an object with an overflow table now walks the receiver's own key list in place instead of building a key array, and keys() and Object.keys read the same list. The table carries two summary bits (a hidden-key bit and an any-enumerable bit) that the walk and the key list use to skip work, and a for-in loop whose bound is a 32-bit integer keeps the bound unboxed. Observable behavior is unchanged: key order, deletion and addition during the loop, prototype-chain keys and shadowing are the same as before. For-in and keys() over 4 to 16 key objects are 8 to 10 times cheaper.
