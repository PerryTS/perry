A method call on `this` inside a constructor, a `super` method or accessor, and a read of a key that is not own yet (an accessor on the prototype chain may run) all run code that holds `this` before the constructor has assigned every key. Facts treated them as plain reads, so a key assigned after them was claimed set before anyone could observe the instance, and a declared field lost its initial `undefined`. They now close the constructor phase. A key the constructor stores holds the hole until the store, and facts no longer call it present from birth: such a key is now reserved (its slot is known, its presence is not). An elided read of it pairs the load with the hole compare and an absent key reads through the prototype chain, stores take the checked route, and the class's layout is not fixed, so `$pshape` clones keep their keys recheck. Before, `this.p === undefined`, `this.p ?? d`, `String(this.p)`, `this.p + 1` and `this.f()` in such a method read the hole as a value and disagreed with node.
