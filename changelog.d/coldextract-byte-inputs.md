**Borrow byte inputs for filesystem writes and crypto updates.** File writes retain the visible Buffer, TypedArray or DataView span with the existing B1 read lease instead of copying it into a native vector. The lease also keeps the bytes alive while an I/O error is constructed; string and array decoding use its owned snapshot form.

One-shot `crypto.hash` uses the existing state/update/digest helpers directly, eliminating its temporary JS Hash object and two prototype dispatches. Hash and HMAC updates share one scoped byte consumer across ordinary objects, local chains and stream methods. Byte inputs ignore `inputEncoding`, as Node does, while string inputs retain their decoding. SHA-384 and SHA-512 use one algorithm-bearing context per family from the ring provider already used by TLS, replacing their separate RustCrypto state variants. Other algorithms retain their existing implementations.

Removes per-input vectors and unifies the wide SHA-2 state representation; no cache, side table, package rule or optional backend path. Regression coverage checks visible storage identity, one-shot result-only JS allocation, offset views, Node encoding parity, partial-block hash copies, long HMAC keys and write error paths.
