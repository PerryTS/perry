Per-unit facts now finish on esbuild's `__commonJS` helper when the unit that defines it also calls it, as oxfmt's bundled acorn does (`ct = (e, t) => () => (t || e((t = { exports: {} }).exports, t), t.exports)` assigned inside an init function). Before, the facts pass ran rounds forever and the compile never finished.

The cause was in a unit's contract check, not in a contract rule. When the check handed out a new closure context of a function that was already a contract function, it escaped that context but did not count it as a change. The run unknown code makes on that context (here the inner closure's call through `e`) was created and then never solved, so the unit stopped with work it had just added still pending. Whether that happened depended on the unit's own previous contract of `ct`: reading the sound contract (`e` called, `t` escapes), the function was already a contract function and the unit published the narrow one; reading the narrow one, it was not, so the change counted and the unit published the sound one again.

The check loop now solves again while the model holds unsolved work (the worklist, pending instances, marker links), whether or not a check site counted its change, so no site can stop a unit early by forgetting to report one. The test `a_helper_reading_its_own_contract_back_reaches_the_sound_fixpoint` times out on the old loop and converges in 3 rounds with `t` escaping.

On the corpus the proven site counts are unchanged (qs_parse 344/1768, commander 44/1175, fastify 1699/22842, tscwork 51608/122969, tssrc 20028/87017). The other facts change only in units that had stopped with work pending: 6 sites that read as dead now have receivers (still unproven), 4 sites change their reason, one ajv literal in fastify gains a written field `gen` and a second writer of `data`, and the rest are diagnostic records. Codegen acts on none of these.
