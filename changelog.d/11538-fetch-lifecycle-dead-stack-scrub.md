- **perry-stdlib tests**: `fetch::lifecycle::lifecycle_tests::readers_survive_a_full_trace_that_releases_ids_of_their_own_kind` failed deterministically on Linux CI (debuginfo-off test builds) and blocked #11424. The reader's allocation runs a synchronous full trace, and that trace scans the native stack conservatively. The calls that minted the "garbage" id, and the aging collection before the reader, left the raw id in a slot of the reader's frame that the reader never writes, so the scan retained it. There is no runtime leak and no stale global record. The case now zeroes 64 KiB of dead stack from its own frame before each reader. The new test `a_stale_dead_stack_copy_of_the_id_is_scrubbed_before_the_reader` plants the id in dead stack; it fails without the scrub and passes with it. On perrymaster with CI's env, the lifecycle test failed 10 of 10 runs on main and 0 of 40 with the fix.
