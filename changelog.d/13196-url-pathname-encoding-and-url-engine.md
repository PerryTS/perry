Constructor `pathname` now applies the WHATWG path percent-encode set instead of only escaping non-ASCII, so `new URL("https://x/a b<c").pathname` is `/a%20b%3Cc` (`/a b<c` before) and matches Node. `%` stays outside the set, so existing escapes and stray `%` pass through untouched, and tab/LF/CR are stripped rather than encoded. The shared encoder also gains `^`, which Node escapes in paths (`/a^b` → `/a%5Eb`) even though the standard's set omits it.

Assigning `pathname` on a URL with an opaque path is now a no-op, as in Node: `new URL("mailto:a/../b")` followed by `url.pathname = "q/../r"` keeps `mailto:a/../b` instead of rewriting it. Hierarchical URLs (`https:`, `file:`, `foo:/a`) still take the write.

`url-engine` is now linked for a default or namespace `node:url` import that only calls helpers. `import url from "node:url"` leaves `NativeModuleRef("url")` in the HIR rather than the `module: "url"` marker the feature scan looked for, so the engine was never installed and `domainToASCII`/`domainToUnicode` silently fell back to plain IDNA — `domainToASCII("a/b")` returned `a/b` where Node returns `a`. This also closes the last two failures in `test_gap_6375_legacy_url_parse_format.ts`, which uses that import shape.

New node-parity cases in `test-parity/node-suite/url/url/`: `path-percent-encoding.ts` (constructor escapes, `%` passthrough, whitespace stripping, opaque-vs-list `pathname` writes) and `default-import-helpers.ts` (constructs no URL, which is the trigger for the engine gap).
