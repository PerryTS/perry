Performance and cleanup: compiled code no longer tests for, or decodes, an INT32-tagged Number. Since P3 B4a nothing can produce one, so a Number has one encoding, the plain double, for every operand, proven or not. Removed from generated code: the INT32 arms of `===`/`!==` and of the relational operators against a Number, the per-local decode of a comparison graph, the boxed arm of the shared array-key normalizer, the INT32 half of the typed-entry and direct-closure-call guards and their convert block, the switch discriminant's canonical view (a numeric `switch` now compares the discriminant directly), the Number-parameter entry conversion, and the Number receiver's INT32 test. `PERRY_WP_REP_P3` is gone: it restored a tag test that no longer exists. The runtime's own INT32 readers are unchanged (P3 B4b removes them). `PERRY_VERIFY_FACTS=1` still checks every trusted Number is a plain double (P3 B3).
