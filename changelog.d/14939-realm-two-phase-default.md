Runtime: the two-phase population of the realm global is the default. A program's first touch of a core global (`Array`, `Object`, `Error`, `Promise`, `Map`, `console`, ...) builds phase A alone; the families of phase B (`WeakMap`, `WeakSet`, `WeakRef`, `Proxy`, `FinalizationRegistry`, `Atomics`, `Intl`, `WebAssembly`, `Temporal`, the performance entry classes, `Date`, the typed arrays, `ArrayBuffer`, `SharedArrayBuffer`, `DataView`, `Buffer`) are built when the program first observes one of them or the global object itself. A program that never does starts with fewer instructions and a lower peak RSS; a program whose first touch is the global object populates its realm in one pass as before. `PERRY_REALM_TWO_PHASE=0` at compile time restores the one-pass population (the program then links none of the two-phase path). On Linux the two-phase population (the phased copy of the rows, the core entry's first touch, the phase-B driver and their helpers, about 19 KB) lives in a tail section behind the program's own text (`.perry_tail`, placed by the link rule that places the JS text), so the runtime text and the program text of a program lie where they lie with the switch off; other object formats keep it in the text.
