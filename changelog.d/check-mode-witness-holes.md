Check mode (`PERRY_VERIFY_FACTS=1`): two classes of false whole-program facts ran to a wrong result with exit 0 instead of the false-proof report (exit 86). Both are closed where the generated code leans on the claim; with check mode off the generated IR is unchanged. (1) **The read of a hole-free Array.** The facts keep the element of a for-of walk a Number when the Array never holds a hole (`Model::hole`: a push-grown list, an in-bounds index store, a hole-free birth). A hole met by such a read is `undefined`, and what the read feeds converted it silently (`ToInt32(undefined)` is `0`, a number-context read's cold arm makes `NaN`). The element read now tests its own value claim (`ElisionFacts::number_element_reads`, a Number that is never `undefined`) where the slot is read: the key is an index below the length and the capacity, the slot is no hole, and it holds a Number (`array_rep::witness` at the three element-read entries for a local receiver the facts give an Array representation; `array_rep::witness_read` for every rep-keyed read and the rep-keyed default, predicate "array rep"). Readers audited: the for-of walk read, the IteratorRecord loop's read, the rep-keyed tier and its default (`a[k] ?? d`), the in-floor and below-length loads, held-length reads, at-rest reads (their word witness already refuses a hole) and the fixed-storage read. New negative control `PERRY_FACTS_SABOTAGE=nohole` (wpfacts: no Array ever holds a hole, falsified at the source and not at a store). (2) **The int32 claim on every binding shape.** The int32 witness was keyed on a body's proven `let`s, but codegen leans on the claim in two more places: a local the facts give `I32` takes the canonical i32 slot in every body, also where no proven-`let` set exists (module init, a closure, a static method), and a proven `let` the facts leave `F64` because nothing demands an int (a `const` read once) still gets the collectors' i32 slot, is read from it, and had its initializer lowered natively and seeded untested. The witness now follows the claim (`facts_int32_locals::claimed`): each double that enters either slot is tested, each `++`/`--` of such a local is tested on the double the step makes, and check mode lowers a proven local's initializer as a value (the witnessed path) instead of through the native initializer path. Shapes audited: a `const` or `let` read once, destructured bindings, a parameter default, compound assignment and update, field initializers, ternary and logical arms, call arguments, return values, a `const` a closure captures, module-level bindings, loop-local bindings, and method, static-method, closure and generator bodies. S0 arms: `forof-hole-negative` (`nohole`), `forof-dense-birth-negative` (`arrdense`), `int32-const-negative`, `int32-init-negative`, `int32-closure-negative` (`range`). No new switch: `PERRY_VERIFY_FACTS` is the switch.
