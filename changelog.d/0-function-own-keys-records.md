A function's own keys (`name`, `length`, `prototype`, added properties, symbols, private elements) live in the same record structure an ordinary object uses: one const-generic overflow `Table` home serves objects and functions, so every key operation (read, store, delete, descriptor, symbol, private element) has one body for both. Own-key tests on functions read the record instead of a separate property bag: `hasOwnProperty`/`Object.hasOwn` on literals and functions, `fn.name`, own `prototype`, `delete` on literals and function-constructor builds are faster. A function's record carries an absence fact for `call`/`apply`/`bind`, so `f.call(..)`/`f.apply(..)` on a function that inherits them reads the pristine `Function.prototype` slot directly. `Function.prototype.call` runs the plain call first, so evaluation order now matches node (`fcall_order`).
