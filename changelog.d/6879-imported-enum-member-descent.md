**Fix imported enum members reading `undefined` (#6879):** a member of an imported enum (`import { TokenKind } from "./tokens"; TokenKind.Ident`) resolved to `undefined` in several expression positions — `String(x)`, template-literal interpolation, array literals and object literals — while the same access bound to a local, passed to a user function, or string-concatenated worked, and the identical enum declared in the same module was correct everywhere. The `fix_imported_enums` pass, which rewrites `PropertyGet` on an `ExternFuncRef` into the member's constant, carried its own hand-rolled expression walker ending in `_ => {}`; any variant it did not list stopped the walk dead. The unlisted variant was `StringCoerce`, which wraps `String(x)` and every template interpolation — and, because it is an outer wrapper, also hid the array/object cases nested beneath it. The pass now delegates descent to `crate::walker::walk_expr_children_mut`, the shared compiler-enforced walker whose module docs describe this exact bug class, so a new `Expr` variant can no longer reintroduce it. The statement walker lost its catch-all too (it was silently skipping `do…while` and labeled statements), and class field initializers and computed keys are now visited. Found compiling the Milo compiler, whose lexer and parser are built on an imported `TokenKind`, so every parse failed with `expected 'undefined', got 'IDENT'`.
