Performance: cold slow paths inside hot loops no longer cost the loop its registers. LLVM learns that a helper call is unlikely from the `cold` attribute of the helper's declaration, and uses it to place blocks and to decide where the register allocator saves a value that is live across the call. The GC statepoint rewrite, which runs before the optimizer, keeps only the attributes of the call site, so for every helper that can collect the fact was lost: the loop poll's call, the shared cold element read and the inline-cache misses were weighed like the code around them, and values live across them were stored and reloaded on the likely path. A pass before the rewrite now copies `cold` to each call site of a `cold` helper and gives a branch with exactly one side that leads only into such a call the weights `llvm.expect` would give. Three helpers that exist only as the slow arm of an inline fast path are now declared `cold`: `js_gc_loop_safepoint`, `perry_array_read_cold_shared` and `js_array_note_numeric_write_value`; and the guard of the inline `-`, `*`, `/` and bitwise fast path expects two Numbers. Calls, conventions, statepoints and GC roots are unchanged. `PERRY_COLD_PATHS=0` restores the previous code.
