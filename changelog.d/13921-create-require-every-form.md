A literal `require` through `createRequire` loads an installed CommonJS package however the module obtains `createRequire` from `"module"` (a default import, CommonJS destructuring or binding of `require("module")`, or inline `require("module").createRequire`) and however it names itself as the base (`import.meta.url`, `import.meta.filename`, `new URL(".", import.meta.url)`, `fileURLToPath(import.meta.url)`, `__filename`). A relative URL whose final segment is `.` or `..` now keeps the trailing slash of the directory it names (`new URL(".", import.meta.url)` was the module's directory without its slash), and a `createRequire` base that ends in a separator resolves relative to that directory as in Node. Before, those forms threw MODULE_NOT_FOUND at runtime for a package that a literal `require` loads.
