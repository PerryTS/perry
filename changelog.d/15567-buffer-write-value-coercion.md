`Buffer.prototype.writeInt8`/`writeUInt16LE`/`writeFloatLE`/`writeDoubleBE`, the other fixed-width writers, `writeIntLE`/`writeUIntBE` and `writeBigInt64LE`/`writeBigUInt64BE` handle their arguments as Node does: the Number writers coerce the value with `+value` (so `"7"` and `{ valueOf: () => 5 }` are written as 7 and 5 instead of 0, and a BigInt throws `TypeError`); the BigInt writers compare the value with their bounds as Node's relational operators do (a string through StringToBigInt, an object through its `valueOf`) and throw `Cannot mix BigInt and other types` for anything that is not a BigInt; an invalid value, offset or `byteLength` throws Node's `ERR_OUT_OF_RANGE` / `ERR_INVALID_ARG_TYPE` with its message. The `Received …` clause of Node-style range and argument errors now prints a Number as JavaScript does (`1e+21`, `1.5e-7`, `-0`, with Node's `_` grouping: `1e_+21`) instead of Rust's full decimal expansion.
