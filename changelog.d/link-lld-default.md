Native x86_64 glibc Linux executables now link with lld by default when `ld.lld` 13 or newer is on PATH; `PERRY_LINK_LLD=0` (or `off`, `gnu`) keeps GNU ld, and without lld on PATH GNU ld is used as before. The binaries are smaller from the same code (chess −1.1%, hello2 −1.5%) and run no more instructions than with GNU ld: mimalloc's calls of the 16 libc functions that Rust code also binds through the GOT (mmap, memcpy, memset, clock_gettime, ...) now go through the GOT too (a vendored libmimalloc-sys 0.1.49 whose build script adds `perry/perry_noplt_libc.h` to mimalloc's compile only, and fails the build if one of those calls is still a PLT call), so lld no longer gives each of them a second, lazily bound PLT slot. The runtime's own `prctl` calls do the same. aarch64 Linux keeps GNU ld by default (not measured; `PERRY_LINK_LLD=1` opts in).
