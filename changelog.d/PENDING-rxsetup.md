RegExp `replace`, `test`, `exec` and the other RegExp operations no longer pay setup on a subject the pattern cannot match. Each compiled pattern now records the ASCII units every match begins with, derived once from its source when the RegExp data is published (a run of up to four units, each a literal, a `\d` or a simple class, case-folded under `i`). RegExpBuiltinExec fails at once on a string that contains no start of that run, before any program or subject binding. `RegExp.prototype[@@replace]` on a string subject with a string replacement takes the same check before it creates a handle scope, so a short no-match `str.replace(/\+/g, " ")` returns the subject after a header test, a `lastIndex` store and a byte scan.

The builtin-RegExp proof is now a fact on the receiver and the prototype: the receiver still carries the RegExp birth layout word, and `%RegExp.prototype%`'s shadow bit is clear. It replaces the per-site shape memo and its priming walk over `exec`, `test`, the flag getters and the symbol methods. The matcher, the flags and `lastIndex` are read and written directly through the birth layout's slots.

Semantics are unchanged: own or prototype overrides of `exec`, `Symbol.replace` or the flag getters, subclasses, relinked prototypes, non-Number `lastIndex` values, non-writable `lastIndex`, and the `lastIndex` results for `g`, `y` and plain RegExps all follow ECMAScript and Node. A pattern whose leading units could match non-ASCII text by case folding (`k` and `s` under `iu`/`iv`) records no run at that point.

qs `parse` instructions per call: 726,841 on main db6b253e91 (500,567 on 63f1b0e8f8, before step 5 phase 2 removed the read caches) drop to 445,233; `stringify` is flat. A short no-match replace with a hoisted RegExp costs about 50 runtime instructions.
