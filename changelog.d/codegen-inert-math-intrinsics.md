Performance: inside a loop, `Math.abs`, `Math.floor`, `Math.ceil`, `Math.sqrt`, `Math.min` and `Math.max` over operands proven to be Numbers lower to LLVM intrinsics only (`llvm.minimum`/`llvm.maximum` keep JS's NaN and signed-zero results), and a conditional `c ? a : b` whose test and arms are proven primitives runs no user code. Both are now inert: they no longer end a loop's receiver region or keep its body from counting as allocation-free. A loop such as `for (let f = Math.max(0, file - 1); f <= Math.min(7, file + 1); f++)` or one updated by `r += side > 0 ? 1 : -1` can keep its cached receiver facts. An operand that is not a proven Number (a `valueOf` object), `Math.round`/`trunc`/`sign`, the spread forms and a conditional with an object arm stay as before. `PERRY_INERT_MATH=0` turns it off.
