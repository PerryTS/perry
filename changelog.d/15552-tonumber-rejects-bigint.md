Spec ToNumber now throws a `TypeError` for a BigInt, including a BigInt that `ToPrimitive` returns for an object operand, so `[1, 2, 3].slice(1n)`, `"x".repeat(2n)`, `isNaN(1n)`, `Math.trunc({ valueOf: () => 1n })`, a BigInt timer delay and the other ToNumber callers throw as Node does. `Number(1n)`, `new Number(1n)`, `Number` used as a callback and `Intl.NumberFormat` formatting still convert. `++`/`--` on an object field holding a BigInt (`const o = { n: 1n }; o.n++`) keeps it a BigInt instead of turning it into a Number.
