Fix (whole-program facts, activation reach): an iterator's `return` called by a built-in consumer is no longer called inactive. A consumer that stops before its iterator is done closes it (IteratorClose): `Array.from(it, f)` when `f` throws, `Array.from.call(C, it)` when a property definition throws, a `Map` / `Set` / `WeakMap` / `WeakSet` constructor or `Object.fromEntries` on an entry it cannot take, a `groupBy` callback that throws, `Promise.all`, an iterator helper over `Iterator.from(it)`. The solve made the call of `return` for a for-of and for array destructuring only, so the `return` method's body was "inactive" while it ran: check mode (`PERRY_VERIFY_FACTS=1`) reported `Activation / inactive body: body entered` (parity fixtures `iterator/test_gap_iterret_close_consumers`, `iterator/test_gap_iterret_close_control`), and `PERRY_FACTS_DCE=1` trapped in the removed body. The consumers that can stop early now make that protocol call on the iterator `v[Symbol.iterator]()` returned and on `v` itself (`Gen::iterate_closed` for the lowered consumers, `builtins::iterate` for the built-in ones). Array and argument spread run the iterator to its end and call no `return`, as before. `PERRY_FACTS_REACH_ITER_CLOSE=0` restores the previous model.
