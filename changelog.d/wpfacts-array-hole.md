Whole-program facts: an Array's iteration now reads only the indices below its length, so it yields `undefined` only when the array may hold a hole. Each array object carries that fact: a literal without an elision, a spread literal and an array record are born dense, appends (`push`, `unshift`, `splice`) keep them dense, and a store under an index or a computed key, a `length` store, an index `defineProperty`, a spread into the array, a delete or unknown code's writes may leave a hole. Every other birth may hold one. An index read `a[i]` keeps `undefined` (it may be past the end). This is the first half of the chess for-of element class (G9): the loop element still holds the done result's `undefined` until the iteration protocol is read per loop.
