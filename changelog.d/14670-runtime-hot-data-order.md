Linux binaries keep less of their read-only data in memory: the link now places the runtime's `.rodata` and `.data.rel.ro` sections that ordinary programs read (tables, vtables, constant strings) together at the front of their output sections, in the same linker script as the default hot-text order, instead of leaving them spread over the whole runtime data where every first read maps another 64 KiB of the file. The order is a checked-in list (`crates/perry/src/commands/compile/link/hot_data_order.txt`) recorded over a corpus of programs with valgrind's lackey, one hash-free key per data section (its symbol, or for an unnamed constant a digest of its bytes and relocations), resolved by the compiler against the runtime archives of the link. No instruction, object or data byte changes, only where the runtime's data sits. `PERRY_HOT_DATA_ORDER=off` keeps the previous layout; `scripts/hot_data_order.py` records and builds the list, and its `check` command is the gate. Native glibc Linux executables only; with GNU ld the `.rodata` half needs x86-64's default script and may add up to one page of alignment padding.
