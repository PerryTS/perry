Calling a method on a value whose static type is `EventEmitter` now dispatches on the runtime receiver (#11300). A parameter annotated `EventEmitter` lowers `emitter.on(...)` straight to the events provider's `js_event_emitter_on(handle, ...)`. That function only knows its own emitter handles, so for any other EventEmitter (a stream, a `net.Socket`, `process`, a user subclass) `on`, `once`, `off`, `emit`, `listenerCount`, `listeners`, `eventNames`, `removeAllListeners` and `set`/`getMaxListeners` silently did nothing. mongodb's `onData(emitter: EventEmitter, ...)` is called with its Transform-based message stream, so the driver never saw a server reply, and server selection timed out.

- Each entry point in both providers (`perry-ext-events` and the stdlib's bundled events) now checks whether it owns the receiver. A receiver it does not own is re-dispatched by method name on the runtime value, through `js_native_call_method`, exactly as an untyped call is.
  - For ext-events, a receiver is foreign when it is outside the provider's handle band: a heap address, or a small id registered with another provider, such as a net socket.
  - For the stdlib provider, a receiver is foreign when it is an aligned heap address.
  - The payload of `undefined`/`null` keeps the old no-op.
- The owned-receiver test is inlined, and the re-dispatch helpers are `#[cold]`. On a 1M-iteration `on`/`emit`/`off`/`listenerCount` microbench with a real `new EventEmitter()`, instructions rise by 0.26% (12.564G → 12.597G).
- New gap test `test_gap_11300_typed_emitter_param_dispatch`. It covers a plain emitter, a Transform subclass, a PassThrough, a user subclass, `process` and a `net.Socket`, all passed through `EventEmitter`-typed parameters. New unit tests cover the receiver classification.
