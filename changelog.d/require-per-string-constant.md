The whole-program facts treated a `require` call whose specifier is not a literal as one that may load `node:module`, so as soon as any value reached the specifier they sank `Module._cache` and returned an unknown value. In every CommonJS program that is not closed (one `require('process')` or `this.constructor` is enough), each static require keeps an arm that reloads its target through the support module's `reload(path, parent)`, which calls the loader with a parameter; the first path constant to arrive escaped the cache with every module record, its exports, classes and prototypes, and an unknown value flowed into every require binding. A require call now resolves per value of its specifier: each string constant resolves exactly as a literal with that string does (a compiled module's path gives that module's exports, `module` and `node:module` sink the cache, a builtin name gives that builtin, any other string the opaque result), and only a value no constant spells (any string, an object, an unknown value) keeps the computed branch. A literal is the one-value case of the same function. Proven read/call sites on small drivers: commander 49 to 135, semver 188 to 1322, yaml 359 to 2264, with solver work down (yaml 2.09M to 1.30M) and outputs unchanged.
