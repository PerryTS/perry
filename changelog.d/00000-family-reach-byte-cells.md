The typed-array / Buffer runtime group is linked by the whole-program fact `family_reach` instead of the text detector: a program the facts say never creates or observes a typed array, Buffer or ArrayBuffer does not link the group (its installer does not name `js_runtime_install_typedarray`), and a program the facts say may use one links it even where the detector saw no name (constructors reached through constant computed keys of `globalThis` answered `null` before). The name dispatch of the typed-array methods (`at`, `fill`, `set`, `indexOf`, the iteration methods and the rest) moved behind the group's install hook, so a program without typed arrays no longer carries it. A "never" is a claim the runtime checks in every build: the image hands it to `js_runtime_families_never`, and the one allocation of every byte cell (`buffer::store::store_alloc`) aborts with a message if a byte cell is born under it; the typed-array constructors and the method dispatch abort on an empty hook instead of answering `null` / `undefined`. A comparator sort's two private index cells are no values and are exempt (`store_alloc_scratch`). `PERRY_FACTS_FAMILY_LINK=0` restores the detector's decision and makes no claim. New check `perry-gc-effects births` (rules `scripts/gc_call_effects/byte_cell_births.txt`): every realm native whose body can reach the byte-cell allocation in the runtime's call graph must be an entry of the typed-array family or declare the birth, so the declared births the fact reads are complete.
