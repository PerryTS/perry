Fix: a local binding, parameter, function, class or import named like a global namespace now shadows it in direct member calls and constant reads, as in JS. Before, `const Math = {...}; Math.abs(x)`, a parameter named `JSON` and `JSON.stringify(v)`, `Math.PI`, `Number.MAX_SAFE_INTEGER` and `process.env.X` on a local `process` all lowered to the builtin. This applied to JSON, Math, Number, String, BigInt, ArrayBuffer, Date, URL, Response, AbortSignal, Buffer, Uint8Array and process. Every namespace arm of the call and member lowering now asks the one `shadows_unqualified_global` predicate.
