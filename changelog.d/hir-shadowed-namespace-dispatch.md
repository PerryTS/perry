Fix: a local binding or parameter named like a global namespace or a builtin module now shadows it in direct member calls and constant reads, as in JS. A function, class or import of that name shadows it too. Before, `const Math = {...}; Math.abs(x)`, a parameter named `JSON` and `JSON.stringify(v)`, `Math.PI`, `Number.MAX_SAFE_INTEGER` and `process.env.X` on a local `process` all lowered to the builtin. This applied to JSON, Math, Number, String, BigInt, ArrayBuffer, Date, URL, Response, AbortSignal, Buffer, Uint8Array, Symbol, RegExp, Map, Proxy, Array, Reflect, Object, process, tty and v8. Every namespace arm of the call and member lowering now asks the one `shadows_unqualified_global` predicate.
