**fix(runtime): a `VTABLE_IC` hit also requires the method name bytes to match, so compiled mysql2 no longer reads `'hi'` as `617` (#11341).** The per-thread vtable inline cache chose and matched its entries by `(class_id, method-name address)`. Not every caller passes a name that lives in rodata. The `new Function` interpreter (`dyn_eval`) passes a transient `String` for each member call, and `js_native_call_method_value` passes a GC string's bytes. Once such a buffer was freed and a different name was allocated at the same address, the cache dispatched the call to the previous name's method.

mysql2's generated text-row parser calls `packet.parseLengthCodedInt()` and then `packet.readLengthCodedString()`. The second call intermittently ran the first, so a text column read back as a number: 13 of 20 runs of the affected program on main with a `mysql_native_password` user, 0 of 20 with this fix. Entries now store the name bytes (up to 24 bytes, the same limit as `OBJ_DISPATCH_IC`). A new unit test, `vtable_ic_hit_requires_matching_name_bytes_not_only_the_address`, rewrites a buffer in place with a different name and asserts the lookup misses.
