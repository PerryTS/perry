Performance: a guarded element store of a statically numeric value (`a[k] = n` through a key that is no proven index, a field's Array, a captured Array) first tests that the slot's old value and the new value are both plain doubles. Such a store changes the slot only: no pointer is retired or stored, so it needs no layout note, write barrier or string addref, and a plain double suits either element kind once a NaN is the canonical one. It is now the two tests, the NaN select and the raw store; the value classification, the kind load and the layout predicate run only for the other pairs (a hole fill, a pointer, string or INT32 box on either side), which take the general store unchanged, as do a growing store, a frozen Array and a receiver that fails the guard word. `PERRY_NUMBER_STORE_ARM=0` emits no such arm; `PERRY_STORE_ARM_DIAG=1` prints one line per store that gets it.
