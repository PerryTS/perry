perf(codegen): outline eligible module-entry bodies into per-chunk functions (#8595). Building on the analysis in #8600, `PERRY_OUTLINE_ENTRY=1` rewrites an oversized entry body (`hir.init`) into contiguous chunk functions called in order, hoisting each top-level `let` declaration to the front of the entry and moving its initializer into a chunk so the existing `emit_module_globals` escape rule globalizes exactly the bindings shared across chunks. This keeps every function small enough for LLVM to fully optimize (a single 68 MB entry function is under-optimized by size-capped passes and is the root of #8583's RS4GC fan-out and the #4880 ISel cost), so it is primarily a *runtime-performance* change, with compile time as a bonus. Fail-safe and off by default: the transform declines (leaving the body unchanged) unless the whole body is provably safe to relocate — every top-level statement a plain expression or a single-binding `let`, no exports / globalThis / top-level await. Chunk `FuncId`s are minted above every existing function and nested-closure id. Validated end-to-end: an outlined program produces byte-identical, correct output to the single-function build across every moving-collector arm (`entry_outline_transform_8595`). Bodies with unhandled shapes (`var`, destructuring, top-level control flow, exports, `process.env` literals) still bail — extending coverage to real bundles like `cli.js` is the follow-up. Relocatable runs are outlined *around* any statement that must stay inline (control flow, etc.), preserving execution order, so a body only needs runs of plain statements — not a wholly plain body — to benefit.
