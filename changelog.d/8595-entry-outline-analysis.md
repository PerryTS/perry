perf(codegen): add module-entry outlining analysis + reporting (#8595, first increment). The module top level is lowered into a single LLVM function; for a large minified bundle that one function is enormous (the Claude Code `cli.js` entry is ~68 MB of IR, ~13,170 GC-root slots), which is simultaneously pathological for `rewrite-statepoints-for-gc` (#8583), instruction selection (#4880), and register allocation. This adds `codegen/entry_outline.rs`: the chunk-boundary rule (contiguous top-level statement ranges, never splitting a compound statement) and the cross-chunk `let` set (the bindings a future transform must globalize so chunks share state), reported under `PERRY_OUTLINE_ENTRY_REPORT=1`. Analysis and gate only — no transform yet, no codegen change; the correctness-critical transform (eval order / TDZ / hoisting / top-level await) lands separately.
