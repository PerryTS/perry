`for (const x of a)` over a value annotated as a numeric typed array (`Uint8Array` ... `Float64Array`) walks it by index only when the value really is a numeric typed array: a new runtime admission (`typedArrayForOfAdmits`, `js_typed_array_for_of_admits`) chooses between the live index walk and the iterator-protocol loop over the same value. A Number or an array-like object behind the annotation now throws node's TypeError ("not iterable") instead of iterating 0 times or as an array-like, a Set, a Map, a generator object or a BigInt view is iterated by its own iterator (lazily, closed by `break` / `return`) instead of 0 times. Heads the index rewrite does not take (a pattern or `var` head, a labeled jump, a long body) use the value when it is a numeric typed array, else the values its iterator yields.
