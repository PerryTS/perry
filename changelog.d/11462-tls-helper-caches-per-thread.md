### Fixed

- perry-runtime: the frozen arrays behind `tls.rootCertificates`, `tls.getCACertificates()` and `TLSSocket#getSharedSigalgs()` are now cached per thread. Before, they sat in process-global slots that every thread's collector visited as GC roots, although each array lives in the heap of the thread that built it. Once that thread exited and another thread's arena reused the address, the other thread's full traces kept whatever object was there alive (a dangling root). `js_tls_create_server` fills the sigalgs cache, so the TLS server tests made `fetch::lifecycle` reclamation tests fail intermittently in the parallel perry-stdlib suite: an unrelated `Headers` bound-method closure was pinned by the stale root. `tls.setDefaultCACertificates` is still process-wide: the PEM list is kept as Rust data, and each thread rebuilds its own array when the list changes. New test: `tls::tests::cached_tls_arrays_belong_to_the_calling_thread`.
