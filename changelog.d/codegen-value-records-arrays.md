With `PERRY_FACTS_VALUE_RECORDS=1` an Array whose elements are value records of one template is a record array: a `GC_TYPE_RECORD_ARRAY` head (length, capacity, the record's word count) with one edge to a pointer-free `GC_TYPE_RECORD_ELEMS` buffer that holds the records' words inline. It is its own representation (never a plain Array rep) and only the record-array intrinsics touch it: the birth of an empty literal that is the whole value of its holder (`let x = []`, `x = []`, `o.k = []`, a class field initializer), `push(r)` (the lanes are copied, no object is born), `pop()` and `a[i]` (a record result bound to lanes, absent when empty or out of bounds), `length`, and `for (const r of a)` (the index arm of the for-of; its iterator arm is dropped). wpfacts admits a record held by such an array (`R6`): every holder of the array holds nothing else, every operation is one of the intrinsics on a binding or a named read, the birth is at its holder, and the holders are in the record's module; anything else rejects (`R6Op`, `R6Store`, `R6Join`, `R6ArrayHolder`), which keeps the record a heap object in an ordinary Array. Each runtime intrinsic checks the head's type (a mismatch exits 86), and check mode adds the receiver witness `value record array`. New S0 arm `vrarrjoin`, parity fixtures `test_vr_arrays.ts` and `test_vr_array_rejects.ts`, and the `PERRY_VALUE_RECORDS_TRACE=1` census counts `arrays` and `array_ops` (value records VR-4b).
