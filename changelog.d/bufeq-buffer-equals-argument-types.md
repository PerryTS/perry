`Buffer.prototype.equals` and `Buffer.prototype.compare` now throw node's `TypeError [ERR_INVALID_ARG_TYPE]` for an argument that is not a `Buffer` or `Uint8Array` (a `Uint8ClampedArray`, another typed array, a `DataView` or an `ArrayBuffer` used to be accepted), and `Buffer.prototype.copy` rejects an `ArrayBuffer` target as node does while still accepting every `ArrayBufferView`. Instances of user classes extending `Buffer` or `Uint8Array` are accepted by all three, instances of classes extending another typed array or `DataView` by `copy`; the check reads the same view storage the methods then copy or compare, so `copy` never reports 0 bytes for a target it cannot write.
