Performance: `a + b` of two short ASCII strings whose join fits an inline string (five bytes) is now built from the operands' bits: an `or` of two shifted payloads, no scratch buffers, no byte-by-byte unpack, scan and repack. The arm sits at the head of `js_string_concat_box` (typed `+`) and of `js_dynamic_string_or_number_add` after its two-Numbers test (untyped `+`, which reached the same concat only after a second call). An operand qualifies when it is an inline string, or a heap string of at most five bytes whose header already proves it ASCII; any other pair takes the general path unchanged, and where the arm answers it returns the same bits the general path builds. `PERRY_STRING_FAST_PATHS=0` turns it off at run time. `PERRY_STRING_PROBE=1` on an instrumented runtime prints how many concatenations it answered and declined.
