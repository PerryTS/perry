Fix: an indexed loop whose Array changes its length through another name sees the change. `for (let i = 0; i < xs.length; i++)` with no call in its body is lowered with `xs.length` read once when the loop's walker (`classify_for_length_hoist`) finds no store in the body that can change it. The walker reads the text of the loop: it judged a store through `xs`, treated a local the text makes an alias (`const b = xs`) as `xs`, and took every other receiver for another Array. With `xs = k ? POPS : FIXED` and `POPS.pop()` in the body the loop ran on with the stale length and read past the end (`1,2,3,undefined,undefined,undefined,`, node `1,2,3,`); the same held for `shift`, `splice`, an assignment of `length`, growth by `push` or by an index store (the loop stopped too early), two parameters bound to one Array, an alias read from a field, an object literal, an Array of Arrays or a call's result, a closure's captured local, and a module-scope loop. wpfacts now exports `BindingFacts::named_length` (module `named_lengths`): a local that holds only plain program Arrays has a named length when every event that may change the length of an Array it may hold (the events `held_lengths` records, now with the node each store's receiver was read from) is placed in a function and, in every function that can name the local, has a receiver read from that local (its node, a narrowed read of it, or a summary instance's copy). A loop without calls runs only its own function's code, so with the fact no store through another name reaches the Array. The walker (`stmt::loops::named_len`) first runs with every other receiver feared: a store through one is then what the same store through `xs` would be (`b[i] = v` at the loop's counter stays inside whichever Array `b` is; anything else ends the hoist), and a loop it keeps that way leans on no fact. A loop it would refuse is asked again with the fact, where a receiver that hands the walked local's value on (a sequence, an assignment) still ends the hoist; without the fact (no facts, a per-unit solve, a program with markers, a local that may hold more than plain Arrays) the loop reads the length at every step. A sealed buffer or proven native view, whose length nothing changes, asks nothing. Check mode (`PERRY_VERIFY_FACTS=1`) compares the kept length of a loop that consumed the fact with the live one before every run of its body (exit 86, "named length"), and versioned clones do not consume it there; `PERRY_FACTS_SABOTAGE=namedlen` is the negative control. `PERRY_FACTS_NAMED_LENGTHS=0` turns the fact and the question off, which is the loop of before (a compile-cache input); the dump (`PERRY_FACTS_DUMP`) prints one `# named_len` line per Array local with its verdict or the event that refused it, and `PERRY_ARRAY_BASE_DIAG=1` prints one `[perry named len]` line per loop that asked.
