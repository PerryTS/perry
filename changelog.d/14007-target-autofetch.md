`perry compile --target android|ios|ios-sim|wasip1|wasip2` fetches the signed `@perryts/perry-target-<triple>` package from the perry release on demand, as `perry target add <target>` would, when the target's runtime or stdlib is not installed: it prints one `perry: fetching ...` line, verifies the Ed25519 manifest, and installs once per perry version under `~/.perry/targets`. The compile-time fetch is now generic over the package kind (`ensure_package`), and `locate_or_fetch` looks again after an install. An installed package that lacks the archive, the host's own triple, instrumented (`_instr`) archives and `PERRY_NO_AUTO_FETCH=1` never fetch; a refused fetch puts its reason and the install commands in the missing-library error. `perry run --target` keeps choosing local or remote by the installed libraries and does not fetch. The wasi npm smoke test sets `PERRY_NO_AUTO_FETCH=1`.
