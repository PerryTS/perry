Runtime realm: a built-in function can declare, at the runtime's own definition of the function, what it does to its inputs (`#[realm(Array.prototype.push, effects = { reads(this); stores(rest(0) -> elems(this)); returns(prim(num)) })]`; verbs: reads, coerce, calls, stores, stores(fresh), returns, open; slots this, result, arg(N), rest(N), returned(N), elems(..), field(.., key); operands also fresh(..), species(..) and unions `a | b`). The compiler's realm table is now generated once, in the leaf crate perry-realm-table (so a runtime edit does not rebuild perry-hir), and carries the declarations typed (`RealmEntry.effects`); whole-program facts can read it, no solver rule uses it yet. `perry-gc-effects effects` checks every declaration against the runtime call graph as a coarse backstop (a body that reaches a JS entry or the write barrier must say so) and prints the census of all realm natives. Declared: Array.prototype push, reverse, sort, filter, map, forEach, every, some, find, indexOf, includes, join. The compiled runtime and compiled programs are unchanged.
