**crypto: short runtime-built strings no longer segfault crypto calls (#11481).** A string of 5 bytes or fewer built at runtime is stored inline (SSO, `SHORT_STRING_TAG`); its low 48 bits are length + payload, not an address. Crypto masked every string/bytes argument to 48 bits and handed it to `bytes_from_ptr`, which dereferenced the payload as a `StringHeader*` — so `createHash("sha1").update("x" + n)`, `digest(enc)` with a computed encoding, `createHash(alg)` / `createHmac(alg, key)` with a computed algorithm or key, and pbkdf2/scrypt/hkdf password/salt/digest all segfaulted. Two layers are fixed: the stdlib's f64-argument readers now go through a new `bytes_from_value` (`crypto/util.rs`) that decodes SSO bytes directly, and the codegen crypto arms (`expr/calls/crypto_{hash,kdf,keys,misc}.rs`) unbox string/bytes arguments with `unbox_str_handle` instead of the raw `unbox_to_i64` mask. Covered by `sso_arg_tests` in `crypto/hash_handles.rs` and `test-files/test_gap_11481_crypto_sso_string_args.ts`.
