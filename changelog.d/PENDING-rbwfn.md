The shared read-before-write check (`collectors/read_before_write.rs`, asked by `typed_locals` and `integer_locals`) no longer treats creating a nested function declaration as a read of what it captures. A function binding (a `function f() {}` hoisted to the top of its body, or any local bound once to a closure and never written again) runs only where its value is used: a direct call runs its body after the arguments, and every other use (an argument, a property or array store, a return, an alias, `new`, a class capture) hands the value on, so its body may run from that point on. The check now judges the body's reads at each of those points, transitively through the function bindings a body uses, and at the creation only for captures copied by value (those without a cell the body preallocates). A body with a direct `eval` or a `with` keeps the old rule. In tsc this keeps int32 counters such as `enterCount`, `braceNesting` and `singleLineCommentCount`, initialized before the nested functions that read them are first called.
