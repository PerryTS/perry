### Fixed

- perry-runtime: an exiting thread now releases its entries in the process-global closure side tables (dynamic props, static prototypes, deleted keys, wasm funcref externals). `Arena::drop` drops every entry whose owner lies in the blocks it is about to free. Before this, a stale entry outlived its heap. Once another thread's arena reused the address, the entry looked like that thread's young owner, which tripped the `gc/young_log.rs` rule-1 debug assertion (#11319) and handed the dead closure's props to any new closure allocated at the recycled address.
- perry-runtime: `js_loop_turn_bounded` (`turnloop_pool::turn`, `perry_ffi_pool_turn`) now still collects ready completions when a main-thread notify is pending. Before, it returned without turning, so a synchronous pool waiter spun until something else cleared the process-global `NOTIFIED` flag, which on a non-primary agent never happened.
- perry-stdlib: the lib unit tests pass on clean main, both default-threaded and with `RUST_TEST_THREADS=1` (#11417). The crypto `randomBytes`/`pbkdf2` value-form tests now follow the turnloop design (the poll-phase next-iteration delivery, and pbkdf2 on the pool) and run as their own agent. The Fetch handle-band tests and the async_bridge resolution-queue tests serialize on their shared process-global state. The readline fixture reset now clears the runtime's stdin detach latch.
