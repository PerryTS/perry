Performance: an element read or store whose key the whole-program facts prove an integer Number inside the int32 range no longer normalizes the key at run time, and one whose key's interval is non-negative no longer tests its sign. wpfacts exports the key interval of every element site (reads, stores and called elements, joined over every copy of the site) as `key_signs`; codegen converts such a key with one exact `fptosi` (or takes the native integer it was widened from) instead of calling the shared normalizer, and a proven array index enters its element tier directly: no sign test, no `-1` select and no property-key arm. A key that may be negative keeps its sign test (the unsigned bound's miss arm, or the split's test), so it still reads the named property exactly; a key that may be a fraction, NaN, a string or a symbol has no interval and keeps the normalizer. `Array.prototype.at`, typed arrays and the index method clones are unchanged. Check mode (`PERRY_VERIFY_FACTS=1`) tests the claim at each consuming site and reports a false proof as "key sign" (exit 86); `PERRY_FACTS_SABOTAGE=keysign` is its negative control. `PERRY_FACTS_KEY_SIGN=0` turns the facts and their consumers off; the dump (`PERRY_FACTS_DUMP`) prints one `# key_sign` line per element site with an integer key.
