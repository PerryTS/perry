### Added
- LIFE I3 (instrumented runtime only, `PERRY_LIFE_REGIONS=<path>` in a binary compiled with `PERRY_LIFE_MEASURE`): the region ceiling. For every loop iteration, activation and turn, a sampled instance is decided at its end by one forced minor (plus a synchronous full for inside objects already old): clean when no object allocated inside it, by compiled code or the runtime, is still reachable. The inside set is the allocation census's fresh-header event. Byte samples record the verdict chain of their enclosing instances; `scripts/life-regions-report.py` builds the byte-share headline. Loop ids in the measure hooks are now stable (`loop` rows in the site file). Fixtures r1-r5 in `scripts/test-life-measure.py`. The census names a body that codegen compiles from a copy (`F$sig`) by its function (it was attributed to `<init>`); a loop iteration on a lowering path without a back-edge hook ends at the next iteration's start (counted, `restarted`); the report adds a hook-coverage table. The report also writes `ANALYSIS.md`: class a split by the outermost clean loop's code (the program's own file vs `node_modules`), top region ids by innermost-clean bytes with nesting depth, bytes by the region id's clean share (instance-based and byte-sample-based, with the per-id sample counts), dirty instances by survivor count with holders, and the share of class a decided only by restarted loops. `PERRY_LIFE_REGIONS_RATE=1` decides every instance (the default time budget can push the sampling shift to its floor, which leaves per-id shares empty).

### Fixed
- LIFE I3d: the region verdict no longer depends on how densely instances are decided. Shape key/attribute storage (`GC_FLAG_SHAPE_SHARED`, engine metadata, never a JS value) is not part of a region's inside set: the measurement's own full collections pruned shapes, the next instance re-minted their key lists and the shape table's carrier gate held them at its end, so every densely decided zod iteration read dirty (counted per region id as `meta_objs`). "Alive at a boundary" for an object a full decides is one predicate (`life::full_alive`) shared by the lifetime probes and the regions. `PERRY_LIFE_REGIONS_WHY=<path>` writes, for the first dirty instances of each region id, each survivor's holder chain back to its root (the full's mark parent record, the root-scan subphase, the registered scanner or the native frame). Fixtures r6 (promotion inside the iteration, clean), r7 (one kept object, dirty with one survivor) and r8 (shape key lists re-minted, clean; control `PERRY_FACTS_SABOTAGE=lifemeta` must fail) are checked dense and sparse; r8 mints its key and attribute lists at run time (an Error-subclass instance, as zod's `ZodError`), and the test requires `meta_objs > 0` so the fixture exercises the exclusion. Holder-chain labels no longer read attribute words of key storage as string pointers (the dump crashed on postcss and yaml).
- LIFE I3e: `PERRY_LIFE_REGIONS_SHIFT=<n>` fixes the global sampling shift; the time budget raised it to the 2^-16 floor on every measured program, so a "sparse" run decided almost nothing by id. The allocation census (`PERRY_LIFE_ALLOC`) adds `#shape_shared` (objects and bytes stamped as shape key/attribute storage).
