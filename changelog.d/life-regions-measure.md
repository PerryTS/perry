### Added
- LIFE I3 (instrumented runtime only, `PERRY_LIFE_REGIONS=<path>` in a binary compiled with `PERRY_LIFE_MEASURE`): the region ceiling. For every loop iteration, activation and turn, a sampled instance is decided at its end by one forced minor (plus a synchronous full for inside objects already old): clean when no object allocated inside it, by compiled code or the runtime, is still reachable. The inside set is the allocation census's fresh-header event. Byte samples record the verdict chain of their enclosing instances; `scripts/life-regions-report.py` builds the byte-share headline. Loop ids in the measure hooks are now stable (`loop` rows in the site file). Fixtures r1-r5 in `scripts/test-life-measure.py`. The census names a body that codegen compiles from a copy (`F$sig`) by its function (it was attributed to `<init>`); a loop iteration on a lowering path without a back-edge hook ends at the next iteration's start (counted, `restarted`); the report adds a hook-coverage table. The report also writes `ANALYSIS.md`: class a split by the outermost clean loop's code (the program's own file vs `node_modules`), top region ids by innermost-clean bytes with nesting depth, bytes by the region id's clean share (instance-based and byte-sample-based, with the per-id sample counts), dirty instances by survivor count with holders, and the share of class a decided only by restarted loops. `PERRY_LIFE_REGIONS_RATE=1` decides every instance (the default time budget can push the sampling shift to its floor, which leaves per-id shares empty).
