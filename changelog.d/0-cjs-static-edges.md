A literal CommonJS `require("./x")` of a module Perry compiles is now linked at compile time: the call runs the target's initializer once and reads its module record directly, with no string dispatch, cache lookup or path registry on the way. CommonJS modules now evaluate when their `require` call runs, after the statements before it, which is Node's order (previously a required module ran before the requiring module's body), and `module.children` lists each child once per parent, as in Node. A program is "closed" when no module can reach the loader: no `node:module`/`vm`/`inspector`/`repl` import, no native addon or `data:` import, no dynamic `import()` or `eval`, no write or escape of `require.cache` or `require.extensions`, no computed `require(expr)`, and no use of `require` or `module` as a value. A closed program links no dynamic loader at all (no path registry, no reload support, no `createRequire` machinery), which can make small CommonJS programs several megabytes smaller. A program that is not closed keeps full Node semantics for those features: every literal `require` then reads the live `require.cache` entry first, so a deleted entry re-runs its module, and modules publish themselves to the path registry as before.
