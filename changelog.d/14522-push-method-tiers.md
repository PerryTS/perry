Array `push`: every tier that calls the builtin append now knows that `push` is the builtin on its receiver. Three tiers did not. (1) The guarded numeric tier (`js_typed_feedback_numeric_array_push_guard` + `js_array_numeric_push_f64_unboxed`, taken by a `number[]` with room and a value that is a Number by annotation only, e.g. `a.push(x + y)`): the runtime guard reads the named layout only for element descriptors and never the Array's own-prototype bit, so an own data `push`, an own accessor `push` or a prototype installed on that one Array still ran the builtin (`own.push = fn; own.push(v)` returned the new length and appended). The tier now makes the inline tier's word test after the guard (a null named layout, the default prototype chain) and takes its fallback otherwise. (2) The native array push the HIR folds for a field receiver in value position or in a constructor (`return this.items.push(v)`) appended with no test of the receiver; the node is now the call it is (`perry_hir::folded_call::native_array_push`): codegen guards it with the diamond the other folded methods have (held: the append as before; failed: the real `Get` and call), and the facts model it as the `push` method call, as they do for `Expr::ArrayPush`. A fill push of a push-filled birth is unchanged. (3) The slow arms of `Expr::ArrayPush` asked only an Array for an own `push`; a receiver that is no Array (`const a: number[] = obj as any`, an Array subclass instance included) now takes the real `Get` first (new runtime entry `js_array_push_f64_spec_or_method`): its own or inherited user `push` runs, a missing or non-callable one throws the call's TypeError, and the realm's builtin continues with the append. The inline push tier and its admission are untouched. Switch: `PERRY_PUSH_METHOD_TIERS=0` (main's lowering and facts; a compile-cache input).
