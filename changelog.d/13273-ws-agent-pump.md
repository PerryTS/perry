`perry-ext-ws` now runs on every agent's own loop: its event pump is registered as a per-agent pump (`register_agent_event_pump`) and the keepalive (`js_ws_has_pending`) counts only the calling agent's connections and listening servers, so a `worker_threads` worker's ws events are drained by that worker's loop instead of piling up undelivered.

`perry-ext-ws` also owns its per-agent state end to end. When a `worker_threads` worker that owned ws servers or clients exits, its retire hook drops every row the agent owns (queued events, its listening-server count, connections, client listeners, parent-server links, protocol state and handles) without queuing a close event that another agent's pump could run; before, those rows stayed for the life of the process. Client listener tables and server handles record the agent that allocated them, and a collection visits only the current agent's slots instead of every agent's. A server's listening count is released once, to the agent that took it, rather than to whichever agent closes the server.
