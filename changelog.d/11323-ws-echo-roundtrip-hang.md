- **ws: a server + client echo round-trip in one program no longer hangs (#11309).** A standalone `new WebSocketServer({ port })` plus a `ws` client (send, echo back, close) ran to completion under Node but never exited under Perry. Three defects, fixed together:
  - **`close_listener` cut off in-flight connections** (`perry-http-server`). An accepted connection resolved its `Host` through the listener map, and `close_listener` removes the listener. Every completion after `wss.close()` was dropped: data, EOF, close and error. A `ws.close()` issued in the same tick as `wss.close()` never delivered its close frame to the server, neither side finished the closing handshake, and both connections stayed open for ever. Each `Conn` now holds the `Arc<dyn Host>` it was accepted for. A closed listener still refuses keep-alive for any further request, as before. This matches the documented contract: "in-flight connections finish".
  - **`'listening'` / `'open'` fired twice** (`perry-ext-ws`). The standalone server binds synchronously and queues `Listening` in its constructor. `js_ws_on('listening')` then saw `is_listening` and queued a replay on top of it, so every listener ran twice. A client opened from `'listening'` was opened twice, and in the server-initiated-close shape the second client was still handshaking when the first one's `'close'` called `wss.close()`, which also hung. The replay (and the equivalent one for `'open'`) now happens only when the original event has already been drained.
  - **A finished link lost its transport** (`perry-ext-ws` `turnloop_link`). `deliver()` and `terminate()` forgot the link and *then* looked up its transport. That lookup fell back to the process default, which only `perry-ext-http` registers. Without an `http` import the socket was never shut down, and with one, `finish`/`destroy` went to `perry-ext-http`'s writer with a ws connection id. The transport is now taken out of the removed link.
- Coverage: `test_gap_turnloop_ws_echo_roundtrip.ts` covers both user-visible shapes and times out on the base. New unit tests: `turnloop_link::tests::{a_completed_close_finishes_through_the_links_own_transport, terminate_destroys_through_the_links_own_transport}` and `tests::listening_is_replayed_only_once_the_queued_event_has_drained`, each checked to fail with its fix reverted.
- Not fixed here: `wss.once(...)` on the native `WebSocketServer` never fires. Use `wss.on(...)`.
