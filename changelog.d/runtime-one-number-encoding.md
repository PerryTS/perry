The runtime no longer decodes an INT32-tagged word as a Number (representation RFC §10 P3, B4b): a JS Number has one encoding, the plain double, in every value the runtime consumes. `JSValue::is_int32` / `as_int32`, the `is_int32_bits` predicate and about 330 consumer arms in perry-runtime, perry-stdlib and the http, net, sharp and better-sqlite3 extensions are gone (equality and compare, ToString and ToNumber, JSON, console formatting, key and index decoding, argument validation); the tag constant is now `INTERNAL_WORD_TAG`: the `0x7FFE` band holds runtime-internal words only (the I32 slot words of an at-rest Array or an I32 field lane, overflow routes, the bound-function marker, class captures, key attributes). The classifiers that read raw slot words (`value_bits_to_number`, the check-mode kind tests, the GC census, typed feedback, structured clone) keep the I32 slot word. perry-ffi: `JsValue::is_number`, `to_number` and `to_int32` read a plain double only; `JsValue::is_int32` is deprecated and always false. No behaviour change for programs: no producer of an INT32 Number existed since B4a.
