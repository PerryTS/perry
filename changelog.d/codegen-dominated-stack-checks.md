Performance: a compiled body makes one stack check per path instead of one per inlined helper. Inlining copies a helper's stack check into its caller, so a body that inlined nine helpers compared the same stack pointer with the same limit ten times on one path (the chess engine's `describe`: 18 instructions per call instead of 2). A check that another check of the same body dominates cannot fire: the frame's stack pointer does not move inside an activation, and the limit changes only inside `js_stack_overflow`, which does not return. Such a check is now dropped with its overflow arm, after inlining and before the statepoint rewrite, so the arm's call never becomes a statepoint. The first check on every path stays, so unbounded recursion still throws `RangeError: Maximum call stack size exceeded` at the same place. On Apple aarch64, where the limit is read through the thread's hot cache, a dropped check takes that lookup along when the lookup's blocks are the check's alone. `PERRY_PROLOGUE_COST=0` turns it off.
