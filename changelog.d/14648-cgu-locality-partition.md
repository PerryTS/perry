New opt-in codegen-unit partition by call-graph locality: `PERRY_CODEGEN_UNIT_LOCALITY=1`. A module large enough to be compiled as several LLVM units (16 MiB of generated IR or 8 000 callables; `three.core.js` is 8 units) deals its functions largest-first into the currently smallest unit, so a function's unit follows its size rank: one function that grows by a few bytes re-deals the functions below it (a one-line edit of `three.core.js` moves a third of its 6 207 functions to another unit and the binary by 16 to 20 KB), and a caller meets its callee in one unit only by chance (there is no inlining across units). With the switch on, functions joined by a direct call or an address reference grow into clusters, strongest reference first (recursion cycles, single-caller callees, other direct calls, then closure bodies with their creator; a module initializer that names every method joins nothing), clusters keep source order, and the sequence is cut into the same number of units at the cluster whose name hashes lowest inside a window around each balanced position, so a cut stays where it is when the bytes before it change; units are emitted in source order. The same edits then move no function. It stays off by default because the three.js binaries grow by 0.2 % and 0.5 % (more calls are inlined, and a split module's definitions are all external, so the inlined callee stays too) with instructions unchanged. `PERRY_CODEGEN_UNIT_MAP=<dir>` writes each split module's partition and reference graph as `<module>.units.tsv` under either partition. Modules that are not split (most programs) are unaffected.
