Performance: an index store whose key the program text bounds by a length test leaves no hole in the whole-program facts. Every `a[k] = v` used to mark its Array as one whose iteration may yield `undefined`, because a store past the end leaves a hole; for an Array whose length the program decides at run time (a `[]` grown by `push`, a `slice` copy) the key's interval cannot rule that out. Now a store is in bounds when a test `i < a.length` guards it (a `for` or `while` test, an `if`, `&&`, `?:`, an early exit), `i` is not written since, and the key is `i`, `i - c`, or `j`, `j ± c` for a local declared in the guarded code as `let j = i - c0` that is only ever decremented (an insertion sort's `result[j + 1] = result[j]`), and the Array is one of this program's whose length never shrinks (no `pop`, `shift`, `splice`, `length` store, delete or escape, through any name). Such a store overwrites an element or appends, so a for-of over the sorted copy yields Numbers only and the value stays an int32 through typed calls. `PERRY_FACTS_INBOUNDS_STORE=0` restores the previous facts; `PERRY_FACTS_DUMP` lists each proven store (`# inbounds_store module= site= arrays= kept= shrunk=`); check mode reports a hole read as a Number (negative control `PERRY_FACTS_SABOTAGE=inbounds`).
