The parity harness asked one question — "did Perry print what Node printed?" — with two implementations that could disagree: a ~30-stage `sed` chain in `run_parity_tests.sh` and a separate `normalize()` in `scripts/node_suite_run.py`. Each carried rules the other lacked: the shell chain decodes `<Buffer …>` dumps, folds whole-line `true`/`false`, truncates float precision and normalizes `console.time` output, while the Python one masks the `node:test` reporter's own artefacts. A disagreement decides whether a divergence between Perry and Node is reported at all, and the two runners gate different things — the shell chain behind the release-blocking `parity` job, the Python one behind the scheduled `node-suite-guard`.

Both now call `scripts/parity_normalize.py`, which owns the rule set and exposes two named profiles rather than one merged one. Merging was rejected on evidence, not taste: `(N.NNNms)` matches ordinary output, so adopting the node-suite reporter rules corpus-wide would hide real divergences behind a "duration" that was never a duration; and the parity chain's frame deletions are deliberately broader than the node-suite's, so adopting them there would delete legitimately indented output. The profiles are declared side by side so they cannot drift apart unnoticed, and `tests/test_parity_normalize.py` pins both against 26 fixture pairs captured from the two implementations this replaces — including `<Buffer>` decode with a NUL byte, which the historical `$( … )` silently dropped.

The comparison can no longer degenerate into a silent green. Both normalizer call sites run inside `$( … )`; if that process failed to start, its stdout was empty on **both** sides, the two sides compared equal, and every test reported PASS. `run_parity_tests.sh` now probes the normalizer once at startup and exits 1 with a FATAL message rather than run a suite whose comparisons cannot fail.

The `parity` and `smoke` suite selectors are removed. Both filtered `test-files/test_parity_*.ts` — a subset of what `--suite all` already runs — and nothing in CI, `scripts/`, the Makefile or the documented workflows invoked them. They survived as a second spelling of the same sweep, and the name implied a corpus boundary that does not exist: the `test_parity_` prefix still marks a gate category for `scripts/parity_threshold_gate.py` and `scripts/parity_matrix_trend.py`, but it selects no tests. Passing `--suite parity` or `--suite smoke` now fails with a message naming the replacement instead of silently sweeping everything.
