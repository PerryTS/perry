### Fixed

- **Function name/source registration no longer tightens a published FFI contract to buy its startup win (#9188).** Registering function metadata runs once per function a bundle *contains* — 72,713 of them on the compiled claude-code TUI — so the per-call cost is a startup cost every program pays whether or not it ever reads a name. Copying the bytes made a second, dirty copy of 5.1 MB of names and 23.8 MB of source text that the program image was already carrying read-only, and the source half exists only to serve a `Function.prototype.toString()` most programs never call.

  The copy had already been removed by storing `(ptr, len)` and borrowing the image. That is sound only if the bytes outlive the *process*, which is strictly stronger than the "outlives the call" the entry points had published — and `js_register_function_name` / `js_register_function_source` are `#[no_mangle] pub extern "C"` symbols, reachable from separately-loaded provider images and from FFI, so the stronger promise cannot be imposed on callers that already exist. #9188 was filed to make that a deliberate decision rather than a side effect of a perf commit; this is option 2 from the issue, splitting the entry points instead of retightening the contract:

  - `js_register_function_name` / `js_register_function_source` are back to their original contract: the bytes need only outlive the call, because the registry copies them. Every caller that is not codegen uses these — the runtime's own global-helper installation (`parseInt`, `isNaN`, …), provider images, FFI.
  - `js_register_function_name_static` / `js_register_function_source_static` require process lifetime and store the borrowed slice. Codegen emits these, and only these, from `__perry_init_strings_<prefix>`, where the bytes are `@.str.N` `private unnamed_addr constant` globals in the image.

  All the volume is on the borrowing side, so the startup copy stays gone from the path that had it, and no published contract was tightened underneath a caller.

  **Storage.** Borrowed and owned bytes live in separate maps rather than one map of an enum: an enum value would add 8 bytes to every one of the ~60,000 borrowed entries to carry the handful of owned ones, which measured as a net loss (+0.31 MB) even though it removed 1.8 MB of copies. The name registry already had that shape (a small overrides map for names `register_function_name_if_absent` infers at run time); source text gains the matching pair. Owned entries take precedence on read — an owned entry can only come from an explicit runtime registration, which is the more specific statement about that function — and the two locks are never held at the same time, so there is no acquisition order to get wrong.

  **The tests are sabotage tests, not exercises.** `copying_name_entry_point_owns_its_bytes` and `copying_source_entry_point_owns_its_bytes` register from a heap buffer, overwrite the buffer *in place* while it is still alive, and assert the registry still returns what was registered. Deleting the copy makes them fail deterministically (verified: 3 of 6 fail when the copying entry points are rewired to borrow) rather than turning into latent UB in a provider image, which is the failure this split exists to prevent. `copied_name_takes_precedence_over_the_image_name`, `if_absent_respects_a_name_in_either_map` and `snapshot_and_len_cover_both_maps` pin the two-map read rules, including that `Error.stack`'s staleness check (`function_name_registry_len`) counts both maps — a name in the snapshot that the length does not count is a name the resolver caches and never refreshes.

  Files: new `crates/perry-runtime/src/builtins/fn_metadata.rs` (the registries, split out of `formatting.rs`, which was 26 lines under the 2,000-line cap); `crates/perry-codegen/src/runtime_decls/mod.rs` and `codegen/string_pool.rs` (declare and emit the `_static` spellings); `scripts/check_runtime_symbols.sh` (both new symbols added as sentinels, so a stale runtime archive predating the split fails there instead of at link time on a build worker). `codegen/emission_order_tests.rs`'s IR-text matchers follow the emitted spelling — left on the old name they would have matched nothing and passed vacuously.

  Validation: 3,075 `perry-runtime` lib tests, 1,400 `perry-codegen`, 380 `perry-hir`; all 62 script gates in `scripts/run_lint_gates.sh`; `cargo check --workspace --all-targets` under `-D warnings` and `cargo clippy --workspace` (the Linux-only `pthread_getattr_np` redeclaration warnings reproduce on a clean `origin/main` checkout and are not from this change); the gap suite; and an end-to-end probe covering `console.log(fn)`, `fn.name`, method names, `fn.toString()`, and computed-key name inference.
