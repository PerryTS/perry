Stream state record reads are direct slot loads again. `read_slot` reads only the stream's traced state record: one record check and one load, with no property read and no indirect call. Before this change it also served the six public state fields behind the record's eight data words (`highWaterMark`, `buffer`, `length`, `pipes`, `corked`, `writelen`). For those it picked a std `thread_local!` key at run time (the state's birth shape, or the `_readableState` / `_writableState` site), so `LocalKey::with` called the key's accessor through a function pointer, and it fell back to an ordinary Get. That made every record-only getter Reenters in the GC call-effects table.

The public fields are now their own type, `StateData`, read and written by `read_state_data` / `write_state_data`. Their record words sit after the private slots and serve only the constructor's normalization and streams with no published state object. On the state's birth shape the read is one shape compare and one slot load, with each side's birth word accessed directly. Any other layout takes the ordinary Get node performs, in one cold out-of-line helper. A record slot can no longer name a public field, so the record getters are GC leaves by construction.

The linux-x86_64 call-effects table moves 23 stream getters from Reenters to Leaf: `isErrored` / `isReadable` / `isWritable` / `isDestroyed` / `isDisturbed`, the `readable*` / `writable*` flag getters, `closed` / `destroyed` / `errored` / `isPaused`, and `js_node_http_response_state_get`. The `highWaterMark` / `length` / `corked` getters stay Reenters because they keep node's ordinary Get.
