Runtime: the two-phase population of the realm global is the default. A program's first touch of a core global (`Array`, `Object`, `Error`, `Promise`, `Map`, `console`, ...) builds phase A alone; the families of phase B (`WeakMap`, `WeakSet`, `WeakRef`, `Proxy`, `FinalizationRegistry`, `Atomics`, `Intl`, `WebAssembly`, `Temporal`, the performance entry classes, `Date`, the typed arrays, `ArrayBuffer`, `SharedArrayBuffer`, `DataView`, `Buffer`) are built when the program first observes one of them or the global object itself. A program that never does starts with fewer instructions and a lower peak RSS; a program whose first touch is the global object populates its realm in one pass as before. `PERRY_REALM_TWO_PHASE=0` at compile time restores the one-pass population (the program then links none of the two-phase path). A program links one copy of the population's rows, not two: a fourth link-time hook (`perry_realm_populate_whole`) sends a one-pass population of a two-phase program (a first touch through the global object, a `vm` context) through the phased copy, same rows in the same order. What only a realm that starts with phase A alone runs (the core entry's first touch, the phase-B driver) sits in one run at the end of the default hot-text order, so a program that starts one-pass maps the text it mapped before.
