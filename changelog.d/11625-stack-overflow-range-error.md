- **Unbounded recursion throws a catchable `RangeError: Maximum call stack size exceeded` instead of dying with SIGSEGV / exit 139 (#10812).** Every compiled function, closure, method and static-method body now starts with a stack check (`perry-codegen/src/expr/stack_guard.rs`): load this agent's stack limit from a new slot of the per-agent pointer block (`AGENT_PTR_STACK_LIMIT = 2`, `perry-abi`), compare the stack pointer (read with an inline-asm register move, so no frame pointer is forced), and on overflow call the new `js_stack_overflow` (`perry-runtime/src/stack_guard.rs`), which builds and throws the `RangeError`. The overflow block branches on to the continuation instead of ending in `unreachable`, so ShrinkWrap can still sink the prologue past the check. `preserve_nonecc` recursion clones (#8175) keep their frameless leaf entry: they skip the entry check and are checked before each clone-to-clone call instead (`lower_call/func_ref.rs`), guarded by the existing `the_clone_entry_is_shrink_wrapped_frameless` gate.
- The limit is published once per thread from `tls_hot::fill` and sits `min(1 MiB, stack/4)` above the stack's low end, leaving room for runtime frames between checks and for the throw itself; while the error is built the limit is relaxed to half that reserve, so a recursing `Error.prepareStackTrace` is fatal rather than looping. The slot is read inline where the pointer block already is (initial-exec TLS on ELF executables, the pthread-TSD hot cache on Apple aarch64); targets that would need a call per function entry (Windows, x86-64 Darwin, wasm, dylib/staticlib outputs) emit no check and keep the old behaviour. No JS-callable native signature changes.
- Regression: `test-files/test_gap_10812_stack_overflow_range_error.ts` (function, method, closure-through-`map`, getter and try/catch-fallback recursion). Also fixes a prefix-collision in `element_shape_native_tests` (`ptr %r8` matched inside `ptr %r87`) that the renumbered registers exposed.
