Fix (whole-program facts, activation reach): a method reached through a name-keyed fold is no longer called inactive. HIR lowers `r.deref()` to `Expr::WeakRefDeref` (and `.register` / `.unregister` to the FinalizationRegistry nodes) wherever a binding of that bare name holds a `new WeakRef` / `new FinalizationRegistry` somewhere in the module; the runtime helper tests the receiver's kind and hands any other receiver to ordinary dispatch, so `{ deref: () => 40 }.deref()` under a colliding name runs the object's own method. The solve modelled the intrinsic only, so that method's body was "inactive" while it ran: check mode (`PERRY_VERIFY_FACTS=1`) reported `Activation / inactive body: body entered` (parity fixture `map/test_gap_weakref_receiver_shapes_7947`), and `PERRY_FACTS_DCE=1` trapped in the removed body. The fold is now also the ordinary method call on every receiver that is not the helper's own builtin kind (`Gen::name_fold_call`; the genuine WeakRef / FinalizationRegistry keeps its facts: no lookup is made on it). `PERRY_FACTS_REACH_FOLDS=0` restores the previous model.
