Performance: the Array that `slice` bears from an Array receiver is a plain Array for the whole-program facts. The default species arm of the runtime's `slice` allocates a fresh ordinary Array with its elements at the front of the allocation and copies the receiver's slots, so the copy now has an array rep (`# arr_rep … rep=arr<…,0>`: floor 0, not dense, not fixed) with the element representation of what it holds: its reads take the rep-keyed tier and its runtime-key stores the rep-keyed store, where both were the guarded tiers. The copy is admitted only while its species constructor is `%Array%` or none (a `constructor` object whose `@@species` is another realm constructor makes something else; a program species constructor's result is a separate value of the call), and, as any Array, only while it is not escaped, frozen or given a named property. `PERRY_FACTS_SLICE_BIRTHS=0` keeps the copy a dense, not plain, birth. Check mode tests the claim at every rep-keyed read and store ("array rep"); `PERRY_FACTS_SABOTAGE=slicebirth` with `slice-birth-negative` is its negative control.
