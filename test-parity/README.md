# test-parity/ — conformance gating artifacts

Two gates read this directory. They cover different suites and work
differently; the difference is the point.

## `gap_snapshot.json` — the gap suite (per-PR gate)

Generated by `scripts/gap_snapshot.py`, consumed by `scripts/run_gap_tests.sh`,
which is what the required `conformance-smoke` check runs on every PR.

It lists every `test-files/test_gap_*.ts` that is **not passing**. A test absent
from the file is expected to pass. The check is **bidirectional**: a new failure
is red, and so is a listed test that starts passing. That second direction is
the whole reason this file exists — under the old one-directional gate a fixed
test kept its entry forever, and the skip list decayed into orphans nobody could
revalidate (#797).

Never hand-edit statuses. To accept the current state:

```bash
UPDATE_SNAPSHOT=1 ./scripts/run_gap_tests.sh
```

then commit the diff. New entries land as `category: untriaged` with a null
issue — fill those in, that is the triage step the gate is asking for.

The required CI baseline remains `gap_snapshot.json` on Linux. The gap wrapper
selects `gap_snapshot.windows.json`, `gap_snapshot.macos.json`, or
`gap_snapshot.other.json` on other hosts, so platform-only results do not
pollute Linux's ratchet. Bootstrap a missing platform file on that host with
the same `UPDATE_SNAPSHOT=1` command, triage its generated entries, and commit
it. `GAP_SNAPSHOT=/path/to/file` can override the selection for an explicit
comparison.

The snapshot records `node_fail` and `skipped` explicitly instead of dropping
them. A test the oracle stopped covering is a visible diff, not a silent hole:
CI sat on Node 22 while the suite grew Node 24/26 features and hid 14 tests
that way (#6364). The oracle version is pinned in `.node-version` — it is a
correctness input, so regenerate the snapshot on the pinned Node, on Linux
(several failure classes are platform-specific).

## `known_failures.json` — the full parity suite (tag-gated)

Hand-curated allowlist consumed by the `parity` job in `test.yml`, which runs
the whole `test-files/*.ts` suite on tags and opt-in PRs. Still one-directional:
it only catches new failures. Migrating it to a generated snapshot needs a
full-suite baseline from a tag run and is a follow-up; until then its gap-suite
entries are redundant with `gap_snapshot.json` and are kept only so the
tag-gated job keeps passing.

Entries apply on every host by default. A failure that is specific to one or
more operating systems can add a `platforms` array containing `linux`, `macos`,
`windows`, or `other`; `scripts/parity_known_failures.py` compares it with the
`platform` recorded by `run_parity_tests.sh`. For example:

```json
"test_windows_only_gap": {
  "issue": "1234",
  "added": "2026-07-30",
  "category": "bug-open",
  "reason": "Fails only with the Windows runtime.",
  "platforms": ["windows"]
}
```

The parity runner also supports Git Bash on Windows. It uses the native
`TEMP`/`TMP` directory, selects `.exe`/`.lib` artifacts, and does not require
Unix-only `bc` or process-limit support. The remaining documented prerequisites
(`cargo`, Node.js, Python, and the Windows linker toolchain) must be on `PATH`.

## Category definitions

Used by both files.

| Category | Meaning |
|---|---|
| `ci-env` | Passes locally, fails in CI for environmental reasons (missing fixture server, no network). Not a Perry defect. |
| `module-inventory` | A Node module surface that is not fully implemented yet. Flips to pass as APIs land. Not a regression. |
| `bug-open` | A real Perry defect with an open tracking issue. |
| `bug-stale` | The tracking issue is closed but the test still fails. Needs re-triage and a new issue. |
| `gap-categorical` | A known categorical gap (e.g. `console.dir` formatting, lone surrogates). See CLAUDE.md. |
| `gap-bisect` | A failure whose cause has not been localized yet; needs a bisect. |
| `untriaged` | Machine-written placeholder from a snapshot update. Replace it with a real category and issue. |

## Generated, gitignored

`reports/` and `output/` are per-run artifacts and are gitignored. The only
committed evidence is the snapshot, the baselines (`node_suite_baseline.json`,
`parity_matrix_baseline.json`), and `threshold.json`.
