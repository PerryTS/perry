# Class D side-table deletion

Baseline: `f98073e991d1c6e2d5ba29adee2dc7c41649df7e`.
Build/test host: qb6, CPUs `0-23,32-55`, Cargo `-j8`, separate main/head targets.
No version fields change. Shape and transition caches remain.

### Legacy overflow storage

The only production value writer is `object/spill.rs::overflow_set`. Its normal
shaped-object arm calls `spill_set`, which stores into the traced array at
`ObjectMeta::spill`. The legacy map and last-Vec cache are populated only by its
fallback (disabled spill mode, a non-object owner, or an index beyond the compact
spill ceiling). Test writers in `object/test_root_accessors.rs` and
`gc/tests/block_skip.rs` manufacture entries directly.

Production value reads are `overflow_get`; all its caller sites appear in the
search above. GC readers are the overflow root scanner, the object child-slot
walk, copied-object scanner/cross-check, move rekey hook, sweep empty check and
per-owner cleanup. The object census reads lengths/bytes. Test probes read the
map to detect sweep or relocation.

The fallback is redundant under today's normal object model, rather than dead
under every environment configuration. Exotic receivers are dispatched before
shaped-object storage: closures use their traced own-property bag; native/exotic
expandos use their own bags; arrays and errors use their specialized paths.
`field_set_by_name/tail.rs` rejects other recognized GC kinds before plain-object
writes. The remaining direct overflow writers operate on ObjectHeaders.
The census fixture builds 200 wide objects plus Map and closure expandos,
collects, then checks the retained values. Main's normal census reports zero
legacy overflow entries (0 bytes). The same binary with `PERRY_OBJECT_SPILL=0`
reports 410 entries / 83,016 bytes. Both print `258`, matching Node. This proves
redundancy of the selectable mode, not that the whole branch was never executable.
Head prints the same Node result with and without the retired environment value,
and the overflow row is absent from both head census files.

Deletion removes both fields from `ObjectHotTables`, every GC hook listed above,
the census row and the rekey manifest entry. Larger representable indices now
use the object-owned spill array; compact IC admission retains its existing
index ceiling. GC survival tests inspect the real mark before sweep, without
introducing an allocation, root or barrier into their mutator window. Existing
spill marking, growth and evacuation tests continue to cover the structural edge.

### Stale closure-property prune

There is no declaration or writer for `CLOSURE_PROPS`,
`CLOSURE_STATIC_PROTOTYPES` or `CLOSURE_DELETED_KEYS`. Search hits are historical
comments and the stale dead-owner label. `closure/dynamic_props.rs` documents
that properties, deleted markers and recorded prototypes live in the traced
`ClosureHeader::props` bag; those values move and die structurally.

The prune implementation is **not completely dead**: with `wasm-host`,
`webassembly_table.rs` calls `register_wasm_funcref_external`, which writes
`WASM_FUNCREF_EXTERNALS`. The lifecycle readers remove/release replaced handles,
prune dead keys, rekey moved wrappers, release exiting-thread ranges and gate
sweep work. This live native-resource custody remains. The registry entry is now
labelled `WASM_FUNCREF_EXTERNALS` and compiled only with that feature, so the
stale label and the default-build no-op visit disappear.

### Typed-feedback address scanner

Every production Observation writer is in `typed_feedback.rs` and `guards.rs`.
Property, method and numeric-write observations pass through
`shape_keyed_object_addr`, which returns zero for these sources. Array, closure
and helper-return writers explicitly store zero. The sole nonzero receiver
writer was the artificial thread-exit test probe.

`object_shape` already returns `shapes::object_shape_id` for every genuine
ObjectHeader. Helper-return object facts use that same function. Every real
nonzero `shape_addr` is therefore a ShapeId, not a keys-array address.
`roots_object_addr` always returns false; `roots_shape_addr` rejects ShapeId
tokens. The registered scanner takes the registry mutex but visits no production
address. Its old rewrite test manufactured an arena address that no production
writer supplied.

The values are **read**, but only as diagnostic scalar facts: feedback-key
equality, representation-invalidation attribution, a never-called
`invalidate_shape_change` scaffold, and the artificial thread-address teardown.
Thus deletion removes the unused receiver-address field, represents shape facts
as `u32 shape_id`, deletes the unused shape-change scaffold, address teardown and
synthetic tests, and unregisters the inert scanner. Key equality and live
representation invalidation still compare shape/class/type facts. Profiles
continue to export their existing stable facts, never arena addresses. A separate
instrumented class census probe registers six sites and records array, method
and property observations; both arms print `39800`, matching Node, and export
identical feedback profiles. Their mutable runtime-scanner registrations change
from 97 to 96, while the probe reports the same 9,626 visited slots and 50 pointer
roots. The removed scanner contributed no production root, even with feedback on.

## Census gates

The declaration-site root census does not enumerate RuntimeState's struct
fields or this opaque non-TLS feedback registry; its documented limitations
already say so. No fake exemption or renamed holder conceals either deletion.
The runtime heap census drops the overflow row entirely; the rekey census drops
its custody entry. The root census's RuntimeState description drops the retired
field, and its JSON inventory reconciles pre-existing baseline drift:

- Delete stale declarations/frontier pins and entries that became scanner-covered.
- Classify existing scalar test controls/counters, old-gen pacing byte counts,
  the root-verification boolean, and the pointer-free inherited class-key snapshot.
- Re-audit PASS1_MARKED: the synchronous unbounded full cycle does not yield or
  relocate between mark propagation and sweep entry; pass2 consumes the TLS
  snapshot before reporting. Minor/budgeted cycles skip the window. This lane
  only removes a startup scanner registration from its pinned sources.
- Reconcile the existing shape-key scanner delegation and ephemeron work-queue
  custody in the rekey manifest. Neither changes runtime behavior.

### Instructions, RSS and emitted sites

The A/B rows are medians of three interleaved trials (arm order alternates),
`instructions:u`, diagnostics off, `setarch -R`, CPUs `0-23,32-55`. RSS is the
same trial's `/usr/bin/time` maximum resident set. THP is disabled through
inherited `prctl(PR_SET_THP_DISABLE, 1)` and confirmed as base pages in the
separate diagnostic runs. Full-collection counts come from the separate n=3
GC diagnostic batch, not the instruction runs. Worker head counts are 41, 41,
42, versus main 41, 41, 41; the table gives medians.

Class instructions per iteration use the supplied README method:
`(instructions(200000) - instructions(50000)) / 150000`, with equal warmup,
three interleaved trials at each size. The two effectively flat class rows are
within counter/process-start noise. Virtual-call and spread reductions are
small and consistent with removing runtime helper work. Removing the spill
mode's OnceLock checks, empty legacy-map lookups during object tracing/copying,
the inert feedback scanner mutex visit and the default closure prune visit
explains the bounded reductions in real-program instructions. This lane adds no
cache, name check, latch or side table; it unifies overflow on structural spill
storage and removes unused address bookkeeping.

Emitted bytes per program site are unchanged (0-byte delta): this lane changes
no compiler/HIR/codegen operation sequence. The checked tsc/Fastify native
objects are identical. The micros' emitted program-object `.text` totals are
also identical, before/after: getter 11,124/11,124 B; object array 9,225/9,225 B;
virtual call 10,967/10,967 B; spread 5,774/5,774 B. Every final linked program's
`.text` shrinks by 21,056–21,952 B, as shown above.

RSS does rise for Fastify (+2,936 KiB), buffer (+1,324 KiB) and worker
(+2,760 KiB) in the primary n=3 sample. Separate interleaved n=3 `/proc/PID/smaps`
probes with diagnostics and THP off identify a runtime image working-set/layout
change despite smaller linked text:

| Program | executable text resident delta KiB | other image resident delta KiB | sampled anonymous mappings main/head KiB |
|---|---:|---:|---|
| fastify | +2,536 | +80 | main 55,296–87,788; head 55,048–55,060 |
| buffer_heavy | +360 | +604 | main 45,076–45,104; head 45,116–45,124 |
| worker_heavy | +1,120 | +140 | main 66,412–72,472; head 67,512–70,856 |

These sampled peaks are attribution runs, not replacements for the primary RSS
measurements. `AnonHugePages` is zero in every sample. Fastify's arena reservation
and copied-object counts match between arms. Buffer's maximum per-cycle arena
reservation/in-use bytes are identical (10,485,760 / 4,462,064); worker's per-agent
maxima are identical (8,388,608 / 2,466,792). The reproducible image-page deltas,
identical emitted Fastify objects and overlapping anonymous-memory ranges
support code layout plus worker scheduling/peak sampling as the mechanisms,
rather than retained overflow entries or enlarged GC arenas. The worker
anonymous-memory contribution is noisy at n=3; its observed range exceeds the
primary median delta. No instruction regression or emitted-code growth accompanies
these bounded RSS changes.

check. It runs under `/root/MEASURE.lock`, CPUs `56-63`, `setarch -R`, n=3
