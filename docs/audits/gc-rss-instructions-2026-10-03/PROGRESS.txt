CURRENT PROPOSAL: pooled-block publication grace window (v6)
Implemented on top of the consolidated main69 candidate. A newly pooled block
starts with two publication ticks: the first completed collection preserves
resident contents; the following completed collection discards interior pages
if the block remains unused. Taking/re-pooling a block restarts the window.
Expired entries are advised only once. Critical, emergency and idle drains
retain their existing immediate allocation-release behavior.

This is a reuse heuristic indexed by completed collections. With normal pacing
it provides the intervening mutator an opportunity to reuse storage; consecutive
explicit/forced collections can advance the clock without an allocation gap.
It does not prove a block can never be needed again. Application fault/RSS/CPU
results must decide whether this criterion is worthwhile; no benchmark names,
new GC knobs or threshold changes are involved. Private pool entries gain one
small countdown field; no per-live-object side table or shape/header ABI changes.
