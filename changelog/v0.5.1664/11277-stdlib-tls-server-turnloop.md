tokio removal, lane L part 2 (`perry-stdlib -> tokio`): `fetch`, the `node:tls` server and the external `net` / `tls` / `ws` adapters no longer pull tokio into an auto-optimized program.

- **`node:tls` server on turnloop.** `tls.createServer().listen()` used to spawn a tokio accept loop, a `tokio::spawn` per connection and a `run_tls_socket_task` per socket that selected on an `mpsc` command channel. The listener and every accepted connection are now turnloop handles (`crates/perry-stdlib/src/tls/turnloop_server.rs`, completion-sink slot 14, id band `1 << 50`), and `perry-tls-session`'s sans-I/O rustls session is driven from the completion sink. `write` / `end` / `destroy` submit where the JS call happens. The 1 ms pause before `'close'` is an unreferenced `timer_arm` deadline. A thread that does not own the agent's loop posts through `perry_ffi::agent_post`, which is the P1 rule perry-ext-net follows. The events, their order, the registries and the handshake error texts are unchanged. One timing change: a bind failure is now reported synchronously, so the listener's keep-alive is released before `listen()` returns.
- **Features.** `web-fetch`, `tls-runtime`, `external-tls-server`, `external-net-pump` and `external-ws-pump` now imply `async-bridge` instead of `async-runtime`. `tls_stream.rs` is compiled only for bundled `net`'s TLS client and `wss://` (`tls` / `bundled-ws`).
- **CLI.** Auto-optimize used to select `async-runtime` for every co-built wrapper (`binding_needs_shared_tokio`). It now selects it only for wrappers that still bundle tokio, via the new `binding_bundles_tokio` (http, https, http2, mongodb). The #7629 link check and the no-auto warning key on that predicate too. The rule that added `async-runtime` for the `bundled-ws` / `bundled-net` / `http-client` wrappers is gone. perry-ext-net / -ws / -undici / -nodemailer stay in the co-build set.

Measured with auto-optimize on (tokio codegen units in the per-program stdlib archive / `tokio-1.` strings in the binary, before → after): fetch 16/41 → 0/0, net 16/52 → 0/0, tls+net 16/52 → 0/0, tls only 16/52 → 0/0, ws 16/41 → 0/0. The http control stays at 16 units.

Still on tokio: `http` / `https` / `http2` (perry-ext-http, until lane D lands), mongodb, pg / mysql2, bundled `net/mod.rs` and `ws.rs` (reached only with the well-known flip disabled, or through `full`) and every `full` / PERRY_NO_AUTO_OPTIMIZE build.
