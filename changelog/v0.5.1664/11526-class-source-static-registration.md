### Performance

- **Class source text is registered by borrowing the program image, not by copying it to the heap (#11501).** Codegen registers the original source of every class a bundle contains, so `String(C)` / `C.toString()` can answer with it — a class ref is an INT32 immediate, not a `ClosureHeader`, so this side table is its only record. `js_register_class_source` copied each class's text into an `Arc<str>` at module init, which on a large bundle dirtied megabytes of heap to hold a second copy of bytes the image already carried read-only, in service of a `Function.prototype.toString()` most programs never call. Function source stopped doing this in #9188; classes never got the same treatment.

  - New `js_register_class_source_static(class_id, ptr, len)` stores the borrowed slice and requires the bytes to live for the rest of the process. Codegen emits it for executables, where the text is a `private unnamed_addr constant` in the image.
  - `js_register_class_source` keeps its original contract (the bytes only need to outlive the call; the registry copies them). Codegen still emits it for `dylib` / `staticlib`, whose rodata `dlclose` can unmap, using the same `strings_outlive_registry` choice as the function-source registration.
  - `class_source_for_id` / `class_ref_to_string` now return `Cow<'static, str>`, so reading image text is borrowed too instead of being copied into a fresh `String` on every call. Borrowed bytes are stored unvalidated and decoded on read, as function source is (#9187), so module init does not page in every class body just to check it.

  Both ownership kinds live in the existing map (one enum value per class). No new side table: the function registries split them only because an enum costs 8 bytes on each of ~60,000 borrowed entries, and a bundle has far fewer classes than functions.

  Tests: `static_class_source_borrows_the_callers_bytes` asserts the registered text comes back at the caller's address, both from `class_source_for_id` and from `class_ref_to_string`. `copying_class_source_owns_its_bytes` overwrites the caller's buffer after registration and asserts the registry still returns what was registered. `last_registration_wins_across_ownership_kinds` pins last-write-wins across the two spellings and the NativeFunction fallback. `emission_order_tests.rs` now requires the `_static` spelling for executables and the copying one for `dylib` / `staticlib`. All of these were sabotage-checked: with the fix reverted, each one fails.

  Files: `crates/perry-runtime/src/object/class_registry/class_meta.rs` (registry and both entry points), `crates/perry-codegen/src/runtime_decls/strings.rs` and `codegen/string_pool.rs` (declare the new spelling and emit it by output kind), `crates/perry-codegen/src/wasm32/runtime_abi.tsv` (new symbol), `scripts/check_runtime_symbols.sh` (sentinel, so a stale runtime archive fails there instead of at link time), and `scripts/test-retained-source-pool.mjs` (matches the spelling an executable now emits).
