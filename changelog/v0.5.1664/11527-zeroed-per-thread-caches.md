- **perf(runtime): per-thread IC / plan caches are zero-allocated instead of filled (#11507).** The transition cache, the three array-tail transition tables, `VTABLE_IC`, `OBJ_DISPATCH_IC`, the store/read plan caches, the intern table, the inherited-read cache and the try/catch jump-buffer slab were built with `vec![EMPTY; N].into_boxed_slice()`, which for a struct element writes every slot and so dirties every page at thread start. They now come from `zeroed_cache::new_zeroed_cache` (`Box::new_zeroed_slice`), so untouched pages stay unmapped. The contract is an `unsafe trait ZeroEmpty` on each entry type: all-zero must be a valid value and the table's miss. Only one encoding had to change. `ArrayTailDirectIndex`'s miss was `u16::MAX`; stored indices now carry a +1 bias so the miss is `0` (the largest index, 8191, still fits). Emitted-code ABIs are unchanged: the transition cache's empty entry was already all-zero, and `TRANSITION_CACHE_SIZE`/mask are untouched. No table was made lazily created. Zeroed allocation already defers the pages, and a first-use branch would sit on hot probe paths.

  Measured on Linux x86-64 with a release runtime, as `Private_Dirty` from `/proc/self/smaps_rollup`, 5 runs each. Hello-world is unchanged (7168 → 7160 kB; with `PERRY_MEMORY_PROFILE=small` it went 1316 → 1304 kB). Release LLVM had already folded the main thread's fills into `calloc`, as the issue suspected. With 8 idle `perry/thread` workers alive, dirty memory fell from 45.5–47.5 MB to 41.4–43.4 MB, about 0.5 MiB per worker under the default THP profile. With `PERRY_MEMORY_PROFILE=small` it fell from 8.06–8.16 MB to 6.88–6.97 MB, about 150 KiB per worker. The saving is smaller than the issue's ~1.9 MiB estimate because the compiler already zero-folded most tables.

  Tests: each cache has a fresh-thread test asserting every slot of a newly created table reads as empty. There is also a round-trip test for the direct index's first and last index. Two sabotage checks were run. Reverting only the direct-index bias turns `fresh_thread_array_tail_tables_read_empty_everywhere` red. Making `new_zeroed_cache` return non-zero bytes turns all eight fresh-thread tests red.
