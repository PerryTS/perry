**Every class-field read, store and read/modify/write is a shape-site access (#12483).** A plain JavaScript class, the commonest class in `node_modules`, cost 150 instructions per `this.a` read where the same class written in `.ts` with declared fields cost 13. A `: any` field initializer (`a: any = 1`) cost 322–1,417 per read. The #10503 fixtures were inverted: the plain class, whose static guess is right, ran 1.8× (`tc.js`) and 3.4× (`tc_field.js`) slower than the class that adds keys conditionally.

Root cause: four mechanisms trusted the class's static **birth** ShapeId (its canonical keys global) and never learned anything else. They were the class-field read tower, the class-field store guard, the read/modify/write inline arm, and the loop regions' static supplier. No instance of a plain JS class ever carries that id: constructor-store fields are reservations, so the instance is born without those keys and reaches its shape by transitions. A `: any` field with a numeric initializer completes on an `F64` lane the runtime learns from the value, while the static birth rep, gated on the declared type, predicted `Any`. So every access missed the guard and paid an out-of-line call behind it.

- **Reads.** The class-field GET tower is deleted. A class-field read is the ordinary property site: receiver test, one ShapeId compare, one slot load, whatever the receiver. The compared ShapeId is the site's learned word, or, for a class whose instances are born on and keep its static ShapeId and that has no subclass, that ShapeId: a constant, so reads of one receiver share the proof (LLVM, or the class-guard run memo), and every miss is one call of the complete site operation (`js_object_get_field_ic`). Only a statically proven receiver (`Ptr<Shape>`) still loads without a compare. `js_class_field_get_ic`, `_fast`, `_fast_miss` and the read helpers behind them are gone, along with their tables and anchors.
- **Stores.** The class-field store guard and the sloppy class-store arm are deleted. A class-field store is the static-key store site, which keeps its own gated barrier. Only a statically proven store keeps its guard-free arm. For a declared field of a class whose instances carry their keys from birth, the store is an own-data overwrite. The site then emits only its existing-key hit inline (`emit_static_store_ic`'s `existing_key`); the ways, key-add memos and setter arm stay behind the same miss entry, so constructors of object literals and typed classes don't grow. `js_class_field_set_ic`, `_fast`, `_fast_miss` and `js_typed_feedback_class_field_set_guard` are gone.
- **Stores into `F64` lanes.** When the field is born on an `F64` lane in every ShapeId its class compares, the inline hit is only the `F64`-lane store of a plain finite double, with no GC bookkeeping. Anything else takes the same miss.
- **Proxy receivers on the read miss path.** `js_object_get_field_ic_slow` and its shared body no longer peek a GC header at `obj - 8` for a Proxy's bit-zero-tagged cell address; that was a misaligned dereference (a debug-build abort, undefined behaviour in release). It was latent for any untyped `p.x` on a Proxy, and class-typed reads now reach it as well.
- **Read/modify/write.** The inline arm proves the slot from the store site's memo word (the proof `js_property_rmw_fast` makes), or, for a field of a class that keeps its static ShapeId (as for reads), from that ShapeId and the layout's slot and lane.
- **Class-guard run memo.** `class_guard_memo` (one proof per receiver per straight-line run) now serves these predicted reads and updates instead of the retired class read precheck.
- **Loop regions and element-shape loops.** The static supplier names a class only when its instances are born on, and keep, its static ShapeId (`class_instances_keep_birth_shape`). Otherwise the region takes the learned word and the element loop takes the shape arm.
- **Birth rep.** A defined field's `F64` birth lane follows the value its definition writes, not its annotation, so the static ShapeId names the shape the instance completes on. Constructor-store reservations keep the declared-`number` requirement.

Measured on qb6 (marginal `instructions:u`, main → head): `soloread.js` 150 → 13 (its `.ts` twin 13 → 12); `tc_field.js` plain / if_many 266 / 78 → 14 / 14; `tc.js` plain 4.55M → 2.01M per run (if_many 2.47M → 2.01M). In the §C1.4 matrix's new `anyfield` column, read1 drops from 322–1,417 to 10–12 and overwrite from 306–1,296 to 7–9, matching `cfield` cell for cell. In the new untyped `jsclass` column (built from the `.js` twin), read1 drops from 151–153 to 12–14. The remaining `jsclass` gap is read4 and read4_hoisted at +4–5 (the learned region word keeps its slot indices in registers), plus the method row's untyped-receiver calls. On the 12 real programs instructions move −0.33% to +0.02% and `.text` shrinks by up to 132 KB (tsc); binary-trees arena −0.26%, plain +0.64% (one more instruction per two-read `check` call, GC counts identical).
