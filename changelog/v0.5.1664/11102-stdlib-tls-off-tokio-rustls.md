- **turnloop P8 group H: perry-stdlib no longer depends on `tokio-rustls`.** The three bundled surfaces that negotiated TLS through it — the `node:tls` server (`tls.createServer()`, `crates/perry-stdlib/src/tls.rs`), the bundled `net` client's `tls.connect()` / `socket.upgradeToTLS()` (`src/net/mod.rs`) and the `wss://` connector (`src/ws.rs`) — now run their handshakes on a sans-I/O rustls session, `perry_tls_session::TlsSession` (new `crates/perry-tls-session/src/session.rs`: client *and* server, over a caller-built `Arc<rustls::{Client,Server}Config>`, so the dynamic SNI cert resolver, client-certificate verifier and Node CA verifiers carry over unchanged). `crates/perry-stdlib/src/tls_stream.rs` drives it over the tokio sockets those surfaces already own and keeps `tokio_rustls`'s observable contract: rustls's error text on `InvalidData`, `"tls handshake eof"` on EOF mid-handshake, the fatal alert flushed to the peer before a handshake error is reported, clean EOF after `close_notify` vs rustls's `UnexpectedEof` message without one, `close_notify` on shutdown. The sockets stay tokio (`async_bridge::RUNTIME`, group L). The `js_tls_client_preflight` provider is untouched. `scripts/tokio_inventory.json` loses the `perry-stdlib → tokio-rustls` edge; `tokio-rustls` stays in `Cargo.lock` through perry-ext-net / perry-ext-http (groups A and C).
