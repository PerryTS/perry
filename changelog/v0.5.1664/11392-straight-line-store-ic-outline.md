- **perf(codegen): outline the store inline caches of a run-once store table (#10663).** A function with 512 or more property stores outside any loop now lowers those stores to the outlined `js_put_value_set_packed_miss` call instead of the inline polymorphic cache. The cache is about 20 basic blocks and 4 non-leaf calls per site, and a site outside every loop runs once per call, so the fast path was never used. `mysql2/lib/constants/errors.js` (3,942 `exports.X = N` / `exports[N] = 'X'` lines in one CommonJS factory) went from ~886k IR lines and 15.8k non-leaf call sites in one function (the relocation-estimate trip reported in the issue) to one call per store. Measured locally (perry-dev build, `--no-auto-optimize --no-cache`), a program that `require`s the file compiled in 3m53s before (217 s in one LLVM unit) and 26 s after (the module's IR fell from ~51 MB to ~7 MB, one unit instead of two), with output identical to Node's.

  The decision is per function and made from the HIR before lowering (`collectors/straight_line_stores.rs`, `codegen/helpers::decide_straight_line_store_outline`), stored on `LlFunction` next to the root-spill decision. Stores inside a loop keep the inline cache, and so do all stores in a function the hot-loop pre-passes marked (`hot_loop_callee` / `alloc_hot`), using the same `loop_targets` test as `new_site_is_in_loop`. An outlined store is the same call every inline-cache miss already makes and still goes through the site's runtime ways cache, so behaviour is unchanged. Module-wide outlining (`PERRY_FULL_OUTLINE_IC`, ≥4000 callables) is unchanged.
