Fix CommonJS loading of project Node-API addons authorized by `perry.nativeAddonPaths`. The wrapper now uses the canonical project-path map for both `require` and `require.resolve`, so generated loader IDs match the sidecar manifest's `$project/...` entries even without a project package name or beneath nested package metadata. Package-addon IDs retain their existing resolution.

Regression tests fail with the unfixed resolver and pass after the fix; all 148 CommonJS-wrapper tests pass. Native validation on arm64 macOS loads a real C addon from named, unnamed/debug-symbol, and nested-package projects after relocating the executable and sidecar and removing the original addon directory. Output matches Node 26.5.1, and an unauthorized project addon is still rejected. No version bump.
