fix(gc): the collector now works while the program is idle (#9589). Every automatic collection was scheduled by allocation, so a program that burst and then went quiet — a paste into a TUI, a request storm — kept whatever the last mid-burst cycle left in old-gen indefinitely; the compiled claude-code TUI pinned 425–680 MB through minutes of idle, flat to the byte, where node's memory reducer brings the same bundle to ~150–200 MB. `js_wait_for_event` now hands the collector the moment before it parks: if a budgeted cycle is open it is finished there, and if at least one collection has completed since the reducer's last full and the loop has been quiet for 3 s, a full budgeted cycle starts with the block-pool drain armed and runs in 4 ms slices that yield to the event loop as soon as a wake is pending, so input never waits behind more than one slice. Unproductive fulls back off exponentially (a retaining idle heap pays one whole-heap mark per ~32 collections, not per minor); a burst re-arms the reducer at once. New trigger kind `idle_reclaim` in traces; `[gc-idle-reclaim]` counters under `PERRY_GC_DIAG=1`; kill switch `PERRY_GC_IDLE_RECLAIM=0`. The reclaim tail of every full cycle now also purges mimalloc (`mi_collect(true)`): the platform trims it already called reach only the system allocator, so deallocated arena blocks sat in mimalloc's segment cache and RSS never followed `heapUsed` down.
