**`Array.prototype.toSorted` returned a stale pointer whenever its comparator allocated.** Both entry points captured their arguments before the clone allocation, so a moving minor — inside `js_array_alloc`, or inside the sort's callback into JS — left them reading and returning forwarded pointers; with the common `(a, b) => a.localeCompare(b)` comparator the returned array was dead. They now root their inputs with `RuntimeHandleScope` and take the relocated pointer back from `across_const`, and they return the sort helper's live result instead of the pointer captured before the sort. The regression runs both paths under forced evacuation with a comparator that calls `gc_collect_minor()`, asserts the source actually moved, and validates that the returned address is a live tracked `GC_TYPE_ARRAY` that is not itself forwarded before comparing payload values — a forwarding stub can make a generic read look correct while leaking the stale return. Without the rooting that liveness assertion fails; with it, both sorts return their sorted copy.
