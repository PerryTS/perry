String methods no longer hold their receiver across an argument coercion. `padStart`/`padEnd` ran `ToLength(maxLength)` and `ToString(fill)` with the receiver unrooted, because only the arguments' own lowering fed the rooting decision. `charAt`, `at`, `codePointAt`, `charCodeAt`, `slice`, `substring`, `substr`, `repeat`, `indexOf`, `lastIndexOf`, `includes`, `startsWith`, `endsWith`, `anchor`/`link`/`fontcolor`/`fontsize` and `localeCompare` unboxed the receiver to a raw address before the coercion ran. An object argument whose `valueOf`/`toString` collects therefore left a young receiver pointing into from-space; every one of these faulted under the from-space quarantine. Each coercing arm now coerces its arguments first, in spec order, with the receiver and arguments rooted across the coercion, and reads the receiver afterwards. A number or string argument needs no coercion and keeps the old unrooted, call-free shape (`b.toString(16).padStart(2, "0")`). `localeCompare` now coerces `that` before validating `(locales, options)`, which is the ECMA-402 order.

The native root-dominance checker now checks that tracked registers are relocated at each safepoint instead of assuming it. A `ptr addrspace(1)` register used below a safepoint without going through its relocation is reported (`unrooted`, or `stale` when the bundle names it), and constant-based values are exempt. Before this, a raw word that re-entered the tracked domain and crossed a safepoint was invisible to the checker. That is why the dependency-scale gate caught only 39 of 40 seeded violations (zod `classic/compat.ts`, in a stack-guard block). Both native gates now catch 40/40, with 0 hazards.
