- **fix(hir,runtime): a late-assigned `url.URL` read `undefined` for every property; a non-special URL's `href` gained a trailing `/` (#11322).** With `import { URL } from "url"`, `let u; u = new URL(s)` (mongodb 7.0.0's `HostAddress`) tagged `u` as a `url` native instance, so `u.hostname` lowered to a receiver-bound `NativeMethodCall` that returned `undefined`. `const u = new URL(s)` was unaffected. Cause: the assignment path (`lower/expr_assign.rs`) kept its own, looser copy of the `new C(...)` native-instance classification. That copy lacked the initializer path's exclusions for the heap-object `url`/`util` classes and the handle-backed constructors, and did no alias resolution. Both paths, and the `await new` arm, now share one classifier, `native_instance_for_new` (`destructuring/var_decl/native_new.rs`). Separately, `parse_url` seeded the path with `/` for every authority-only URL. Per WHATWG only special schemes do that, so `new URL("foo://a:5")` now has `pathname === ""` and `href === "foo://a:5"`, matching Node. Coverage: `test-files/test_gap_url_late_assign_non_special_path.ts` and `crates/perry-hir/tests/late_assigned_native_new.rs`.
