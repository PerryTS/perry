JSON.parse objects are born with the layout of their key sequence again (#12618): each object's members are scanned first, then the object is created once with its final key list and its values written into fixed slots. Duplicate keys keep their first position and take the last value. No parsed object gets an overflow table at birth; only later mutation (a reviver or user code) can add one. Restores the pre-step-4 parse cost and memory for record arrays (a 20k-record sum: -70% instructions, -49% RSS against step 4).
