**Buffer, typed-array and key-object recognition is a header read (#10694, #11919 item 1).** A `Buffer`, `Uint8Array`, `ArrayBuffer`, `SharedArrayBuffer`, `DataView`, secret `KeyObject` or `CryptoKey` is now told apart by its own GC type byte: `GC_TYPE_BUFFER` (a Node `Buffer`) plus six new buffer-family types (26..31) that share its `GcTypeInfo`. A typed array is told apart by `GC_TYPE_TYPED_ARRAY` / `GC_TYPE_NATIVE_TYPED_VIEW` and the `kind` its header already carried. `is_registered_buffer`, `is_uint8array_buffer`, `is_array_buffer`, `is_shared_array_buffer`, `is_data_view`, `is_secret_key`, `crypto_key_meta`, `buffer_brand` and `lookup_typed_array_kind` keep their signatures, so their ~470 callers are unchanged; each one is now a magnitude/alignment check, one header load and a compare.

Deleted: `BUFFER_REGISTRY`, `UINT8ARRAY_FROM_CTOR`, `ARRAY_BUFFER_REGISTRY`, `SHARED_ARRAY_BUFFER_REGISTRY`, `DATA_VIEW_REGISTRY`, `SECRET_KEY_REGISTRY`, the process-global `EXTERNAL_UINT8ARRAY_REGISTRY`, `TYPED_ARRAY_REGISTRY`, `TYPED_ARRAY_SHARED_BACKING` (now a flag byte in `TypedArrayHeader`), every latch and min/max address window in front of them (`RegistryAddrWindow` has no users left and is gone), the post-trace dead-registry scans, and the `PERRY_BUFFER_DIAG` probe instrument. A dead buffer's attribute entries (own properties, view record, AB alias, resizable max, CryptoKey metadata) are now dropped by the new `BufferSideTables` finalize hook of the sweep that frees the cell, and a dead typed array's by the existing typed-array hook.

Two guards that a table lookup did not need: a `Box`-leaked symbol has no `GcHeader`, so a header that claims a buffer or typed array is believed unless the payload's first word is `SYMBOL_MAGIC`, in which case the allocator decides (`header_is_owned`); and the runtime paths that decode a raw `top16 == 0` word (the shape of a subnormal number too) now let the allocator vouch for it before any header is read.

Behaviour fix found on the way: `keyObject.toCryptoKey()` re-branded the KeyObject's own cell, so the KeyObject also answered as a CryptoKey and `ko === ck` held. It now returns a fresh CryptoKey cell, as node does.

Measured (perrymaster, n = 9, release with 16 codegen units, against 1e80538852): instructions tsc −0.31% (inside its ±2.7% noise floor), Zod −1.54%, commander −1.08%, qs −1.06%, hello −0.20%; `Buffer.isBuffer` over mixed values −41%, DataView get/set −13%, `Buffer.from(string)` −19%; full collections unchanged; peak anonymous RSS unchanged; every binary smaller (hello and Zod −144 KB).
