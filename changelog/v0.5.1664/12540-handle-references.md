Native handles are JavaScript objects again in every coercion (#12540). Since honest pointers a handle (Headers, Blob, Request/Response, Web Streams, sockets, ...) carries `HANDLE_TAG` instead of `POINTER_TAG`, and the ToNumber / ToString / ToNumeric / `+` ladders that branched on `is_pointer()` sent it into their "plain number" arm: `1 / headers` was typeof "object", `headers + 1` and `String(headers)` were "NaN", `-headers` printed nothing, and a computed write `headers[key] = v` was dropped. Generated `==` / `<` and compare chains tested "is a plain number" with a one-sided signed compare that admitted `HANDLE_TAG` (a negative NaN), so `headers == headers` was false; typed-array and view stores could write a handle's bits as a float.

- `JSValue::is_reference()` / `value::is_reference_bits()` (and `perry_ffi::JsValue::is_reference`) is the one test for "heap object or native handle"; `is_pointer()` stays the representation test for a site that reads a GC header. The coercion ladders, `console.log` / `util.inspect`, the `instanceof` right-hand-side check, the iteration guard and every hand-written `is_pointer() || is_handle()` copy use it.
- A computed write on a handle is the ordinary receiver-aware [[Set]].
- Generated plain-number tests share the sign-closed `emit_plain_number_bits_test`.
- `scripts/reference_test_inventory.py` (CI: Reference-test audit) fails on a new raw pointer-tag test in the JavaScript-semantic modules unless `scripts/reference_test_allowlist.txt` justifies it, and on any one-sided signed number test in perry-codegen.
- Gap tests: `test_gap_12540_handle_object_coercion`, `test_gap_12540_handle_object_reflection`.
