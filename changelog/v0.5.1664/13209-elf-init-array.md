Linux: the feature-installer and static-shape-seed startup units register through `.init_array` instead of `@llvm.global_ctors`. LLVM lowered `global_ctors` to the legacy `.ctors` section for the in-process target machine (`UseInitArray=false`), which glibc on aarch64 never runs, so the dyn-eval, regex, url and temporal engines were never installed and `new Function` threw "dynamic Function refused". Mach-O and COFF are unchanged.
