fix(codegen): a call that takes raw string pointers no longer holds an earlier pointer across a later argument's coercion (#11830). Converting an argument to its ABI pointer can allocate and run user code (`JSON.stringify` calling `toJSON`, a short string being materialised, `js_string_coerce` calling `toString`), so converting the arguments in order left every earlier raw pointer one collection from a retired from-space address. The native-table `StrPtr` arguments, the FFI-manifest `string` / `json` parameters, the `perry/ui|system|...` table `Str` arguments and the i18n `{name}` placeholders now coerce each such argument in order into its own rooted slot and read the pointers back in one pass after the last coercion. The i18n params now live in a rooted group and are re-read at each use instead of being registers shared across the plural / locale diamond. Witness: `test_gap_gc_11830_native_str_args` (seeded-GC, fails on main, passes here); IR tests in `lower_call/conversion_window_tests.rs` cover the FFI, `perry/ui` table and i18n sites.
