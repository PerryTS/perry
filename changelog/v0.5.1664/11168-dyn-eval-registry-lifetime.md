Fix unbounded parsed-function retention in runtime `new Function` after the source cache reaches its 4,096-entry or 32 MiB limit, and when parse caching is disabled. The GC now drops registry ASTs once nothing holds them: no live closure (tracked with per-id owner counts, so a collection never rebuilds the live set), no source-cache entry, no active call/construction pin, and no registered parent AST. Minor collections prune through a young-owner log instead of walking every owner. Weak closure owners follow relocation and respect old-generation liveness during minors. Active AST pins are released through interpreter root-stack savepoints even when throws skip Rust destructors.

The nested-function node cache is now keyed by (parent function id, AST-node address) and evicted only together with its parent AST, so per-request nested closures reuse one registration while the parent lives instead of re-registering after every GC. `vm` scripts and direct `eval` register their parsed statements as pinned registry entries: previously the statements were a local freed on return, so a later script could reuse a node address and resolve to the earlier script's function (`vm.runInThisContext("(function(){return 1})")` followed by `…return 2…`). Function ids wrap without reusing a registered id. The GC hooks are gated on the `dyn-eval` feature, so `perry-runtime` builds without it.
