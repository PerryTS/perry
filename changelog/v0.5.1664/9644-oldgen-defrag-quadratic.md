fix(gc): old-page evacuation no longer rescans the whole old-gen free list once per moved object (#9644). `arena_alloc_gc_old_excluding_pages` asks `old_free_take_exact` for a hole that is not on a page the pass is evacuating, and that check is a linear scan of the size bucket — but in a defrag pass the excluded pages ARE the fragmented ones, so essentially every hole is excluded, the scan walks the entire bucket, fails, and falls through to the bump allocator, once per moved object. Measured on the #9644 fixture: 235,241 objects evacuated in 139 SECONDS, all of it inside the evacuation phase. The holes on evacuated pages are unusable for the duration of the pass and their block is released at the end, so they are now dropped once up front (`old_free_filter_pages`): the same pass takes 132 ms and returns the same 28.3 MB. This is a latent defect in `PERRY_GC_OLD_DEFRAG` itself, not only in the idle path — any workload with enough fragmentation to make defrag worthwhile hit it, which is part of why that knob never showed a benefit signal (#7917).
