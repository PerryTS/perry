- **perf(generators)**: for-of, spread, destructuring and sync `yield*` steps over a sync generator no longer allocate an IteratorResult. The resume body returns the raw step value and records its kind (yield, completion, or a `yield*` inner result object) in a fifth control slot of the generator record. Public `next()` / `return()` / `throw()` build the `{value, done}` object from that pair; `js_iterator_step` reads the pair directly. Sync `yield*` pulls through `js_iterator_delegate_step` + `js_iterator_delegate_kind` (replacing `js_iterator_delegate_next`): a fixed-state delegate hands its raw value to the outer generator, and only a user iterator's result object is re-yielded as-is. The key colouring counts the runtime-born `{value, done}` layout for every sync generator, so reads of `.value` / `.done` keep their inline colour-slot arm. Generator for-of witness -20.7% instructions, class `*values()` for-of -17.3%, fresh `function*` per call -4.5%, Effect-style `yield*` -3.0%; manual `next()` +1.7% (step-kind store and read at the resume boundary). Covered by `test-files/test_gap_generator_pair_steps.ts`.
