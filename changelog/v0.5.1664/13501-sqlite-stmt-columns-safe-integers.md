Fix `better-sqlite3`'s `Statement#columns()` and `Statement#safeIntegers()` reading `undefined`.
The extension served `run`/`get`/`all`/`raw` and, since #13365, every documented data property, but not these two through either the typed native table or handle dispatch — so a caller got no clean "not a function", only whatever its own code did with `undefined`. ActiveRecord's SQLite adapter inspects declared column types to decide whether to read big integers, and `stmt.columns().some(...)` threw `TypeError: Cannot read properties of undefined (reading 'map')`. `columns()` now reports one record per result column with better-sqlite3's five keys in its order (`name`, `column`, `table`, `database`, `type`), taking the origin names from rusqlite's `columns_with_metadata()` so a real table column says where it came from. `safeIntegers()` is a per-statement flag, shaped like the existing `raw_mode`, that makes INTEGER columns read as BigInt; it returns the statement so the call chains, an explicit `false` turns it back off, and an absent argument means on. Both are named in `STMT_METHODS`, so a bare `typeof stmt.columns` yields the bound method.
