wpfacts: the exports of a CommonJS/esbuild bundle (`__export(target, { k: () => f, … })`, a for-in over a literal defining one getter per key) are described per key again when the program writes a value from unmodeled code: a store into ⊤ under a key, or a `delete` on ⊤, is a fact about ⊤'s members, not a write of `Object.prototype` (⊤ holds no builtin prototype), so it no longer refuses every exact literal its runs per key; only a write of `Object.prototype` itself does. On tsc the two writes (`ref.isDefinition = …` and `delete ref.isDefinition` on a for-of element of an unmodeled iterator) had put every export getter of all 35 `__export` literals under `*`: the unproven sites naming "accessor under a computed key" go 44,826 → 0 whole-program; the proven count stays 52,047 because the same exports also reach dynamic code (E14) and calls of unknown function values, the next reasons in line. In explain mode the first write into ⊤ under a key names its site and the receiver's ⊤ origin.
