- **Tests (gc):** fixed an intermittent SIGSEGV in the full `perry-runtime` lib suite (#11362). It surfaced in `gc::tests::barrier::test_dirty_page_map_entry_scan_is_external_range_bounded` and `test_incremental_barrier_marks_external_map_and_set_slots`. The cause was a test fixture, not the collector. The hand-built old-generation Map fixture got its header from `arena_alloc_gc_old` and initialised only `size`, `used`, `capacity` and `entries`. That allocator reuses swept holes without zeroing, so `MapHeader.store` held an earlier test's bytes (`0x7878…`, a `"xxx…"` string). The thread-exit arena drop (`walk_block_maps` → `drop_map_store_at_thread_exit`) then `Box::from_raw`'d that value after the test had passed. The fixture now lives once in `gc/tests/support.rs` and zeroes the whole header first. The Set fixture's residue `meta`/`used` get the same treatment. A new regression test poisons the header with `0x78` before initialising it.
