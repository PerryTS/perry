Release builds ship `perry-cross-wasm32-wasip1.tar.gz` beside `perry-cross-wasm32-wasip2.tar.gz` (part of #13259), so `perry compile --target wasip1` works from an installed release without building the runtime. `scripts/wasi_release.py` and `scripts/wasi_release_check.py` take `--target wasm32-wasip2|wasm32-wasip1` (default `wasm32-wasip2`, whose bundle is unchanged). The release workflow builds the preview 1 runtime, checks that it imports only `wasi_snapshot_preview1`, and packages it. Each WASI-enabled host archive qualifies the release compiler with the packaged bundle (smoke, acceptance and pinned-Node suites with `--flavour p1`, every module checked for preview 1 imports) and stages the runtime under `wasm32-wasip1/release/` next to `wasm32-wasip2/`. A release source that predates the wasip1 packager ships only the wasip2 bundle.
