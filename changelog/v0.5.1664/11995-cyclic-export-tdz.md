**A cross-module read of an exported `let`/`const` in an import cycle throws while the binding is uninitialized, and CommonJS exports never do (Refs #11826, #11987).** An ES module on an import cycle names each exported lexical binding to the dead-zone machinery, so its global starts as the TDZ sentinel and its getter throws instead of handing an importer `undefined` or the folded constant. This re-lands #11963, which also seeded the CJS-to-ESM wrap's `export const X = _cjs.X`: that declarator never stores X's global (its getter reads `module.exports` live), so the sentinel stayed and the check after it threw `Cannot access 'X' before initialization` in qs and tsc. A CommonJS module's exports are properties of `module.exports`, not bindings, and are no longer seeded.
