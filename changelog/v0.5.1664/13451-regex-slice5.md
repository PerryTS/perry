Regex slice 5 (Perex 0.1.17): capture groups are read off the lazy automaton on one-pass matches. An anchored capture search (one-start programs, and the pass after `find` for the rest) records each transition's capture-slot effects once and answers with no evaluator; a transition that keeps two paths alive declines to the evaluator. The automaton's storage is now a separate old `GC_TYPE_REGEX_CACHE` leaf reached by one traced edge from the program cell (new `RegexProgram` descriptor), allocated, at the size Perex gives the program (`dfa::initial_words`), by the program's first search that needs automaton states, and reallocated at the size Perex reports when the program thrashes; searches the first-character descriptor decides allocate nothing, new storage is reset (one word) rather than zeroed, and program construction no longer zeroes or sizes any cache. A program whose capture pass found two paths alive is marked in its storage and not asked again. 32-regex: -46.9% instructions, -54.7% cycles.
