- **`node:http` / `node:https` / `node:http2` servers run on turnloop only; `perry-ext-http` no longer depends on `hyper` or `hyper-util`** (tokio-removal lane A, part 2). Every server has been served by the turnloop connection layer (`turnloop_serve`, `turnloop_h2`) since P5; hyper remained only as a fallback for three cases, and each now has a turnloop answer instead:
  - **A thread that does not own its agent's loop** (an embedder's pump thread, Android's UI thread for `perry-native`) used to build a hyper accept loop of its own. It now posts `listen()` to the owner thread with `perry_ffi::agent_post` (`turnloop_serve::post_to_owner`), which serves the same JS heap — the route perry-ext-net's `turnloop_io::on_loop` already uses. The `listen(cb)` callback is registered (and rooted) immediately; the `'listening'` emit is armed only once the owner's bind succeeds, and withdrawn if it fails. A host where `Loop::new` failed reports `listen ENOTSUP` through the server's `'error'` instead of running a second event loop.
  - **A SCHED_RR cluster worker** (Node's default policy off Windows) received each connection's descriptor from the primary and served it with hyper (`spawn_rr_inject_loop`). The descriptor bridge now hands every fd to the agent's loop with `turnloop_net::adopt_stream` (turnloop `Detached::from_fd` + `Driver::attach`, from #11105), and `turnloop_serve::adopt_connection` starts it exactly like a connection turnloop accepted — same `'connection'` event, codec, idle deadline and response path. `server.close()` stops the bridge handing connections over.
  - **A bind failure on the turnloop path** used to fall back to a hyper rebind that failed the same way; it is now reported once.
- Deleted with the fallback: the hyper HTTP/1.1, HTTPS and HTTP/2 accept loops and service functions, the raw-`'upgrade'` peeler (`raw_upgrade.rs`), the `tokio-tungstenite` attached-`WebSocketServer` handshake (`websocket_upgrade.rs`), the chunked-HTTP/1.0 header rewriter (`io_activity.rs`), and tokio's type vocabulary in the server structs (`ServerResponse::{response_tx, stream_tx, stream_in_flight, connection_close, transport_destroyed}`, `HttpServer::{shutdown_tx, request_rx, upgrade_rx}`, `Http2StreamHandle::response_tx`, `ShapeBody::Stream`/`Eof`, the `CONNECTIONS` registry). `HyperResponseShape` is now `ResponseShape` with a plain `Vec<u8>` body. `src/server/` contains no `tokio::` code; `perry-ext-http` also drops its `http-body-util` and `socket2` dependencies.
- Behaviour that existed only on the hyper fallback and so leaves with it (the default turnloop HTTPS path never had it): `https.Server` `'keylog'` and `'tlsClientError'` events, and `req.socket.servername` / peer-certificate CN forwarded from the in-process client's `x-perry-internal-tls-*` headers. Porting them to the turnloop TLS session is follow-up work.
- `scripts/tokio_inventory.json`: the `perry-ext-http → hyper` and `perry-ext-http → hyper-util` edges are gone (13 → 11 edges); the `tokio` and `tokio-rustls` rows now record that only the node:http/https CLIENT (plan C) holds them open.
