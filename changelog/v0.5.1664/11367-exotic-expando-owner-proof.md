- **Runtime:** fixed an intermittent SIGSEGV at `0x4010000000000010`, and a spurious strict-mode `TypeError: Cannot assign to read only property`, when a property was assigned to a native `AsyncResource` backing (#11364). `exotic_expando_kind` classified receivers from `try_read_gc_header` alone, and that reader checks only address magnitude and alignment. So a 24-byte native `Box` whose preceding allocator word looked like a `GC_TYPE_MAP` header was taken for a Map. `exotic_set_property`'s descriptor probe then read the Map `meta` field at `+0x18`, which is the next allocation's `4.0`, and dereferenced it. If the fake header carried `OBJ_FLAG_NO_EXTEND`, the write was rejected instead. An exotic verdict now also requires allocator ownership (`try_read_tracked_gc_header`: arena range or exact malloc-registry hit). Only receivers whose cheap header read already claims an exotic type pay for that lookup. Every consumer of the classifier inherits the proof, including all descriptor probes in `object/exotic_expando.rs`. In a loaded A/B of the `async_hooks` tests (12,000 runs per arm), main died 1504 times and the fix 0 times. The new regression test `untracked_owner_with_spoofed_map_header_is_not_exotic` spoofs the crash's exact shape.
