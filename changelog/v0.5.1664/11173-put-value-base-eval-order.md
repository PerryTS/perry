fix(codegen): an assignment's member base is evaluated once, before the RHS, for every base shape (#11150)

`this.#tail.next = this.#tail = node` wrote `next` onto the NEW node (a self-loop), so a linked list lost every entry after its head. This was the redis@6.1.0 `@redis/client` `SinglyLinkedList.push` / `DoublyLinkedList.push` blocker. `PutValueSet` carries one lowered base cloned into both `target` and `receiver`. Codegen's `same_put_value_receiver_expr` only recognised locals, `this`, literals, calls and plain property/index chains over those. Every other base took the explicit-receiver lowering, which re-evaluated the receiver after the RHS. Affected bases were a private-field read (`this.#o.x`, `this.#o[k]`, `p.#a.x`), a private getter (run twice), `super.x.y` (getter run twice), `new C().x` (constructed twice) and `(c ? p : q).z` (condition run twice). This held across `=`, compound and logical assignment. The catch-all now compares the two trees structurally over the `stable_hash` serialization (new `perry_hir::stable_hash::same_expr_structure`), so these bases take the same-receiver lowerings that public fields already use. Test: `test-files/test_gap_private_member_target_eval_order.ts`.
