Report `shape_descriptor_census` drift as a verdict instead of a Python traceback.

The census detects drift by raising `CensusError` (and `AssertionError` from its sabotage tests), and `main()` let both escape. Every real detection therefore arrived as a stack trace with the finding buried in the middle, and — because the census stacks dozens of independent assertions — each run reported only the first one, so the layers behind it were both invisible and hard to reach. This is the gate at its least useful: it did detect the drift correctly, and nobody could read what it detected.

`main()` now returns an exit code and catches exactly `CensusError` and `AssertionError`, printing `::error::shape_descriptor_census: <finding>` on one line. Anything else still propagates: an unexpected crash is a bug in the checker and must keep its traceback rather than be dressed up as a verdict. `--emit-baseline` is unchanged and still exits 0 with valid JSON.

This commit deliberately does *not* touch the census's data. The census is currently red for more than one reason at once: its baseline still records `object_header_size_bytes`, which the A1 object-header work replaced with `object_slot_base_bytes` and `object_meta_slot_offset_bytes`, and `assert_authority_surfaces` holds 77 assertions of which the first four have already been observed failing in sequence. Reconciling those is an audit of the census — each assertion has to be verified as still-preserving its guarantee, not merely made green — and it needs its own work unit. Making the failures readable is the prerequisite for doing it at all.

Verified in both directions. With the fix, the current red tree reports `::error::shape_descriptor_census: exact callsite census changed for raw_member_callsite_multiset; added=[], removed=[…]` — one line, zero tracebacks, exit 1 — where it previously printed a `CensusError` traceback. Driven with a deliberately unexpected failure (`ZeroDivisionError`), the traceback is still printed, so the catch is not swallowing bugs.
