**test(ext-net, ext-http): the loop-route tests run on agents they mint, so they no longer flake (#11597).** Several tests assumed that a libtest thread's route for the PRIMARY agent was settled. That route belongs to whichever test thread asked first, and only while that thread lives. So the "non-owner" in `upgraded_stream_adoption_is_on_the_callers_loop_or_refused` could claim a slot freed by another test's exiting thread and get a socket id. `listen_reaches_the_loop_on_every_route` and `deferred_connect_reaches_the_loop_on_every_route` raced another thread's lifetime between their `can_post` snapshot and the call, and `turnloop_is_live_as_the_http2_client_transport` failed whenever another test held the route. This was not a production bug: the first-to-ask rule is intended, and PRIMARY's owner lives for the whole process. The tests now mint agents (`enter_worker_agent` / `enter_agent_for_test`), so every arm (owner, posted, refused) runs deterministically on every run. The posted arm also checks that the owner's turn runs the job. The unconnected-write test now takes `GC_TEST_LOCK`, because another test's `js_net_process_pending` was dispatching its queued fake callbacks, and the adoption test counts only its own agent's sockets. On Linux, failures went from 47/300 (ext-net) and 21/300 (ext-http) on main to 0/600 and 0/300.
