### Performance

- The regex engine moves from perex 0.1.9 to 0.1.11. 0.1.11 carries PerryTS/perex#3, which takes package-shaped repeats and character classes out of the matcher's per-character loop. Measured with `perf stat -e instructions:u` (two-N differential) on perrymaster against `main`: uuid's `validate` regex −65.2% per call, jws's `JWS_REGEX.test` −84.3%, `/^\d+$/.test` −5.4%, and on the package workloads jsonwebtoken/decode −61.1%, uuid/v4 −47.9%, uuid/v7 −34.4%, nanoid/generate −30.4% and uuid/v5_parse −28.4%. Every output is byte-identical to Node 26.5.1, and peak RSS does not move beyond run-to-run noise (#10166).
- perex 0.1.10's `Search::run` fails with `RunError { error, remaining_work, buffers }`. Perry's two search sites now record the work a failed run left instead of keeping the budget they started with. Nothing observes this today, because the budget is `usize::MAX` on these paths.
- perex 0.1.11 is younger than the 7-day cargo `min-publish-age` soak. The owner approved a one-time override for this version on 2026-09-28. `Cargo.lock` was resolved once with `CARGO_RESOLVER_INCOMPATIBLE_PUBLISH_AGE=allow`, and the `Cargo.toml` comment records the approval, the publish time and the sha256 the lock pins, checked against the crates.io API. The soak window is unchanged.
