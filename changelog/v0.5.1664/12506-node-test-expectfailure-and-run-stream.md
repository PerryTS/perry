`node:test`'s `expectFailure` named export resolves to a real function again: it was missing from the runtime's submodule export table, so `import { expectFailure } from "node:test"` fell through to the "unlisted export" sentinel and bound the boolean `true`. The namespace read only looked correct because a `typeof` on it is folded from the API manifest at compile time (node-suite `test/imports/assert-expectfailure-shape`).

`run()` now hands back a `Readable` that can be iterated in a program that never imports `node:stream`: the runner arms the stream module's prototype surface itself, the same way `fs` / `http` / `tls` already do, instead of relying on an install only a `node:stream` import would emit. `for await (const event of run({ files: [] }))` used to throw `TypeError: value is not iterable` (node-suite `test/runner/api/run-empty`).
