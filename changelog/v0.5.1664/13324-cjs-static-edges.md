A literal CommonJS `require("./x")` of a module Perry compiles is linked at compile time: the call runs the target's initializer once and reads its module record directly, with no string dispatch, cache lookup or path registry on the way. A CommonJS module now runs when it is first required, after the statements before the `require` call, which is Node's order (it used to run before the requiring module's body); `module.children` lists each child once per parent and `module.parent` is the first requirer, as in Node. A literal `require("fs")` of a builtin reads its hoisted binding too, so a program no longer links a builtin's whole surface just for having required it.

A program is "closed" when no module can reach the loader: no `node:module`, `vm`, `inspector` or `repl` import, no native addon or `data:` import, no dynamic `import()` or `eval`, no write or escape of `require.cache` or `require.extensions`, no computed `require(expr)`, and no use of `require` or `module` as a value. A closed program links no dynamic loader at all (no path registry, no reload, no `createRequire`), which makes a CommonJS program about as small as its ESM equivalent: a program requiring only `fs` and `path` goes from 11.6 MB to 7.95 MB of code (its ESM twin: 7.81 MB), the AWFY harness from 13.8 MB to 9.9 MB. A program that is not closed keeps full Node semantics for those features: every literal `require` then reads the live `require.cache` entry first, a deleted entry re-runs its module with the requiring module as its parent, and modules still publish themselves to the path registry for computed requires.
