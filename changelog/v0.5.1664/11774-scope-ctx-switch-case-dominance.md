- **Fixed a SIGSEGV reading a captured `let` from a later `switch` case (#11771).** The scope-context grouping (#11710) checks that a binding's home dominates every reference by testing statement numbers against the end of the home's statement list. That end is one past the list's last statement, i.e. the number of the next statement, but the test was inclusive. For a `switch` case, the next statement is the first statement of the following case: it is in the binding's scope but skips the `let`, so `case 1: let x = …; (() => x++)(); case 2: return typeof x` grouped `x`, and entering at case 2 dereferenced the never-allocated scope root (`TAG_UNDEFINED`) as a pointer. The bound is now exclusive (`crates/perry-codegen/src/scope_env/analysis.rs`), so such a binding keeps its entry-initialized per-binding cell and the skipped read is `undefined` again, as the #4926 regression test requires. Unit tests in `scope_env/tests.rs` pin both the refusal and the in-list control.
