- **fix(hir): a user method named like an Array builtin now runs on an instance built from a class value (#11128).** `new C()` where `C` is a local value binding (`const C: any = R`, a factory result, a destructured `require(...)` namespace) was typed `Named("C")`, a name that matches no class. The array fast-path gate read that as "not a string, so an array", and `r.push(1)` lowered to `Expr::ArrayPush`. That wrote a fresh array into `r`, and the user's `push` never ran (redis@6.1.0 `linked-list.js`: `s.push(1); s.length` → `0`). Such an instance is now typed `Any`, so the call goes through runtime dispatch, which still takes the Array path for a real array. The same applies to `new C<T>()`. `InstanceType<typeof C>` receivers are no longer treated as proven arrays either. Proven `T[]` receivers keep their fast path, with byte-identical IR. Tests: `test-files/test_gap_user_method_builtin_name_dynamic_ctor.ts` and `crates/perry-hir/tests/dynamic_ctor_builtin_method_names.rs`.
