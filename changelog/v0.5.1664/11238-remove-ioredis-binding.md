Removes the native ioredis binding (`crates/perry-ext-ioredis`). It served three npm names, `ioredis`, `iovalkey` and `redis`, and all three now compile from their own npm source. This is part of the native-binding removal campaign.

- Deleted: the crate, its three `well_known_bindings.toml` rows, its 18 `module: "ioredis"` native-table rows and `js_ioredis_*` declarations, and the `new Redis()` constructor lowering in `lower_builtin_new`. Also deleted: the `Redis` class-name routing in HIR (`native_new`, `module_decl`, the `Redis` type-annotation tables in `fn_decl` / `expr_function` / `misc`, `duplicate()` chaining) and the `redis`/`iovalkey` → `ioredis` dispatch normalization. Also deleted: the CLI's ioredis feature detection, `PERRY_NATIVE_EXTENSION_PACKAGES` entry, `binding_needs_shared_tokio` / `async-runtime` / sandbox-profile arms, the API-manifest entries and the Android stub symbols.
- The HIR type tables were a live hazard once the source compiles. Any parameter or return value typed `Redis` was registered as a native `ioredis` instance, so its method calls lowered to `js_ioredis_*` FFI instead of the real class's methods.
- Before this change the binding was already worse than source. On main at `feb2b7606` (#11225 included), the default route for all three packages failed with auto-optimize on: `ioredis` (`require("ioredis/package.json")` → undefined), `redis` (`TypeError: value is not a function` after connect), `iovalkey` (wrapper/stdlib tokio mismatch, link refused). With `perry.compilePackages`, `ioredis` already worked from source. `redis` and `iovalkey` could not be taken off the binding at all, because the `Redis`/alias routing still linked the wrapper.
- Re-derived: `native_result_ledger` 309 → 292 rows and 274 → 258 providers (script output, not arithmetic). The tokio inventory drops the `perry-ext-ioredis → redis` and `→ tokio` edges (group J), and the `redis` crate leaves `Cargo.lock`, along with `turnloop-redis`, `arc-swap`, `arcstr`, `backon`, `sha1_smol` and the duplicate `num-bigint` 0.5. `workspace-architecture.json` goes from 71 to 70 members (externalize 13 → 12). The two GC root-holder entries and the unrooted-local-shape baseline row go too (383 → 382). The API reference and `perry.d.ts` are regenerated.
- New gap tests: `test_gap_ioredis_from_source`, `test_gap_iovalkey_from_source` and `test_gap_node_redis_from_source`. Each one runs connect, SET/GET, a pipeline, MULTI/EXEC, SUBSCRIBE/PUBLISH and QUIT against an in-process fake RESP server (`test-files/_helpers/fake_resp_server.ts`), so CI needs no redis-server. `ioredis@5.11.1`, `iovalkey@0.4.0` and `redis@6.1.0` are pinned exactly in the root devDependencies, and each fixture prints its resolved version.
