Fix a panic when wasm programs dynamically construct a class whose constructor takes 16 or more parameters.
The portable fallback of the all-`f64` call trampoline stopped at 16 arguments (`this` plus 15 parameters) and panicked with `unsupported arity` above that, which a Fastify-based HTTP service compiled for `--target wasip1` hit at startup with 18. On wasm an indirect call of an exact all-`f64` signature is correct for any count, so the fallback now dispatches up to 64 arguments (`this` plus 63 parameters) and still fails closed beyond that. Native targets are unchanged. `--target wasi` gets the same fix.
