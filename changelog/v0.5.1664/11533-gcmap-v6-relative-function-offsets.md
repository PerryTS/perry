### Performance

- **GC map v6: no load-time relocations, read-only section (#11508).** The compact GC map stored each function as an absolute `.quad <symbol>`, which cost one dynamic relocation per function. Those were applied eagerly at load and dirtied every page of the table, and they forced `.perry_gcmap` (ELF) and `.pgcmap` (COFF) to be writable. Each function field is now a signed 32-bit `fn - _perry_gc_map` link-time constant (PC32/PREL32, REL32, or a Mach-O SUBTRACTOR pair). The linked section therefore has zero dynamic relocations and is `aR` on ELF and `dr` on COFF. The function entry is 12 bytes on every target, so the header's pointer-width flag is gone. Measured on a generated 20,000-function x86_64 Linux program: 20,064 → 0 relocations in the map, `.rela.dyn` −481,920 B, `.perry_gcmap` −80,256 B, file −631,472 B.
  - On ELF the map names each function by a local label placed at its entry, not by its symbol. A Linux plugin links `-shared` without `-Bsymbolic`, where an exported function is preemptible and a PC-relative reference to it does not link: lld refuses it, and bfd emits a DT_TEXTREL.
  - The runtime decoders (eager and lazy, `crates/perry-runtime/src/gc/roots/stack_maps_{decode,lazy}.rs`) add the section's mapped address and each blob's offset. v5 decoding is removed.
