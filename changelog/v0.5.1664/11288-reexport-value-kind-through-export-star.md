A value that one module imports and re-exports (`import { x } from "./a"; export { x }`) now keeps its kind when it is reached through `export *` (#11275). Before this fix, importers of the barrel got a function in place of `x`: every property read was `undefined`, and a method extracted from it threw `value is not a function`. bson's `ByteUtils` takes this path, so mongodb compiled from source failed its first handshake with `MongoServerSelectionError: value is not a function`.

- Root cause: `run_pipeline.rs` builds the export-origin map (`all_module_exports`) as a fixpoint. Its `export *` branch copied the source module's entry once and never revisited it. On the first pass, an `export { x }` of an imported `x` still points at the re-exporting module itself; only a later pass resolves it to the module that declares `x`. The barrel kept the stale origin, so the var/function classification, which is keyed by the declaring module, missed. Codegen then wrapped the intermediate module's zero-arg getter as a function value. This affected objects, primitives, arrays, arrow consts, declared functions, live `let` bindings, CJS values and namespaces. Classes were not affected.
- Fix: an entry supplied through `export *` records its source, and it is re-copied whenever that source's entry (or its #678 origin name) changes. Names a module exports explicitly (`export { .. }`, `export { .. } from`, `export * as ns`) shadow every star, so a star never claims or overwrites them. For an ambiguous name that two stars both provide, the first star to supply it keeps it; before this fix, the last star processed in a pass overwrote it.
- New gap test `test_gap_11275_reexport_value_kinds`, with fixtures in `test-files/fixtures/issue_11275_reexport_kinds/`. It covers every value kind, plus aliases, `export * as ns`, a re-exported CJS value, one and two star hops, a local export shadowing a star, ambiguous stars, an `export *` cycle, a namespace import of the barrel, and a live binding.
