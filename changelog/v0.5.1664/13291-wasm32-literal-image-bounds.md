Fix program string literals being rejected by the runtime's image classifier on `wasm32`. The compiler emits literals into the `perry_strings` section, but on wasm the runtime only knew the ranges of its own registered images, so any reader that validates a string header (`path.*`, `URLSearchParams`, filesystem paths) treated a literal as a counterfeit. The classifier now admits an image that lies inside the exact `__start_perry_strings`/`__stop_perry_strings` bounds the linker synthesizes, keeping every other check (marker, flags, size, terminator, extent within the section), so a marker-shaped buffer in the data segment, stack or heap is still rejected. The image classifier checks (the unit tests' fixtures, plus the in-section admission case) now also run inside a linked `wasm32-wasip2` program under wasmtime in the required `wasi-execution` job, since this crate's test target does not build for wasm, and a new `string_literal_images` acceptance fixture covers the production link path.
