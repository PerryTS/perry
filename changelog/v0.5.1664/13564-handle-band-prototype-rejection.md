**The handle-band rejection in `default_object_prototype_for_owner` now has a regression test.** That function reads a receiver's object header, so it is only valid for a heap address; `9ae3fec0a1` added the guard that proves it (`is_plausible_heap_addr`, i.e. `!is_handle_band(addr) && is_valid_obj_ptr(addr)`) and landed without a test, because no input was known to reach it with a handle id. The new test asserts that every small-handle id (`0`, `1`, the common registry end, the fetch and proxy and stream band starts, and `HANDLE_BAND_MAX - 1`) is rejected before the read, and that an ordinary object still resolves the default prototype. With the guard removed the test does not merely mismatch — the process aborts (SIGABRT) on the id-band read, which is what makes it a real witness.
