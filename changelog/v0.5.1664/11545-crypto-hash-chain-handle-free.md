- **perf(crypto): `createHash` / `createHmac` objects that never escape no longer register a native handle (#11516).** #11515 made hash/HMAC handles reclaimable by the collector, which bounded memory but put full-trace work on every request that hashes. A new HIR pass (`perry_transform::crypto_hash_chain`) proves the hash object cannot escape and rewrites it onto internal `crypto.__perryHash*` calls; codegen gives each such site a 16-aligned stack slot and the digest state lives there, so no id is consumed, parked or traced. Recognised: inline chains `createHash(a[, opts]).update(..)*.digest([enc])` and the `createHmac` / legacy `Hash` / `Hmac` forms with any number of updates; block-local `const h = createHash(..)` (or a function-scoped `var`) whose every reference, counted module-wide over all LocalId carriers, is the receiver of `h.update(..)` (result discarded or chained) or `h.digest(..)`, outside closures, with no `await`/`yield` in between; the jwa/jsonwebtoken sequence shape `(h.update(x), h.digest(e))`; and CommonJS `var crypto = require('crypto')` aliases (only through the CJS wrapper's own `require`, and still reading the alias first so an unassigned binding throws like node). Anything stored, passed, returned, captured, `copy()`d or used as a stream keeps the registered handle. Measured on the #11515 probes (qb2, `instructions:u`, two-N differential): a `createHash` loop costs 3.9k instructions per hash vs 11.7k before #11515 and 15.7k with it, at 53 MB max RSS vs 165 MB / 108 MB.
- **fix(crypto): node's errors and digest encodings on every hash path.** `createHash('<unknown>')` now throws `Error: Digest method not supported` and `createHmac('<unknown>', key)` throws `TypeError [ERR_CRYPTO_INVALID_DIGEST]: Invalid digest: <alg>` (both returned `undefined`, surfacing later as `Cannot read properties of undefined (reading 'update')`). `digest(enc)` follows node's encoding parse: `utf8`/`utf-8`, `ucs2`/`utf16le` (lone surrogates kept) and `ascii` are string encodings, and a missing, falsy or unknown encoding returns a `Buffer` (it returned hex). `digest(<non-string object>)` no longer dereferences the object as a string. The codegen type facts for a digest call now classify only literal encodings, so `.digest('nope')` is typed as a Buffer.
