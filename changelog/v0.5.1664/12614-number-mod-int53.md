Numeric `%` now has an exact-integer path for operands beyond 32 bits. Generated code keeps its inline i32 remainder check, and everything that check refuses goes to one shared out-of-line helper, `js_number_mod`, instead of an inline `frem` (a libm `fmod` call). Call sites keep their size. `js_number_mod` tries, cheapest first: the u32 domain (32-bit remainder, the tier `js_dynamic_mod` already had), then exact integers within ±2^53 (i64 remainder, with a zero result taking the dividend's sign, so `-4 % 2` is `-0`), then `fmod` for everything else. That covers a zero divisor (NaN), NaN, ±Infinity, fractional and out-of-range operands. `js_dynamic_mod`'s plain-double path uses the same helper.

The motivating shape is an LCG step such as `(seed * 48271) % 2147483647`, whose dividend overflows i32 but not i53. On the 5M-word split/Map driver this is −1.43% instructions:u; zod, tsc, fastify, collatz and binary-trees are flat (±0.03%). `js_number_mod` is a GC leaf (arithmetic plus `fmod`) and is recorded as `Leaf` in the call-effects tables. A runtime unit test compares it bit for bit against `fmod` on 30 edge cases, and `test_gap_number_mod_int53.ts` covers the same edges against node.
