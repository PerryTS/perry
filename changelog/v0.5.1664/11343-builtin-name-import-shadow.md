**fix(hir): a binding imported from a source module shadows a builtin module name, so pg's scram-sha-256 login works (#11336).** `is_builtin_module_namespace` treated a canonical builtin name (`crypto`, `path`, `os`, `fs`, `net`) as the builtin whenever no ordinary local shadowed it. An imported binding is not a local, and the CJS wrap hoists `const crypto = require('./utils')` to an import. So node-postgres' `crypto.sha256(clientKey)` in `lib/crypto/sasl.js` lowered to Perry's hex-digest intrinsic instead of pg's WebCrypto helper. The SCRAM StoredKey became hex text, and every scram-sha-256 login (the default since PostgreSQL 14) failed with `password authentication failed`. A registered imported binding now shadows the name too. Native imports register an alias rather than an imported function, so they are unaffected. New gap test `test_gap_11336_builtin_name_import_shadow` covers the ESM and CommonJS forms and the RFC 7677 SCRAM exchange. Verified against a live PostgreSQL 16.15 with pg 8.23.0.
