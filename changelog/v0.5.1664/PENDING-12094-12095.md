Fix Buffer-typed parameter reads over views and native-backed buffers (#12094), and match Node's gzip header bytes (#12095).

- Buffer parameter pre-registration now resolves element zero through the existing `js_native_buffer_data_ptr` span resolver, also used by Uint8Array views, instead of assuming inline bytes at `param + 8`. The existing view slot keeps that pointer hoisted; its length slot points to the receiver header, so bounds use the real, live view length. The byte offset is unknown rather than asserted zero. No runtime state, cache, alternate resolution path, or Buffer redesign is added.
- gzip previously emitted flate2's default OS byte 255. For the issue's 34-byte gzip output, the deflate stream, mtime (zero), CRC and size trailer already matched Node; only header byte 9 differed. Explicit gzip headers now use Node/zlib's platform OS code (Linux 3, macOS 19, Windows 10) and mtime zero across sync, async and stream encoders. The byte sums on Linux change from 3107 to Node's 2855.
- Add gap tests for plain buffers, subarray, slice, `Buffer.from(ab, offset, length)`, a Uint8Array view cast to Buffer, a 1 MB allocation, `readFileSync`, and nested subarrays.
