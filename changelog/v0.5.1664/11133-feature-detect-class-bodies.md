fix(compile): auto-optimize feature detection now scans class bodies for every gate, and the `url-engine` gate covers URL-as-a-value (#11121)

`redis@6.1.0`'s `RedisClient.parseURL` (`@redis/client`) threw `TypeError: Value of URL.prototype.hostname called on an incompatible receiver` on `new node_url_1.URL(url)`, so `createClient({ url })` could not get past option parsing. It only failed in an **auto-optimized** build. With `PERRY_NO_AUTO_OPTIMIZE=1` (full runtime) it always worked, and that is why the issue's narrowing looked order-dependent.

Root cause: `collect_modules/feature_detect.rs` text-greps each module's lowered HIR to decide which optional runtime features to link. Most gates built their corpus from `init` + `functions` only, but class methods, accessors, static blocks and field initializers are stored under `classes`. Over time a few gates had been patched to add `classes` one at a time (fetch, wasm, zlib, regex, Math, diagnostics, native-name bindings). The rest had not. The only URL use in `client/index.js` is inside `static parseURL`, so `global-url` stayed off. `class_registry/construct.rs`'s dynamic-construct `"URL"` arm is `#[cfg(feature = "global-url")]` (#7008), so `new ns.URL(u)` fell through to the generic construct. The result was an object with `URL.prototype` (hence `[object URL]`) but no URL state, and every getter's brand check rejected it.

Fix:
- Build the HIR Debug corpus once, as `init` + `functions` + `classes`, and use it for every gate. Adding HIR to the corpus can only switch a feature on (a size cost), never off, so this closes the class-body false-negative family for every gate at once, including Temporal, EventEmitter, Intl, text, websocket, webcrypto, webfetch, proc-ipc, readline and dgram. It also formats the module once instead of about 12 times.
- `url-engine` also gates `String(url)`, JSON and the setter paths for URL objects, not just the host parser. Its gate now also fires on the URL family used as a value (the quoted `"URL` token, as `global-url` already did) and on a CommonJS `require("node:url")` / `require("url")` string. Without this, `new ns.URL(rel, urlObj)` threw `ERR_INVALID_URL` because the base URL object coerced to the wrong string.

Test: `test-files/test_gap_11121_url_in_class_body.cts`, in which every URL use sits inside a class body. It fails on `main` only under auto-optimize: the PR tier's fast mode runs `PERRY_NO_AUTO_OPTIMIZE=1` and passes either way, and the full tier's auto-optimize shards are the ones that discriminate. There are also unit tests in `feature_detect.rs`.
