- **net: `adopt_upgraded_tcp_stream` adopts on the caller's own loop, never another agent's (#11155).** It parked the upgraded stream in a process-wide map and posted the adoption with no agent id, so a caller that did not own the loop (a transport's tokio worker) reached the *primary* agent's loop whoever owned the connection, and `ensure_adopted_socket_dispatch` drained every parked id on whichever loop called it — one agent could adopt another agent's stream onto its own thread and heap. It now adopts synchronously on the calling thread's loop, or returns `INVALID_HANDLE` with the stream closed and nothing registered; the parked map and the drain are gone. The issue's other half (a failed adoption still emitting `'upgrade'` with an `undefined` socket) was already closed on `main`: both HTTP raw-upgrade paths moved to `turnloop_net::transfer` + `adopt_turnloop_upgrade` on the loop thread and report a failed handoff as `ECONNRESET` / a destroyed connection. Test: `perry-ext-net` `tests::upgraded_stream_adoption_is_on_the_callers_loop_or_refused` (sabotage-checked against the old implementation).
