node:sqlite `DatabaseSync`, `StatementSync`, `StatementSyncIterator`, `SQLTagStore`, `Session` and `db.limits` are now ordinary JavaScript objects that own GC-finalized native payloads, with node's own accessors, prototypes, `instanceof`, `Object.keys` and `JSON.stringify`. SQLite now calls user-defined functions, aggregates and the authorizer back through the database's traced owner edge instead of id registries and root scanners: a throw inside a callback is rethrown as the exact value after SQLite returns (never unwound through SQLite frames), the first throw wins, a callback may re-enter the same database (nested queries, `exec` from a UDF) without deadlocking, and `close()` inside a running callback is deferred until the outer call returns, which then reports the closed database. `close()` / `open()` keep the same object; statements of an earlier open report "statement has been finalized". A database whose UDF captures it is collected without `close()`. Fixed alongside: `%IteratorPrototype%` carries `Symbol.toStringTag` "Iterator", and a native payload's JS state may hold more fields than its inline slots.
