### Performance

- **Storing to a `: number` class field no longer costs ~31 instructions more than storing to a `: any` field (#10907).** For a `: number` field, the class-field store fast paths always called the out-of-line `js_array_numeric_value_to_raw_f64` canonicalization before writing the raw-f64 slot, including when the stored value was already known to be a plain finite double. That call returns a finite double unchanged, so `o.d = k` paid for a runtime call that did nothing. It only happened where the compiler had shape provenance for the receiver: a parameter or varying receiver takes the generic store either way, which is why the gap was bimodal in the acceptance matrix.
  - **Sloppy arm** (`expr/property_set/sloppy_class_field.rs`): the fast block's only predecessor is the #5093 inline precheck, and that precheck already rejects every value that is not a plain finite double. The call is removed; the value is stored directly.
  - **Strict guarded arm and scalar-replaced field stores** (`expr/property_set.rs`): the strict fast block can also be reached from `js_typed_feedback_class_field_set_guard`, which admits INT32-boxed and non-finite numbers, so canonicalization stays but moves to a cold arm. The new `emit_raw_f64_class_field_slot_store` skips it statically when `expr_produces_canonical_raw_f64` holds (literals, integer-provenance locals, …). Otherwise it emits an inline plain-finite test that stores the value directly and calls the canonicalizer only on the miss. Each arm does its own store, without a `phi`, so `root_reload` still re-materialises the stored operand.
  - The read path and the method-dispatch cliff for parameter receivers (tracked on #10502) are unchanged.
  - Regression tests in `crates/perry-codegen/tests/class_field_store_pointer_test.rs`. The sloppy arm must emit no canonicalization at all. The strict arm must keep it only on the `raw_canonicalize` block, behind the exponent test, with no phi. A literal store must need neither the call nor the diamond.
