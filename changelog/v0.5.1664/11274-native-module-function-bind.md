Fix `Function.prototype.{bind,call,apply}` on functions taken from a native Node module namespace (#11268). `import * as zlib from "zlib"; zlib.inflate.bind(zlib)` evaluated to `undefined` in Perry, where Node returns a bound function. mongodb 7.0.0's `compression.ts` runs exactly this at startup. The same was true of `.call`/`.apply` on any `ns.fn` from zlib, crypto, fs, util, path or events.

`try_module_class_static` (`crates/perry-hir/src/lower/expr_call/module_class_static.rs`) lowered every `<nativeNs>.<X>.<m>(…)` call to a `NativeMethodCall` with `X` as a class and `m` as one of its statics, so `zlib.inflate.bind` became a nonexistent `inflate.bind` static. For `bind`/`call`/`apply` the arm now falls through to the generic call path, which reads `zlib.inflate` as a function value and dispatches through `Function.prototype`. The exception is a static of that name that the API manifest registers under that class (`AsyncLocalStorage.bind`, `AsyncResource.bind`), which keeps its native routing. `events.EventEmitter.call(this)` keeps working, and `typeof events.EventEmitter.bind(null)` is now `"function"`, as in Node.

Covered by `test-files/test_gap_11268_native_module_function_methods.ts` (byte-identical to Node 26.5.1 in both auto-optimize and `PERRY_NO_AUTO_OPTIMIZE=1` modes; fails on the base) and `crates/perry-hir/tests/native_module_function_methods.rs`.
