Generator methods keyed by a well-known symbol now keep their method receiver (#11170). `*[Symbol.iterator]() { let node = this.#head; … }` threw `TypeError: Cannot access private member from an object whose class did not declare it`. That is the shape of `@redis/client`'s `SinglyLinkedList` / `DoublyLinkedList`, and it made the first command after `ready` reject. Instance `[Symbol.hasInstance]()` methods, generator or not, read as `undefined`.

Root cause, part 1 (HIR): a generator `*[Symbol.iterator]()` instance method was lifted into a top-level `__perry_iter_<Class>` generator. `this` was rewritten to an explicit first parameter by `analysis::replace_this_in_stmts`, and a forwarding `@@iterator` wrapper was registered. The hand-written rewrite ended in a `_ => {}` catch-all, so it never reached a `PrivateGuard` / `PrivateBrandCheck` receiver (`this.#x`, `#x in this`). It also missed template literals, `do…while`, labeled statements and arrow bodies. The `this` left behind evaluated to the lifted function's own implicit `this`. Nothing calls the lifted function directly any more: since #9788 the `for…of` fast path goes through `GetIterator`. So the lift is gone. The generator is now registered as the computed `Symbol.iterator` member itself, exactly like `*[K]()`, and `js_register_class_computed_method` still aliases it onto the `@@iterator` slot. `iterator_func_for_class` still records the class for the syntactic `for (… of new C())` detection. `replace_this_in_stmts` (still used by the `get [Symbol.toStringTag]()` lift) now falls back to the exhaustive `walk_expr_children_mut`. It also covers `DoWhile`/`Labeled`, and rewrites `this` inside `this`-capturing arrows, adding the explicit `this` local to their captures.

Root cause, part 2 (runtime, `symbol/get.rs`): the instance and static symbol-property readers skipped `CLASS_SYMBOL_METHODS` for every well-known symbol, on the assumption that each one has a synthetic `@@name` vtable slot. Only `iterator`, `asyncIterator`, `toPrimitive`, `dispose` and `asyncDispose` have one, and only for instance methods. So `obj[Symbol.hasInstance]` / `obj[Symbol.split]` on an instance, and `C[Symbol.iterator]` for a `static *[Symbol.iterator]()`, read `undefined`. The call returned `undefined` too, because well-known-symbol calls go through the property read. Those symbols now fall back to the table.
