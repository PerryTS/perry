**Fix `splice`/`unshift` dropping spread arguments (#6870):** `arr.splice(start, deleteCount, ...items)` and `arr.unshift(...items)` on a typed local array inserted the spread source as a single nested array element instead of expanding it. The typed-local fast path in `local_array_methods.rs` materialized each lowered argument as one `ArraySplice`/`ArrayUnshift` item and never consulted the AST spread flag, unlike the `push` arm. Both arms now fall through to generic dispatch when any argument spreads — that path already expands correctly. `push`/`concat` and all non-spread forms were unaffected and keep their fast paths. Found compiling the Milo compiler, whose LLVM emitter hoists entry-block allocas with `lines.splice(insertAt, 0, ...hoisted)`; the nested array stringified through `join("\n")` as `,` and produced malformed LLVM IR.
