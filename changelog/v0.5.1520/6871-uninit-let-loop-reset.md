**Fix uninitialized `let` leaking across loop iterations (#6871):** `let x;` declared in a loop body was not reset to `undefined` on each iteration when the assignment happened inside a nested loop, so a value set in iteration N was still visible in iteration N+1. Executing a lexical declaration initializes the binding to `undefined`, but HIR emitted `Stmt::Let { init: None }` and codegen — which allocates the slot once and cannot distinguish `var x;` from `let x;` (no var flag on `Stmt::Let`, `var_hoisted_ids` does not reach it) — emitted no store at all. The implicit initializer is now materialized during lowering, where `is_var_decl` is known; `var` is excluded and keeps its prior value as before. Assignment directly in the loop body, and the explicit `= undefined` form, were already correct. Found compiling the Milo compiler, whose parser collects declaration attributes into a nested-loop-filled `let attrs: Attribute[] | undefined;` — a struct's `@derive(...)` leaked onto every following declaration and the compiled binary rejected valid programs.
