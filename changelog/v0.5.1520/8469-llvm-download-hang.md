ci: the Windows LLVM 22 provisioning download is now bounded and genuinely retryable, and `doc-tests` carries an explicit `timeout-minutes` (#8468). A stalled transfer in `setup-llvm22` — `curl` had no `--connect-timeout`/`--max-time`, and `--retry` does not cover a hung connection — consumed GitHub's 360-minute default job budget, so `doc-tests (windows-2022)` was cancelled after 6 h having run zero tests, failing `full-suite-gate` and blocking the release. `curl`/`tar` exit codes and the downloaded size are now checked so a bad transfer names itself instead of surfacing as an archive error.
