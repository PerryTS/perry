fix(gc): `js_put_value_set` re-reads its operands after the property-key coercion (#8495). It rooted target/key/value/receiver in a `RuntimeHandleScope` and then immediately bound them to plain `f64` locals — *before* calling `js_to_property_key`, which runs user `toString`/`Symbol.toPrimitive` code and can evacuate. The handles kept the objects alive, but the locals captured pre-collection addresses, so every path below the coercion used stale pointers: a stored value read back `undefined` one collection later, re-breaking the #6935 contract from the other side. Fixes `proxy_target_set_survives_forced_evacuation` and the `dyn-index-set` case of `property_key_stored_values_survive_forced_evacuation`; the `Symbol.toPrimitive` case routes through `js_object_set_index_polymorphic` and is still open in #8495.
