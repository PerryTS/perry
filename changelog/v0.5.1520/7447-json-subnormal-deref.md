- **`JSON.stringify` no longer dereferences subnormal numbers as heap pointers.** `JSON.stringify(1e-317)` segfaulted and `5e-324`/`1e-320` printed `null`, all reachable from untrusted input via `JSON.stringify(JSON.parse(text))`. Two independent admission tests were at fault — `json/mod.rs::is_raw_pointer` (bit-for-bit the IEEE-754 positive-subnormal predicate) and `stringify_api.rs::try_stringify_lazy_array`'s `top16 == 0`, which runs first, so fixing either alone only moved the crash. A raw pointer and a positive subnormal share bit patterns by construction, so both sites now decide by GC allocation membership (`ptr_is_tracked_heap_object`, dereference-free page-map and registry lookups) instead of by bit pattern. (#7447)
