**GC correctness (generational remembered set):** fix a latent data-corruption bug where arrays born directly in the old generation (>16KB payload, e.g. >2048-element `JSON.parse` results) lost their old→young remembered-set edges: `note_array_slot_layout_only` skipped the write barrier on the assumption that fresh/suppressed fills never need one, so a later minor GC swept the array's still-live children (old parents are black-leaves that trust the remembered set) and reads through the array returned freed memory — surfacing as `TypeError: value is not a function`. The helper now emits the slot write barrier when the array is old-gen (~one page-cache compare for nursery arrays). Also adds a `PERRY_GC_VERIFY_EVACUATION` diagnostic that records every old page ever dirtied and reports `slot_page_ever_dirty` on verifier failures, distinguishing "recorded then lost" from "store never barriered". Measured on a 13MB production bundle: old-young-edge verifier went from 155 missing edges (default GC) / 445 (with evacuation) to 0.
