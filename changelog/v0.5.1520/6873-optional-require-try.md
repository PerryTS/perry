**Fix optional `require()` in try/catch failing the build (#6873):** `try { x = require("./generated") } catch {}` for a module that is not on disk aborted compilation with "Could not resolve namespace import". The static-require transform hoists literal requires to a top-level `import * as`, which discards both the runtime guard and the catch, and an unresolvable namespace import is a hard error (#629). Node and Bun instead throw at the call site and let the catch swallow it. A require whose call sites are *all* inside a `try` and whose specifier does not resolve on disk is now left as a runtime `require` — the path bare package specifiers already take, which reproduces Node exactly. Optional requires that *do* resolve keep being hoisted, so a present module is still compiled in and loads, and one unguarded call site anywhere makes the specifier load-bearing again. Found on the Milo compiler, whose `src/stdlib-bundle.ts` is gitignored and generated: a fresh clone could not be compiled at all, and the error's three suggested remedies were all wrong for this shape.
