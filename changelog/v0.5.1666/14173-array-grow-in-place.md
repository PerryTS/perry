Performance: a push that finds its array full no longer pays a whole runtime push. The inline push tier asks the new `js_array_grow_for_push` for room and stores the element inline as usual, so the regrowth skips the generic push dispatch, the descriptor guard, a handle scope and the classifying slot store. That entry never collects: when the array is the most recent nursery birth (a loop filling a fresh `[]`) it lengthens the array where it stands, with no copy, no forwarding stub and no new address for aliases. Otherwise it makes a young copy as before, and it declines anything that would need a collection. One regrowth drops from about 800 instructions to about 110 in place, or about 420 when it copies. The pushes behind that admission read `length` without the small-address guard, at 56 instead of 59 instructions each. 40 pushes into `[]` drop from 4,122 to 2,709 instructions and 16 pushes from 1,109 to 1,067. The runtime push and `js_array_grow` take the in-place and no-collect arms too. `PERRY_PUSH_GROW_INLINE=0` keeps the previous generated code.
