**`instanceof` now consults a computed static `Symbol.hasInstance`.** When the right-hand side was a bare identifier naming a user class, codegen resolved it to the class id and emitted the static `js_instanceof(v, <id>)` compare. That answer never looks at the function object, so a computed static member — `@@hasInstance`, including one installed with `Object.defineProperty` on the class — was silently ignored, and it was ignored even for a primitive left-hand side. The class case now materializes the declaration's function object (`emit_class_value`, which is non-collecting and returns a pinned value) and calls `js_instanceof_dynamic`, which performs the observable `GetMethod` on it; class metadata that is not this lexical binding never claims it, as before. The regression asserts the emitted IR reads `@@hasInstance` from that object and no longer emits the static class-id compare — red against the previous lowering, which reported "an imported class must read @@hasInstance from its function object".
