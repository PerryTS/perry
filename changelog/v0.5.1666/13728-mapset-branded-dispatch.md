**`ReadonlySet.has` and `ReadonlyMap.get` no longer take their branded fast path on a receiver they cannot prove is the builtin.** The GC header says what the allocation is, not that the receiver still behaves like it: an own `has`/`get` accessor lives in the object's metadata and was stepped over entirely, a custom `[[Prototype]]` method was invisible, and a subclass brand was ignored — so `Object.defineProperty(set, "has", {get})` never ran and `Object.setPrototypeOf(map, {get(){…}})` was never consulted. The fast path now also requires the metadata to be absent and the family's intrinsic prototype to be pristine, so all three fall through to ordinary JavaScript lookup. The structural fallback had the mirror-image bug — it called the method by name in one step, re-reading the property and losing the value an accessor had selected — and now performs the `Get` once and calls the value it obtained, refreshing both operands afterwards because an accessor may collect. Two integration tests pin the observable semantics end to end: against the previous runtime they report `own one 0` / `prototype undefined`, and with the change `own one 1` / `prototype override`.
