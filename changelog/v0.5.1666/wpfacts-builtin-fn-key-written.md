Whole-program facts: a store into a built-in function value (replacing `Math.max.call`, or a field stored on a value that may be a built-in method, such as `node.jsDoc = v` where `node` came from a computed read of an array) now makes only the key it names unknown on built-in function values, instead of every property of every built-in function value. A read under another key keeps what the runtime describes and what the program stored there. An element store writes the numeric keys, and a store under a computed key still writes every key it may name. A store that runs after a read in program order still reaches it. `Object.assign` into a built-in function value and an accessor defined on one (`Object.defineProperty` with a getter) now count as stores under their keys; before, neither made the property unknown, so a read could keep a value the program had replaced.
