`perry target add` and the compile-time ext fetch now print `perry: downloading <asset> (31.2 MB) from github.com` before every download, redraw a progress line when stderr is a terminal (one `done: 31.2 MB in 14 s` line otherwise), and give the tarball request `max(600 s, size at 32 KiB/s)` instead of a flat 600 s, so a slow link is not cut off mid-file. When the release host cannot be reached at all (no HTTP status: resolve, connect, TLS or a deadline) the error reads `cannot reach <host> (<cause>)` and leads with the pinned `npm install -g @perryts/perry-ext-<triple>@<version>` command (npm uses the user's own registry and proxy), then `HTTPS_PROXY` or `PERRY_RELEASE_MIRROR=<dir|https url>`. A 404 stays "no such package"; there is no registry fallback, because the signed manifest lives only on the GitHub release.
