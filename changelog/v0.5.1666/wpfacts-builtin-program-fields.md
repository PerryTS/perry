Whole-program facts: a value the program stores on a built-in namespace or constructor (`Object`, `Math`, ...) or on a built-in method value, under a key the runtime does not declare for that object, is a field of that object. The runtime reads only the keys it declares, so only the program reads such a key back: the stored value is no longer handed to unknown code, and the key no longer reads an unknown value on that object (or on every built-in function value). This covers the common case where a receiver may be a built-in only in the analysis: a computed read of a plain-object dictionary may return the inherited `constructor` or an `Object.prototype` method, and a field stored on what it returned stays the program's. A key the runtime declares (`Error.stackTraceLimit`, `Error.prepareStackTrace`, `Object.keys`, `name`, `length`, `prototype`, well-known symbols) is treated as before, and so is a store on a built-in function the analysis cannot identify. A built-in object handed to unknown code, or reachable by interpreted code, gives up its program fields as an escaped object does. The analysis now also knows that the runtime declares `Error.prepareStackTrace`.
